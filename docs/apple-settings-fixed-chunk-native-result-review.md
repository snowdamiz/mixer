Apple's public contracts support a narrow next diagnostic. [`nextFocusedItem`](https://developer.apple.com/documentation/uikit/uifocusupdatecontext/nextfocuseditem) is nil when no item receives focus in the update. [`didUpdateFocus`](https://developer.apple.com/documentation/uikit/uifocusenvironment/didupdatefocus%28in%3Awith%3A%29) is delivered to environments containing the previous or next item; a callback alone is not proof that the authored carrier focused. [`preferredFocusEnvironments`](https://developer.apple.com/documentation/uikit/uifocusenvironment/preferredfocusenvironments) provides default-focus search priority, not a fixed successor list for Tab. The accepted controller returns only the reference button as preferred focus.

Apple's [iPad keyboard navigation session](https://developer.apple.com/videos/play/wwdc2021/10260/) describes Tab moving between primary items of focus groups, with hierarchy, layout, visibility, and reading direction affecting order. Here the authored and reference buttons are children of a scroll view and the next button is a root sibling; accepted source supplies no explicit focus-group or fixed Tab-order contract. That documentation discusses iPadOS/Mac Catalyst and is not an exact iPhone simulator ordering guarantee. Apple's [Full Keyboard Access session](https://developer.apple.com/videos/play/wwdc2021/10120/) addresses iPhone/iPad accessibility and the shared focus system, but does not establish equality of every AX/app snapshot in this observed execution. The strict paired-focus requirement remains intact.

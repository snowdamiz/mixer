The allocation boundary was inspected and executed in the actual modules. `ArtifactJSON` counts containers, keys and values before descent, limits each container to 256 entries, permits root depth zero through child depth 16, and rejects item 4,097. Long strings use a linear byte walk without constructing character lists. The walker deliberately does not establish Unicode/schema/cryptographic validity: an invalid UTF-8 string passed lexical preflight and was then rejected by the ordered Jason decoder. Ordered members remain available until recursive duplicate checking rejects escaped-equivalent names; no input-derived atoms are created. Actual decoding, semantic checks and signature verification all execute after admission; no regular expression authorizes acceptance.

The [arity-only call traces](../verification/hosted-artifact-admission-review/run-2/allocation-call-traces.json) ran inside the isolated review BEAM and captured no arguments. A valid fixture called `Base.decode64/2` twice and reached Jason. The 6,291,457-byte upload, 100,000-level nesting and 60,000-digit integer reached neither decoder. A 4,194,305-byte payload has the same 5,592,408-character encoded ceiling as an allowed 4,194,304-byte payload, but its actual padding arithmetic rejected it before any `Base.decode64/2` call. The noncanonical `eB==` tail likewise rejected before base64 decoding. JSON still allocates a bounded payload string within the envelope limit; the component does not claim to avoid that allocation or to provide a total memory/concurrency bound.

Whitespace between an envelope colon and the signed value belongs to the envelope rather than the value span: a case with 65,537 such spaces and a small signed object was accepted under the total envelope limit. Internal signed-object whitespace counts toward the embedded bound. Standalone leading/trailing whitespace counts toward the standalone bound. These outcomes match the frozen contract and the Go raw-value boundary.

Closed-field cases independently exercise missing, unknown, wrong-case, null and wrong-type fields in the manifest, scope, limits, grant descriptor and both grant entries, plus envelope and signed-document mutations. Additional cases reject escaped duplicates, invalid UTF-8, invalid escape sequences, isolated/reversed surrogate code units, control bytes, non-ASCII IDs, trailing values, negative zero, fractions, exponents, leading-zero integers and uint64 overflow. Correctly escaped field spelling is accepted. Values `9,007,199,254,740,993` and `18,446,744,073,709,551,615` survive actual JSON/CBOR/signature verification exactly; lowering host state by one rejects. Semantic-invalid but otherwise correctly signed cases reject independently of signature validity.

The grants, host and root rules match the accepted Go schema: exact protocol 3 / guest ABI 2 / UI schema 1, exact scope/runtime/capability map, inclusive state interval, host ceilings and frozen grant hashes. Grants preserve strict ASCII sorted uniqueness and explicit arrays; empty grants and explicit empty capability maps retain empty authority. Default-port and uppercase origins, duplicate permissions, unbound entries and storage entries carrying HTTP authority reject. Unsupported assets, compression, resources and negotiation reject. The entire root collection is validated before selection, including malformed unrelated keys, unrelated missing roles and unrelated invalid scopes. Key IDs are globally unique within the collection. Artifact role, revocation, exact scope and inclusive-start/exclusive-end validity apply at the supplied current integer time. Wrong key, signature tail and artifact/assignment/legacy/missing-domain signatures reject. Trusted maps are explicit host/root policy supplied by the caller; they are not downloaded identity-token authority, and this review makes no claim to authenticate that caller's policy source.

Malformed direct trusted inputs produced closed errors rather than unexpected crashes. `admit_signed/5` returns checked data without inventing upload envelope bytes. `recheck/4` reconstructs from the retained exact envelope and compares the entire Checked value under current host/roots/time. The [15 rechecks](../verification/hosted-artifact-admission-review/run-2/rechecks.json) accept ordinary and identically reconstructed valid structs, reject changed fields, forged success maps, current revocation/expiry and a changed host runtime. Exact equivalent valid material can pass because the bytes themselves remain valid; a freely constructible struct is not an in-process authenticity boundary.

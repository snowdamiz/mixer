# Hosted atomic storage independent preimplementation review

Recommendation: retain the selected narrow atomic writer, transaction identity and deterministic encoding direction for development. This is a **primitive-only recommendation with mandatory contract corrections**, not acceptance of a product repository, full typed validation, authorization, provider deployment or GA gate. Root must record the corrections and exact implementation handoff before repository acceptance. The frozen producer packet was not edited.

The review independently reconstructed the frozen candidate in an owned disposable PostgreSQL 17.11 cluster and copied dependency/build paths. The final run executes the original 41 cases plus 20 independently authored cases. Cases explicitly named “observed limitation” assert the reproduced gap; their passing assertion is evidence of that gap, not a validation pass. See the [review receipt](../verification/hosted-atomic-storage-review/receipt.json), [findings](../verification/hosted-atomic-storage-review/findings.json), and [fresh run](../verification/hosted-atomic-storage-review/run-3/receipt.json).

The correction contract's final post-DML time check also addresses a wait inside effects. Its generic audit “time relationships” must retain the selected future30-second completion tolerance, never infer completion≤decision/recorded. A remaining coordination boundary was reported to root: semantic cached-event association plus exact event-derived response catches the reproduced mismatch, but does not prove original-key association against a coherently rewritten cached row pointing to an otherwise equivalent later200 event. If that privileged corruption model is intended, retain and compare a separately bound request ID or other immutable key/event association; otherwise scope out coherent privileged cached-row rewrites explicitly. The review separately executes an unconstrained numeric finite-integer oracle: NULL, NaN, both infinities, negative/fractional and overrange inputs reject; zero and2^53−1 pass. This reviewer oracle is not shipped product code.

## Selected seams that the evidence supports

The legitimate `SECURITY DEFINER` call changes `current_user` to the exact writer owner while preserving the original runtime `session_user`, backend, full `xid8` text, database and nonce. Exact `role=none` rejects even SET ROLE to self. Runtime direct DML on private domain tables, role membership/elevation and private codec execution are denied. Separate schema/resolver/writer owners, FORCE RLS, closed PUBLIC EXECUTE, fixed search_path and nonrecursive resolver behavior were observed. This agrees with PostgreSQL's [session/effective identity distinction](https://www.postgresql.org/docs/17/functions-info.html) and [definer hardening requirements](https://www.postgresql.org/docs/17/sql-createfunction.html).

The context guard checks the fixed Repo/dynamic Repo, owner process, active reference, original backend/full xid/database/runtime identity, nonce, exact action/target, completion/GUC equality and original monotonic deadline before the fixed operation and on return. Completion NULL, fraction, NaN, infinity and overrange inputs reject in actual SQL. A stale zero rejects; zero is a real numeric value when bound and fresh, not a sentinel for missing data. The zero-positive case deliberately uses raw trusted fixture SQL and establishes no coordinator authenticity.

Fresh reviewer cases confirm actual runtime lock waits through `pg_stat_activity`, then deny a cached retry after policy revocation, DBnow reaches expiry while completion remains fresh, or completion ages to46 seconds while expiry remains valid. The separate later-wait F03 remains unresolved. Missing shared-lock rows abort rather than treating an empty lock query as admission. The single synthetic policy lock does not implement the full profile→principal→family→organization-head→project-head lock chain.

Four persistence fault boundaries roll back the artifact/audit/idempotency/head transition without an event-ID gap. Same-key/different-principal and same-artifact/new-key concurrency retain their selected semantics. Original request bytes determine the request hash; a matching retry returns original bytes/status/event without a new event; a new key on an identical artifact creates its own success audit with no state delta. Typed persisted-result corruption remains F04/F05.

The exact hand-authored event/state/display vectors and both encoders passed. A further120 deterministic independently authored Python exact-integer uint64 vectors, including values above2^53 and near2^64−1, agree byte-for-byte with SQL and Elixir. The restricted encoding follows the selected [RFC8949 deterministic subset](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2.1); this does not qualify a public decoder. Historical Go audit JSON/hash and v3 signature vectors were exercised from an isolated captured services source and remained unchanged. The hosted state hash is an ordered transition commitment over the specified change projection, not a hash of every database column or an order-independent snapshot.

The owned Unix socket proxy observed actual PostgreSQL `CommandComplete(COMMIT)`, withheld that reply and ReadyForQuery, then disconnected. A separate connection saw the committed rows; after stopping/restarting the owned cluster, a fresh-context retry returned the exact original result and one event remained. This is controlled acknowledgement loss after completed server COMMIT, not arbitrary cancellation/deadline/provider timing qualification. Every uncertainty freezes local blob collection.

Local fixture staging/reopen, size/count/aggregate quotas, exclusive immutable creation, partial/corrupt/symlink/oversized objects and orphan handling remain development evidence. An additional corrupt-object test confirms uncertain collection preserves the object while reopen rejects corruption. Trusted owned-directory enumeration, one process, filesystem assumptions and offline corruption recovery remain explicit. There is no power-loss directory-entry, multi-process/multi-host, R2 or production retention guarantee.

## Contract coordination before product ownership

Keep `VerifiedIdentity` unchanged. The actual checked source has no authentication-completion field. The trusted request coordinator must capture completion immediately after a successful `ConfiguredVerifier.authenticate` return, retain it immutably in AuthorizedContext field9 and the matching product GUC, and preserve the original15-second request lifetime and5-second monotonic transaction deadline. Completion is neither verifier-internal evaluation time nor token iat. Recheck exact equality at entry/return and SQL; require completion<expiry, DBnow<expiry, completion≤DBnow+30 and completion≥DBnow−45 without extending expiry or either deadline. The probe's fixed99 is not this integration.

The sole public mutation identity and composite field order are coordinated. The frozen private codec manifest is explicitly conceptual, not an exact migration DDL manifest. Actual observed private identities are `u(numeric)`, `b(bytea)`, `t(text)`, `a(bytea[])`, `hash_domain(text,bytea)`, `target(upload_input)`, `hx(text)` and `event_from_display(jsonb)`. All eight are schema-owner-owned invoker functions, IMMUTABLE, non-LEAKPROOF, PARALLEL UNSAFE with `search_path=pg_catalog`, executable by the writer and not runtime/PUBLIC. [Catalog evidence](../verification/hosted-atomic-storage-review/run-3/tests.json) retains complete identities and ACLs. Root may separately freeze the proposed [product identity supplement](../verification/hosted-atomic-storage-review/private-helper-supplement-candidate.json), mapping target input to `artifact_input_v1`; it remains a proposal. Migration/startup acceptance requires complete exact identities, owners, ACLs, policies and definitions, including the selected full typed decoder. No broad `EXECUTE ON ALL FUNCTIONS` grant or fixture-only foreign EXECUTE/policy/fault machinery belongs in product DDL.

The first real authorization slice admits only verified humans and exactly artifact.upload/read/audit.read with authoritative registered credentials, current scopes, live target ancestry, canonical memberships/revisions and five ordered lock classes. Service/CI identities remain unsupported even though the verifier's identity union can represent them. Current database credential registration/bootstrap/refresh, full target-aware RLS, HTTP/streaming/cancellation, full schema/startup inspector, accepted artifact admission integration, private read/page correctness, provider/Linux/Neon/pooling/R2/operational evidence, Oban/domain-job atomicity/G24, signing/publication/customer/external security and accountable GA acceptance all remain pending. A fixed synthetic human/policy target is not evidence for those gates. FieldLog must later consume immutable published packages from a separate repository. No UI, native, simulator/emulator or physical-phone run occurred; physical phones remain deferred.

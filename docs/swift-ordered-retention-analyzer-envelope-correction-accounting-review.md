## Copy transfers and lifetime places are separate inventories

One actual source-level by-value transfer of a complete16-byte slice, Range,
Option or Pair handle costs **one fixed-copy group**. Its source and destination
are two memory places; their coexistence does not create a second copy edge.
An explicit second actual transfer requires its own group. No compiler
scalarization, elision or machine instruction behavior is presumed.

| Source-level situation | Step obligation | Logical lifetime obligation |
| --- | --- | --- |
| One16-byte value transfer from source to destination | One fixed-copy group | Count both complete16-byte places while both are live;32 bytes |
| A later actual16-byte transfer from that destination to a third place | A second fixed-copy group | Count the third complete place if its lifetime overlaps; do not invent another transfer merely from overlap |
| Two actual independent8-byte scalar field assignments | Two scalar operations | Count each actual scalar/value place through its lifetime |
| Subsequent aggregate construction, argument handoff or return transfer | Account for each actual complete-value transfer separately | Count complete aggregate/argument/return/caller places; do not assume a small payload substitutes for the whole value |
| One helper return received directly into a caller place | Identify the actual return-transfer edge once | Caller receiving storage is the edge's destination; a second copy requires an actual additional intermediate transfer |

The rule is at most16 bounded scalar operations **or** one fixed copy of at
most128 bytes per group. Two actual16-byte copy edges are two groups even
though their summed bytes fit128. A complete16-byte handle transfer cannot be
relabeled as two scalar field assignments. Explicit scalar assignments do not
make a later aggregate transfer free. Scalar and copy work cannot share one
group, and unused/inactive-branch credits cannot pay another operation.

The frozen amended ledger must assign stable IDs to actual operations and copy
edges, with exact source spans, complete types/sizes, source/destination places,
helper and call/return boundaries, branch conditions and lifetime intervals.
Each transfer is charged once; every actual extra transfer, borrow, argument,
constructor, return, bounds check and loop operation is included. The lifetime
table may conservatively overlap places without multiplying the same transfer.
No generic padding, hidden helpers, free allocation or unnamed owner is allowed.

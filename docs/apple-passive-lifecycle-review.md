## Ownership, scope and interpretation limits

The observer's application and window references are weak. It stores no scene;
scene filtering reads the owned window's current association. Notification blocks
retain only the shared locked fault counter and a weak observer. The fourteen
tokens are bounded, a refused fifteenth token is immediately unregistered, and
explicit removal or bag deinit unregisters the admitted tokens. Host controls
exercise real Foundation registration delivery/removal, weak window lifetime and
concurrent fault accounting. They do not execute the UIKit observer itself.

The following are interpretation limits, not blocking findings:

- Ownership loss removes registrations when the next main-thread sample or
  notification reaches the ownership guard; observer deinit also removes them.
  Weak-reference zeroing alone has no wakeup. The implementation remains bounded
  and does not retain the departed window/application while waiting.
- Main-thread notification snapshots require exact app, owned window or current
  scene identity. Nil/other objects are filtered; a previous scene is excluded
  after association changes. This can miss connect/disconnect or other events
  while association is absent or changing. The pinned Apple active/inactive app
  and scene-background documents omit object wording, so their object convention
  is deliberately unproven. No runtime completeness claim follows.
- Off-main delivery increments the locked fault count before identity filtering.
  An unrelated off-main notification using one of the fourteen registered names
  can conservatively mark the diagnostic incomplete. It adds no foreign snapshot,
  reads no UIKit state and queues no delayed main-actor sample. That counter is a
  delivery fault signal, not a count of accepted owned events.
- Sequential state reads are explicitly non-atomic and non-authoritative.
  `captureStatus: complete` means no known local fault was recorded, not continuous
  lifecycle coverage. Filtering, launch ordering, original persistence timing,
  bounded retention and unproven notification conventions can omit events.
  Object addresses are supplementary sampled identities, not durable IDs or
  original event anchors. Initial scene absence cannot establish later absence.

These limits already fit the producer's conservative coverage contract. No
producer file was corrected or resealed by this review. The future result audit
must preserve them when interpreting the supplementary field.

# Independent current-authority prerequisite review

Recommendation: **correction required before final schema/catalog contract selection**. The current-authority resolver and role boundary reproduced their frozen behavior, but the proposed complete catalog manifest misses ordinary privileged deployment/schema drift. This is not an observed authorization bypass by the baseline runtime. Root may retain the demonstrated resolver design while requiring a new bounded catalog/startup contract correction and fresh review before implementing or selecting the final inspector.

Reviewed producer: [authority contract](hosted-authority-schema-contract.md) SHA-256 `d12d3b3a0484289f9990990f104bd3aaaff19eb4488caa6eca730ecdc938fbbd`; [producer receipt](../verification/hosted-authority-schema-contract/receipt.json) SHA-256 `ab20a2694c537ee04f2a07c0e1208ff44a24f7e7c78d930fab9591803b28e9cb`; exact run-9 source digest `ebaae05f782695d3cd9d1fcedc535f0b47cdb736167384b7dc6d8a09fa16b0de`. These reproductions use ordinary privileged DDL/grants against the owned fixture. They do not posit a hostile offline owner coherently rewriting a full historical database, and the correction does not claim to defend against one. The practical requirement is to fail closed when an ordinary deployment leaves privileges or enforcement weaker than the selected manifest. The product startup inspector is still unimplemented; no shipped startup code was bypassed.

The correction should additionally select and inspect role/database defaults for safety-sensitive settings (`pg_roles.rolconfig`/`pg_db_role_setting` as applicable), and validate effective settings on the actual new runtime connection. `pg_parameter_acl` alone does not describe startup defaults. A selected `session_replication_role=origin`, exact session/effective user and role, isolation and other safety settings must be checked before protected traffic. The ALTER ROLE/DATABASE default-setting path is **source-level correction guidance, not a separately reproduced finding in this packet**.

The reviewer independently queried the actual enforcement flags omitted by the producer. The [independent baseline](../verification/hosted-authority-schema-review/adversarial/independent-enforcement-catalog.json) contains 14 permanent relations with default replica identity, 89 validated/nondeferrable constraints, 26 valid/ready/live/immediate indexes, 74 enabled user/internal triggers, and no effective privileged parameter ACL in the fixture baseline. No unsafe baseline flag was observed. The correction should include exact constraint validation/deferrability and index validity/readiness/liveness/immediacy rather than relying solely on rendered definitions. This review did not generate an invalid existing index through a failed production migration and did not alter PostgreSQL system catalogs directly.

Positive controls establish the manifest's useful existing coverage: RLS predicate changes, policy role changes, permissive-to-restrictive policy replacement, CHECK `NOT VALID`, FK deferrability and index predicate changes all produce different producer catalogs. The original ten drift cases also replayed. RLS policy content/permissiveness is already emitted; its omission is not a finding. The independently replayed baseline catalog equals the frozen producer run-9 catalog exactly.

# Experimental complete streaming validation contract

Status: root accepted this bounded experiment on 2026-10-22. Implementation selection: `gpt-6.1-sol`, `xhigh`. This is a Rust-only nondefault `experimental-stream-validation` feature. It adds no C symbols, C structure fields, interpreter/cache/activation routing, imports execution, new executable profile or larger ceiling. The default Cargo build and frozen v1/v2/v3 behavior remain unchanged.

Input explicitly selects integer-v1, numeric-v2 or table-memory-v3 with `Limits::check`-narrowed existing limits. Reject input above the effective module ceiling before copying (at most 4 MiB). Own one exact-length private Box<[u8]> source snapshot directly in the non-Clone sealed result. Root approved direct Box ownership after a local Rust1.99 probe confirmed Arc::try_new remains unstable; no infallible shared-owner allocation is needed. Vec-to-Box conversion is permitted only at exact requested capacity/length, with allocation-boundary tests proving no shrink/copy overlap. A sealed successful span representation retains that owner, exact profile/limits and validator revision. No pathname, mutable caller buffer, serialized proof, external hash or cache identity supplies authority. No conversion into executable `Module` or `Instance` is provided. A later cache/hash identity is outside this contract.

Additional experimental validation budgets may only narrow their defaults: 4 MiB metadata, 64 KiB scratch and 64 million work credits, separate from execution fuel. Exhaustion produces no validated span object. These extra work/capacity budgets may reject pathological input otherwise inside frozen executable ceilings; production validation is not rerouted or changed. Source bytes remain separately bounded; reports include source plus metadata/scratch/fixed-state peak. Categories account live requested capacities, fixed owner/Arc/container/error state and allocation-growth overlap before allocation. Report reservation/accounting peaks separately from directly measured requested allocations; never substitute zero for unavailable allocation evidence. Native allocator internals and OS RSS are separate observations.

Keep compact function/body/type/global/import/export/segment spans and flat signature types. Re-read locals per body; retain no expanded locals for all functions and no instruction/branch-target vectors. Stream every instruction and every variable immediate. Per-function scratch honors the existing 4,096 expanded local/type operands and 128 control ceilings. Import/table/data forms remain the frozen supported subset. No guest code or start function executes.

Validate every section, cross reference and body needed by frozen `Module::decode`, including uncalled bodies and unreachable instructions. Unknown forms fail closed. Maintain the module-wide 200,000 instruction ceiling, function/type/global/table/memory/local/control bounds and only approved imports. Instantiation-stage active-segment bounds failures remain instantiation semantics; this validation-only result does not promise successful instantiation. A complete result appears only after all validation and cancellation checks finish.

Meter before potentially expensive actions: byte reads/scans, bounded source copy, local expansion (including zero-count group traversal), type-stack operations, branch targets, signature-parameter visits and duplicate-name comparisons/copies. Avoid unmetered quadratic traversals. Check existing cooperative Cancellation before/after the bounded nonpreemptible copy, within at most 64 charged traversal credits and before successful publication. Use checked arithmetic for offsets, counts and reservations. No wall-clock preemption guarantee is made.

Errors distinguish malformed, unsupported, type validation, resource exhaustion (category/used/limit), cancellation and allocation failure, retaining function, absolute byte offset and work used. Error handling uses bounded/static state and cannot allocate unbounded diagnostics. Resource-failure/cancellation/partial scans never yield a successful proof.

Verification must cover all three profiles and narrowed limits; uncalled/unreachable malformed bodies; variable immediates and zero-count local groups; exact and one-byte/credit budget boundaries; cancellation; allocation failure behavior; immutable caller-buffer independence and ownership/drop lifetime. Compare against the frozen decoder on independently authored bounded fixtures as a parity reference, not as an independent standards oracle. Record any disagreement before changing production behavior. Run existing default-profile checks and C ABI smoke tests to demonstrate isolation. Record source/tool/command/output identities and direct maximum allocation observations in a separate experimental receipt. No full Swift/FieldLog admission, devices, standards suite, fuzz/security audit or GA claim follows.

## Implemented bounded slice

`src/experimental/` contains the original fallible reader, reservation meter, compact metadata parser and streaming operand/control type checker. It shares the frozen numeric opcode shape tables, not the old instruction decoder or old body validator. Signature parameters are flat types; function/global/import/export/active initializer spans refer only into the owned source. Only the current function's expanded local, operand and control stacks exist. Branch tables are checked target by target. No Instruction/Op or branch-target array is created. Active segment descriptors retain declaration order and encoded payload spans; callers can inspect those borrowed bytes but cannot instantiate or execute them through this API.

Error `resource` is Source, Metadata, Scratch, Work or Profile. The last category carries an unchanged profile count/stack/memory/table ceiling and its attempted/limit values. Invalid min/max pairs are validation errors. Diagnostics distinguish allocation, malformed input, unsupported form, typing, cancellation and exhausted budgets, retaining absolute byte positions and function indices for body errors. Errors contain static strings and scalar state. Limits are checked with the same predicates as frozen `Limits::check`, without constructing its allocating error string. The original production method remains unchanged and parity tests cover narrowed and invalid limits.

Every dynamic buffer growth reserves the entire new requested capacity while the old capacity is still charged. It allocates with `try_reserve_exact`, rejects unexpected capacity, copies with per-element work/cancellation checks, drops old storage, then releases the old reservation. Source ownership uses one exact-capacity Vec allocation before a same-length Box conversion. The qualified allocator observations see exactly one source-sized allocation and zero reallocations, including that conversion. All 12 allocation ordinals in the mixed metadata/local fixture can return allocation failure without retaining heap storage. Oversized input and invalid limits allocate nothing, including with a first-allocation failure armed. Four deterministic allocator gates exercise cancellation around the source copy, metadata and body scratch; each yields no proof.

Fixed metadata reserves `size_of::<ValidatedSpans>()`, which includes the Box owner, metadata buffer headers/options/count, exact Limits and final Usage. Fixed scratch reserves Meter, three Reader states, BodyState with three stack buffer headers, the export-sort Buffer header, two Failure states and 128 bytes of bounded parser scalar state. On the observed macOS arm64 target those reservations are 520 and 744 bytes. These reservations are an explicit validation-accounting model, not measured compiler stack-frame layout, allocator usable size, caller storage, RSS or total process memory. Buffer payload capacities and old/new growth overlap are additional reservations. The receipt measures actual requested heap allocation independently and compares its incremental live peak to source plus all reserved categories. The extra work ceiling can intentionally reject a frozen-valid input: 16,384 unreachable calls to a 4,096-parameter signature use 64,000,000 credits, then fail before attempted credit 64,000,001; no semantic/profile acceptance change is routed to production.

Names are checked for UTF-8 by a metered original scalar decoder. Duplicate export detection uses fallible heapsort of bounded scratch indices with metered byte comparisons, including common prefixes; it does not rely on an unmetered quadratic traversal or cancellation from inside a standard-library sort comparator. A `Reader::take` charges span bytes before its O(1) borrowed slice operation; it does not scan them. Actual name/LEB/instruction/local/parameter/branch-target/stack/copy traversal checks cancellation per charged step. The one source copy and bounded native allocation calls are nonpreemptible. Private span/index arithmetic is bounded by checked construction, source ≤4MiB and checked externally supplied lengths; the representation is never deserialized or caller-constructed.

Reproduce the complete host receipt with `python3 -B vm/verify-stream-validation.py --name FRESH_NAME`. It uses an isolated Cargo target directory, tests default plus feature debug/release builds, explicitly executes ignored development oracles, checks format/Clippy, replays four C smoke fixtures against both builds and compares their public C symbol sets. It also checks every original production Rust file, all three executable profile contracts and the session/header contract against frozen `64123c509e861ddd522631b293eadebdaca11341`; only the feature-gated Rust module declaration is stripped for the lib.rs comparison. Rust compile-fail examples verify borrowed bytes cannot outlive their owner or be mutated. The original bounded mutations/truncations provide 2,040 parity comparisons, and the new Node development validation oracle independently checks 178 supported-subset fixtures. Neither is a complete standards/security suite.

The eight direct allocation fixtures cover a 4MiB source, 512 types each containing 4,096 parameters, 200,000 instructions, 128 controls, 4,096 operands, 65,536 v3 element indices and small/200,000-target branch tables. Their largest observed requested heap peak is 5,251,097 bytes for the signature-heavy fixture; the matching total reservation peak is 5,252,361 bytes, including fixed state. Those are per-fixture host observations, not the maximum over every admitted module and not a deployment memory guarantee. Branch-target count changes source size and work but leaves scratch reservations unchanged. The counters report real observations or explicit reservations; no unavailable measurement is replaced with zero.

The API has no executable conversion, cache identity, C symbol, guest invocation, WASI adapter, activation/release routing or new limit. The full 52,008,982-byte FieldLog candidate is not passed to it; it exceeds the unchanged 4MiB source ceiling, and the other previously measured function/global/control/instruction/memory/import gaps remain. The experiment preserves all Swift/ICU corpus requirements rather than admitting it. Physical experimental validation, full standards suites, coverage-guided fuzzing, independent review, cache/execution design, full Swift admission and OTA/GA remain unqualified.

Reference: the official WebAssembly [validation algorithm](https://webassembly.github.io/spec/core/appendix/algorithm.html) and [instruction validation rules](https://webassembly.github.io/spec/core/valid/instructions.html). Only the existing selected-profile numeric/control/function/memory/table forms are admitted; the reference's additional proposals/types are not implicitly supported. No third-party engine implementation or fixture was used.

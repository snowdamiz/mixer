# Independent observer host source: pre-candidate authoring receipt

The reviewer authored all 28 planned leaf files, one package-peer assertion
harness and one bounded runner under `host/`, using only the previously sealed
old-source inputs, selected contract and preaccess plan. Candidate observer,
producer host leaves/tests/runner, profile additions and implementation packet
contents remain unread. Root supplied a prose producer-progress summary during
authoring; it contained no candidate code or test assertions and did not change
the independent controls. The original three-member preaccess plan seal remains
unchanged.

`authored-sources.sha256` is the exact 30-member source inventory. The runner
contains its own explicit 28-leaf list plus harness name, requires the manifest
hash as an argument, rejects any different inventory and verifies every source
hash before and after its future run. No host code, Python syntax checker, JDK,
compiler, runtime or candidate has been executed/read to validate these authored
sources. Syntax/signature defects, if found after root admission, will be fixed
in a separate source revision with the original bytes and assertions retained.
The matrix currently expands to **287 named cases by source inspection**, not
287 executed cases or passes.

The platform recorder independently separates add entry, acquisition, fault,
return, removal entry, effect, fault, return and retained callback delivery.
It records exact object identities. Insets ownership changes occur at the
modeled acquisition/removal effects, so before-acquisition reentry cannot be
mistaken for a listener already installed. A delayed-removal control intentionally
retains all eight modeled registrations despite eight normal returns; late
callbacks must still be inert. The leaf has no observer retirement, generation,
retry or constructor-publishing decisions.

The harness calls the actual `Observer` methods and saved listener instances.
Reflection uses the old source's `generation` field to set exhaustion and its
`attachment` field to deliver detach during early registration before that
listener reaches the platform. It never translates the lifetime algorithm.
Every acquired or uncertain registration is checked against fake platform
add/remove calls, exact target/listener identities and actual active records.
Clean capture/current controls prevent an always-reject implementation from
passing. Wrong-thread checks include unchanged layout and low-memory callbacks
and terminal origins of close, detach and constructor failure.

Fatal tests include each add before/after acquisition, each removal before/after
effect, primary acquisition/invalidation failure plus every cleanup position,
ordinary/fatal combined cleanup, eight simultaneous cleanup Errors, original
fatal identity, suppression disabled and self-suppression. With ordinary standard
Throwable suppression available, the executable oracle checks that each injected
failure is reachable in the bounded thrown/cause/suppressed graph. If a candidate
uses another bounded diagnostic representation, root must review that public
contract before a separately recorded test-adapter amendment; missing diagnostics
must not silently become a pass. No JVM allocation-failure behavior is claimed.

The clean-control cleanup permutation is used only to verify deterministic
eligible-slot projection in fault cases; eligibility, no later add, single
removal, late-acquisition cleanup and failure identities are independent
assertions. Repeated close checks no new cleanup attempts; it does not impose an
extra requirement that a previously recorded failure can never be rethrown.
Dead-VTO behavior permits an ordinary diagnostic failure while requiring no
platform removal on the dead or replacement target and cleanup of other slots.

The future runner requires root to provide absolute frozen observer/JDK paths
and expected hashes. It discovers no toolchain or process list. It copies the
exact observer bytes to owned scratch, compiles the closed explicit source list
with Java 17, no annotation processors and empty class/source paths, then runs
the assertion main with `-ea`. Each child has a 45-second bound. It retains full
argv/stdout/stderr, source/class/tool identities and timeout/failure/cleanup data,
then deletes only its own temporary directory. Those are authored behaviors,
not yet observed runner behavior.

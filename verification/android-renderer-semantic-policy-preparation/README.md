# Renderer semantic obligation proposal

The final proposal preserves exactly 24 original subjects, their categories and
every original case ID from the released 280-subject checklist. It records exact
source/class/descriptor/instruction identities, source-specific state and return
requirements, and original test-control candidates with their exact source hash.
Every execution join is null. No original case is deleted or called passing.

Scalar authority predicates, count updates, reference-pair constructors and the
first-failure ledger have finite state/identity obligations. Journal and native
snapshot constructors also have actual selected callback boundaries. Each such
emitted tuple has its own seven-state requirement and independently configured
typed value/content oracle. Unhooked getters need finite actual outcomes; names
such as close or loss never invent a native callback. Indirect getter/event/
cleanup calls still require their actual enclosing or exact native-site joins.

The initial draft incorrectly classified most unhooked getters as callbacks.
Direct inspection of the selected leaves corrected that before release. Both
drafts remain as unselected authoring history. The final refinement separates
each hooked tuple and uses output-argument plus enclosing completion evidence
for the void location getter. No callback deletion or runtime acceptance follows
from static analysis. Receiver implementation resolution remains mandatory.

The control candidates identify exact public main methods and real case selectors.
The assertion index is source navigation, not evidence that any particular
assertion was executed for a particular subject. The final producer must bind
fresh source/class/context, actual original subject identities, state/callback
events, exact typed outcomes and independent literal expected values. Existing
receipts cannot be transferred by source line, method name or neighboring hook.

Runtime allocation-failure tests, unresolved transitive helper outcomes, final
policy review, complete fresh matrix, canonical integration, native, OTA and GA
remain pending. Preparation executes no product code, compiler, host test, UI,
capture or process inventory and changes no canonical source.

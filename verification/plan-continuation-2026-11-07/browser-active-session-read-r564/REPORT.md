## Executed first missing boundary

The restricted real RuntimeOwner starts normally with catalog109. The test executes bootstrap, begin, actual synthetic signed RS256 PKCE exchange, claim and activation, receives a genuinely rotated cookie, reopens the durable active snapshot and opens actual Vault.Active. It does not directly fixture-activate or replace runtime phase.

The frozen `mixer_browser_load(cookie_digest, config_digest)` then supplies a current browser snapshot under its browser FOR SHARE lock and lifetime/config checks. It performs no current authorization revocation admission. After real committed updates revoking each of the principal, family and credential, the restricted lifecycle connection still returns a decodable active snapshot. The public read API releases no active result in all three cases. A direct read of `public.mixer_authz_principals` through that same non-superuser lifecycle login returns SQLSTATE **42501**. The exact first unsupported operation is therefore current active identity/linkage admission on the dedicated lifecycle boundary, after raw active snapshot discovery and before any authenticated DTO or dispatcher call. A decoded active snapshot, valid ciphertext and storage_ready cannot satisfy that boundary.

This does not prove every possible future composition impossible. A successor needs an explicitly designed current-authority operation and reviewed lock/publication contract; widening ordinary preauth load or trusting the snapshot would bypass the demonstrated requirement. Schema/catalog/grant changes were expressly excluded here. No new hypothetical SQL operation, authority flag or fake active status was used.

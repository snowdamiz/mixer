PROOF
1. The earlier 011-open-owned-window.command.json supplies only -CurrentDeviceUDID; it did not test a keyboard override or a custom device set. Root recovery separately records deletion of 4CE0ECC9 and both protected devices Booted. These are historical receipts, not fresh observations.
2. Installed Simulator 16.0 (1063.4), in Xcode 26.6 (17F113), SHA256 8b2b67d05d33948bfcb157febed782524c68023972f995945f1fb2243b0d2a29, has actual callsites beyond strings. At 0x100010fc8/0x100010fe4 it reads DeviceSetPath using NSUserDefaults.standardUserDefaults/stringForKey:, then branches to deviceSetWithPath:error: at 0x10001103c when the value exists; absent value uses defaultDeviceSetWithError:.
3. At 0x10001b9e0/0x10001b9fc it reads ConnectHardwareKeyboard through standardUserDefaults/boolForKey:. The returned byte is captured at 0x10001ba8c; the block beginning 0x10001babc passes it to setHardwareKeyboardEnabled:keyboardType:error: at 0x10001baec. This supports a process argument affecting the real keyboard read. It does not prove complete action scope or no side effects.
4. The same binary defeats the stronger no-shared-preferences claim: initial-device selection calls simDeviceSelected: at 0x10000fad4. That method (IMP 0x100014960, independently linked through relative Objective-C method metadata) connects/boots the selected device and writes its UUIDString with standardUserDefaults/setObject:forKey: under CurrentDeviceUDID at 0x100014a3c. Supplying an argument-domain override does not redirect this setter into the volatile domain. A custom device set selects device storage; it does not provide a separate application preference domain. No observed branch in this method exempts custom sets.
5. Apple documents argument-domain precedence/volatility and per-user persistent application defaults. The installed open(1) manual documents -n as a new application instance and --args as main argv delivery; neither promises a separate preference domain. Apple directs simctl users to installed help. Help here documents --set <path>; no official published guarantee of complete Simulator preference/process isolation was located. Forum users' DeviceSetPath examples were excluded as API guarantees.

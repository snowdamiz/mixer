Caller injection remains a real boundary. SwiftRunFailure.code is public,
and the lower Fault/Meter/Reader/cleanup APIs can receive an arbitrarily long
static string, including leaked dynamic storage. A different direct caller
can also supply an existing failure/control/Frozen policy. L_str=5,080 is not
a theorem about those callers or static strings generally. The exact caller
contract requires the unmodified loader-produced proof, fresh control, the
selected closed specializations, and no intervening mutation. A new caller
needs a complete new provenance graph and actual UTF-8 bounds for every
direct and nested string input. check.py can check actual supplied strings'
UTF-8 extents, but deliberately reports that such length evidence does not
qualify a new caller or close nested carrier provenance.

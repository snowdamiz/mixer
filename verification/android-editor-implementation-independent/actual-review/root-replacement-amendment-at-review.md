# Selected ordinary accessibility replacement amendment

This amendment selects a narrow correction of the frozen Android editor candidate
`99ee53d6cf73cc062d5f39f7caa743dfed68f0f22522788adabe83159cacc9cd`.
The candidate's two ordinary ACTION_SET_TEXT failures remain observed product
gaps. Its source is immutable; implement in a separate complete-source derivative.
The cleanup selection and mandatory independent addendum remain binding.

The source-backed preparation is
`verification/android-editor-implementation-independent/replacement-preaccess/replacement-protocol.md`,
sealed by `89fef50e796ef1e1952301be04554e09404f2d00a3d6926a73dacfed0554728a`.
Its platform algorithm and ordering are retained. No key, replacement, selection,
or accessibility algorithm is reimplemented instead of calling the native super.

1. Recognize ACTION_SET_TEXT before entering the generic widget native frame.
   Check main, the original current field/Record/View/roster and ordinary Mutation.
   Invalid payload, stale entry or arbitrary nested input refuses before native
   execution, without fabricating a partial-native failure. Preserve the existing
   nonnull, bounded plain proposal policy, including currently admitted Annotation
   spans. Snapshot the actual CharSequence and Bundle used by the platform call
   into owned stable values; validate that snapshot and original authority before
   any predecessor revocation. Do not validate one mutable value and pass another.
2. Reserve one field-only replacement operation. It excludes another replacement,
   connection creation, adapter dispatch and incompatible bind/prepare/attach.
   It participates in existing disposal-busy accounting, grants no target lease,
   and allocates no new owner/core slot or asynchronous work. Close an existing
   predecessor exactly once against Eold before the accessibility super begins.
   An ineligible, deferred or uncertain close prevents replacement; no transaction
   or commit barrier may be bypassed. With no predecessor retain the precise
   absence/returned disposition. Revalidate original live authority after close,
   and remove all old-target cleanup authority before allowing Enew.
3. Use a separate exact field/Record/View/original-Mutation continuation for this
   one native accessibility call. Its one guarded two-argument setter may admit
   Eold to one Enew identity. It must never weaken ordinary EditorLease equality
   or reuse an old target/cleanup Mutation. First Enew observation may occur in
   movement/selection before text watchers, inside the setter, or at its return;
   allow that only within the selected single native setter invocation. Thereafter
   every relevant callback and final check must see exactly Enew. A second setter,
   second distinct new identity, return to Eold, wrong field/roster, or arbitrary
   input refuses and reports any already-executed uncertainty. Equal content is
   not identity. Recheck the actual closure's default factory/movement/delegate
   premises; do not silently admit an unsupported branch. Prefer the official
   passive getEditableText getter for identity checks, with a faithful host leaf.
4. The owned input filter must admit the validated replacement proposal under
   this exact operation even though the predecessor is permanently revoked.
   Replacement text watchers coalesce feature delivery, without suppressing
   required native super callbacks. Selection, lifecycle, paint and service
   suffixes stay inside the operation through the entire accessibility super,
   including selection after setText returns. Actual loss latches remain effective
   immediately. No loss/gain or successful replacement revives an old adapter.
5. Select exactly one synchronous ordinary textChange event after a successful
   complete native replacement and final original-authority/Enew/text/selection
   validation. This applies to same-value and empty-string replacements as well.
   The native setter still runs for those cases. Determine empty selection from
   the pinned platform/default movement path; do not invent a selection rule.
   A clean native false result with no setter, no buffer change and valid original
   authority returns false without a feature event. A claimed true result without
   the selected replacement, partial mutation or exception is not clean refusal.
6. Capture the exact event string before clearing native continuation authority.
   On the healthy path, release the replacement guard after the platform super
   and all native postchecks finish, then enter the existing synchronous feature
   event path. A compatible Binding echo must preserve Enew, selection and native
   composition; later fresh connection creation may use Enew under ordinary
   facts. After feature delivery only the existing completed-result/scalar return
   rule is available: no native getter, second event, callback postcheck or use of
   successor authority. This is ordinary feature dispatch, not synchronous owner
   cleanup resumption. Do not buffer unrelated text events or create edit replay.
7. Observe first failure/fatal before cleanup; preserve fatal precedence and
   terminal uncertainty. Busy remains through applicable native balancing,
   cleanup, restoration and reporting, then clears last without synchronous
   owner/coordinator resumption. No old target may be closed against Enew. A
   native change whose final authority cannot be validated is not rolled back or
   falsely reported as successful. Deferred Handler failure remains pending.

without a connection; old close before setter; null/invalid/nested no-call

run the complete prior host closure plus the new positive compatibility cases.
Official SDK cross-compilation remains allowed. Native runtime, public V2,

Coordinated implementation refinement: reserve a no-native-authority SNAPSHOTTING
phase after main/current entry capture and before mutable payload evaluation, so
payload callbacks cannot start nested input. Invalid proposals release cleanly
without revocation. A separate Replacement/Record binding and Input
replacementBegin/End pair may provide exact disposal-busy custody. The reservation
allows only its own captured field/Eold predecessor drain, with exact operation,
record and attempt checked before consuming close; it does not broadly ignore
replacement busy in editorCloseAllowed. Ordinary native-depth, operation and
commit barriers remain. Foreign attempts gain no close permission. End requires
the exact operation and completed callback/setter suffix, and clears busy last.
No additional owner/core or coordinator changes are selected. This refinement
was coordinated before dependent producer edits.

Independent baseline findings also select final tuple/roster/target checks after
any identity getter and dispatch through captured `lease.target`, never a mutable
attempt target. The private close predicate takes exact record/attempt arguments;
an active reservation admits only its own captured Eold predecessor in CLOSING,
and drain entry checks that tuple again before consuming close.

EditorInfo supported-input amendment: require nonnull exact runtime class
`EditorInfo` before attempt creation, predecessor revocation, native creator or
output effects. A subclass is a clean no-call refusal, leaving caller output and
any healthy existing connection unchanged. The public surrounding-text and
gesture setters and getters are overridable; the hidden final setter is absent
from the SDK. Thus arbitrary overrides cannot be proven to clear private payload
through the supported public API. This explicit restriction does not claim
universal EditorInfo subclass support. Ordinary exact framework EditorInfo retains
same-object population, final gesture/output checks and honest cleanup; reset
plain public metadata after mutating setters where necessary. Preserve the
original subclass failures and author explicit pre-effect refusal controls rather
than relabeling them as successful scrubs. Platform compatibility and public/native
qualification remain pending.

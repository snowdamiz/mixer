## Exact loader formats

All words are little-endian u64. Both records begin with a512-byte header:
magic at0, version1 at8, header size512 at16 and total byte count at24. Sections
are positive and contiguous with no tail bytes. The loader's compiled source
count is146 and host count11. The historical source144 runner hard-codes144;
its retained build preimage is deliberately rejected by this oracle. Reusing that
runner unchanged would be wrong. New source files would require a separately
coordinated count/header/source-manifest rebind; this fragment adds no file to
the product distribution and is intended as an inline append.

Build magic is `MIXLBD01`; source/host counts are at32/40, four section lengths
at48/56/64/72, executable extent at80 (positive, at most64MiB), target bytes
`aarch64-apple-darwin` at88 with zero fill to152. Sections are full compile
manifest (at most65536), compile argv (at most16384), compile environment (at
most16384), and version stdout (at most16384). Digests at152/184/216/248/280/312
are respectively manifest, argv, environment, version, compiler executable and
actual output executable. Bytes344..512 are zero. Total cap is128KiB.

The five embedded environment keys are:

1. `MIXER_LOADER_MANIFEST_SHA256`
2. `MIXER_LOADER_COMMAND_SHA256`
3. `MIXER_LOADER_COMPILE_ENV_SHA256`
4. `MIXER_LOADER_COMPILER_SHA256`
5. `MIXER_LOADER_COMPILER_VERSION_SHA256`

The compile environment preimage excludes exactly these injected keys to avoid
identity recursion. The build header's compiler/version digest order is
deliberately different: the loader maps its slots0/1/2/4/3 to the embedded keys.
The manifest itself is opaque bytes to the loader, so separately reviewing its
complete actual source/host/tool/orchestration correspondence is mandatory.
The source146 composition uses canonical compact sorted JSON with `distribution`,
`compiled_source`, `host_support`, `orchestration`, `tools`, `root_releases`,
`private_route_cfg`, `test_overlay`, `genuine_loader_fixture_runtime` and
`selected_policy_or_whole_quote`, with schema1. Production source and an exact
test overlay must never be conflated. The oracle checks the key source/host/cfg
relationships; it does not authenticate or qualify arbitrary tools/release rows.

Session magic is `MIXLSE01`; actual source extent is at32, four section lengths
at40/48/56/64, original validator limits at72/80/88/96/104, nonce at112, source
digest at144, full build digest at176 and actual executable digest at208. Four
section digests are at240/272/304/336; bytes368..512 are zero. Sections are
source File identity (exact64), actual process argv (at most16384), sorted
process environment (at most16384) and raw absolute cwd (positive, less than4096,
no NUL). Total cap is64KiB. Source File identity is device/inode/length/mode as

four i64, encoded as their little-endian bit patterns.

Both argv/environment lists encode count:u64 then repeated length:u64 + raw
bytes. Count is at most64; argv is nonempty; each string is less than4096 with
no NUL; total at most16384. Environment entries are `key=value`, nonempty key,
strict lexicographic raw-key order and no duplicates. Runtime environment

exclude the five compile keys. Raw non-UTF8 bytes are preserved. The actual
loader compares all observed process bytes, session commitment and nonce.

# Hosted membership and private storage contract

Status: proposed root freeze for the next bounded development slice. This is an implementation blueprint, not an implemented migration or authorization service. It extends the accepted [identity contract](hosted-identity-contract.md), [pure verifier](hosted-token-verifier.md), and their root acceptances. Product-plan §§6.4, 13, 17 and 18 remain binding. Observed starting revision: `4d6ab07e159db2e02a2433396e9a83f275c33a40`.

The vertical slice is a verified human identity → current database membership → private v3 artifact upload/read → immutable actor audit and principal-bound idempotency. Only `artifact.read`, `artifact.upload`, `audit.read` exist in this authorization registry. Release validation/publication/promotion/rollback/halt, service/CI grants, member administration, login/provisioning, public delivery, signing and dispatch remain unsupported and fail closed. Existing Go migration 001, wire vectors and historical events stay byte-for-byte unchanged. No production publication or credential operation is authorized by this document.

## Schema freeze blueprint

Use additive Ecto migrations under `hosted/priv/repo/migrations/`, serialized by root after contract freeze. New schemas are `mixer_authz` and `mixer_hosted_release`; do not reuse or mutate `mixer_release` or reinterpret its rows. Every table below has `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY`. Oban remains in its current separate schema/role contract. PostgreSQL extensions are unnecessary for this slice.

Common types: internal principal/binding/family/membership IDs are non-recycled UUIDs; public org/project/app/environment IDs retain protocol `ValidID` (1–128 ASCII bytes, `[A-Za-z0-9_.-]`, exact case). Use text with `COLLATE "C"`, byte-length checks and no normalization or wildcard semantics. Digests are exactly 64 lowercase hex characters or 32-byte `bytea`, consistently selected at schema freeze. Revisions are positive signed `bigint`; overflow aborts. Token/valid-after times are bounded integer Unix seconds, 0–2^53−1, preserving verifier precision. Optional membership windows use the same seconds; `not_before < expires_at`, inclusive start/exclusive end. Timestamps used for display do not decide authorization.

| New `mixer_authz` table | Required columns, keys and constraints |
| --- | --- |
| `identity_trust_profiles` | `profile_id` text PK (verifier's 1–128 UTF-8-byte bound), `current_version` 1..2^31−1, `enabled`, exact `issuer`/`client_id`/`identity_class`, `revision`. Match the verifier's issuer/client bounds, human/service closed class. This is the durable admission/incident-disable row; no JWKS, fetch URLs or key cache lives here. Emergency disable may retain version while incrementing revision. Re-enable or changed audience/endpoint/trust policy requires a strictly higher version. Issuer/client/class are immutable per profile ID: changes need a new profile ID and explicitly provisioned immutable bindings, never an in-place binding reassignment. All changes lock this row exclusively and increment revision. |
| `principals` | UUID PK, `kind` human/service, `status` active/disabled, `valid_after`, `revision`, optional `owning_organization`. Human owner is NULL; service owner is required with FK. Kind/ID never change or recycle. First slice rejects service admission regardless of token scope. |
| `external_identity_bindings` | UUID PK; FK profile/principal; exact issuer/subject/registered-client/class; unique `(profile_id, issuer, subject, registered_client)`. Subject 1–256 UTF-8 bytes. Principal/class must agree with profile. Binding tuple/principal immutable, no runtime insert/update/delete, no email column used for linkage. A later linking workflow needs its own contract. |
| `credential_families` | UUID PK, binding/principal/profile FKs, `status` active/revoked, `valid_after`, positive `revision`. Composite FK to binding's exact immutable principal/profile tuple; family cannot move to another binding. No hard deletion. A family is a durable revocation boundary, not an inferred JWT claim. |
| `credential_references` | `(binding_id, jti_sha256)` PK; family FK with matching binding/principal/profile; `accepted_issued_at`, `accepted_expires_at`, immutable. Hash is SHA-256 of exact UTF-8 verified `jti`; namespace comes from binding/profile/issuer/client, never a bare digest. Require exact token times for this registered reference. No raw bearer/refresh token. |
| `credential_denials` | Same credential composite PK/FK, `denied_at`, `retain_until`, revision/reason code. Insert/update/removal locks the existing profile/principal/family first. An absent denial row cannot be locked, so its family is the fence. Retain at least through credential expiry + 30 seconds; future pending privileged intents also require terminal cancellation or a retained tombstone. No runtime DML. |
| `organizations` | Public org PK, active/deleted status, revision. No physical deletion/reuse in this slice. |
| `projects` | `(organization, project)` PK, FK org, active/deleted status, revision. |
| `applications` | `(organization, project, app)` PK, composite FK project, active/deleted status, revision. |
| `environments` | `(organization, project, app, environment)` PK, composite FK application, active/deleted status, risk class development/staging/production, revision. Labels confer no release permission. |
| `organization_authorization_heads` | Org PK/FK, positive `revision`. Precreated atomically with org; never lazily created by runtime. Locks all organization-wide policy and parent lifecycle changes. |
| `project_authorization_heads` | `(org, project)` PK/FK, positive `revision`. Precreated with project; fences project memberships, app/environment lifecycle and later grants. |
| `organization_memberships` | UUID lifecycle PK, org/principal FKs, canonical role, explicit `project_binding` = `organization_wide` or `organization_only`, status invited/active/revoked, validity window, revision, grantor audit reference. No implicit org-role expansion. |
| `project_memberships` | UUID lifecycle PK, composite project FK, principal FK, canonical role, status/window/revision/grantor audit reference. Regrant after revoke creates a new lifecycle ID. |

Canonical roles are exactly `owner`, `administrator`, `developer`, `release_manager`, `billing_manager`, `viewer`. Role CHECKs reject the old Go reader/editor/publisher names. For a given org/project, union active eligible explicit memberships, then apply all restrictions. The first slice has no denial-rule or custom policy DSL; unknown policy representation denies rather than being ignored. An org-only membership establishes org visibility but does not grant project visibility or private data. Organization-wide binding is explicit stored policy covering active projects; a project membership covers exactly one project.

| Role on target project | artifact.read | artifact.upload | audit.read |
| --- | --- | --- | --- |
| owner / administrator / developer | yes | yes | yes |
| release_manager / viewer | yes | no | yes |
| billing_manager | no | no | no |

Each yes additionally requires the corresponding exact verified OAuth scope. Missing scopes deny; arbitrary claims/headers confer nothing. Project membership can make a project visible even when its role has no supported private permission; that distinction yields 403 rather than granting data. An active billing-only project member therefore gets 403 on artifact/audit, while a nonmember gets 404.

Indexes: every FK referencing composite key; `(principal_id, organization, status, project_binding)` for organization memberships and `(principal_id, organization, project, status)` for project memberships; credential lookup by `(binding_id,jti_sha256)`; family lookups by immutable binding; denial PK. Add partial unique active lifecycle indexes per `(principal, scope, role, binding-kind)` to prohibit duplicate active grants without preventing a revoked history. Every policy lookup is an exact indexed target query. Fetch at most 65 applicable memberships; >64 is `authorization_unavailable`, never a truncated allow. An owner fixture enforces the same cardinality bound. No unsupported grant tables are created now.

`credential_references` resolves the verifier's `credential_ref` to an existing family. The current verifier exposes no `sid`/family claim and no registration workflow exists. Unknown `jti` denies. Tests explicitly preprovision signed synthetic tokens, including a refreshed-token `jti` mapped to the same principal/family. This is not provider issuance, refresh, login or production credential lifecycle evidence. A real provider/bootstrap owner must later define how authoritative registrations arrive; runtime must not auto-register any correctly signed token.

## Database roles, resolver and RLS

Use separate `mixer_hosted_schema_owner` and `mixer_hosted_authz_resolver` NOLOGIN roles, neither superuser nor BYPASSRLS. Runtime login owns no schema/table/function/database and cannot SET ROLE to either. Resolver owns only the allowlisted SECURITY DEFINER functions; migration owner owns tables and policies. Resolver has no schema CREATE privilege after migration and no authz INSERT/DELETE. Revoke PUBLIC execution in the same transaction that creates each function; revoke PUBLIC schema CREATE and database TEMP for runtime, and do not grant runtime untrusted-language or extension creation. Default privileges must not accidentally expose future tables/functions.

| Role | Minimum privileges in this slice |
| --- | --- |
| API runtime | schema USAGE; EXECUTE only on enumerated resolver/policy helpers; scoped SELECT/INSERT on domain artifacts/audit/idempotency; SELECT and UPDATE of only sequence/hash columns on domain tenant heads. No direct identity/policy table SELECT or DML, no domain UPDATE/DELETE/TRUNCATE/REFERENCES. |
| Nonlogin authz resolver | SELECT on named identity/policy/resource-existence tables; column SELECT on artifact tenant/digest/normalized target metadata only (never signed bytes/blob/content); UPDATE(`revision`) on the five lock-bearing profile/principal/family/org-head/project-head tables only. Explicit SELECT and UPDATE RLS policies TO resolver using true on these five; SELECT-only policy on remaining authz tables. A simple SELECT policy TO resolver on artifacts supports the narrow target resolver, whose function checks current member visibility before returning metadata. No login and no runtime role chain makes this role usable outside the allowlisted functions. |
| Migration owner | Offline fixture/migration authority only. It creates rows, policies, guards and narrow functions; never appears in API/processor pools. The test harness can bootstrap through this isolated authority. Production member-management endpoints remain absent. |

Why the UPDATE column grant/policy exists: PostgreSQL 17.11 rejects `FOR SHARE` without UPDATE privilege (`42501`); granting only UPDATE(`revision`) with SELECT-only RLS silently makes lock rows invisible. The [real disposable probe](../verification/hosted-membership-storage-contract/run-3/receipt.json) proved a resolver UPDATE policy is also necessary. Every lock helper must assert exactly one row found after **each** lock; success from an empty `PERFORM` is forbidden. No exposed helper executes an authorization UPDATE. This narrow grant is lock plumbing, not runtime membership-write authority. It needs requalification against the deployed PostgreSQL version/topology.

All resolver functions: explicit schema-qualified objects/types/operators where relevant, `SET search_path = pg_catalog`, `SET row_security = on`, no dynamic SQL, no tenant-selected identifiers, bounded arguments, bounded output, no PUBLIC EXECUTE, no exceptions containing identity parameters. Use `VOLATILE` for lock/fresh-state helpers; do not annotate a time/current-policy resolver IMMUTABLE or LEAKPROOF. A function must not return membership lists or arbitrary rows. Authz policies never call a function that queries the same policy-protected table under runtime; resolver SELECT policies are simple role-specific predicates. Domain RLS may call resolver helpers; authz policies do not query domain tables, avoiding a cycle. The probe retains an intentional recursive-policy `42P17` rejection and a passing nonrecursive pattern.

Required narrowly typed helpers (names are internal, not HTTP APIs):

| Function/seam | Input/output and constraints |
| --- | --- |
| `lookup_binding/credential` | Exact profile/issuer/client/subject/jti digest plus verified class; returns only matching immutable principal/binding/family IDs, never creates anything. Preliminary lookup grants no permission. Reassert the immutable mapping after locks. |
| `lock_admission_rows` | Locks one profile → principal → family → org head → project head, in that order, using `FOR SHARE`; returns exact IDs/revisions or denial. No `SKIP LOCKED`. On missing row abort; a nonvisible target is reported through normal nonenumerating errors, never a different lookup endpoint. |
| `decide_current` | A new SQL statement **after** lock acquisition, READ COMMITTED: exact profile revision/version/enabled and immutable identity match; human active principal; existing active family; credential registry and absent denial; iat ≥ both valid_after cutoffs; fresh token expiry; live target ancestry; windows, membership ceiling/scopes; bounded matches. Returns only decision/evidence for this identity and target. |
| `resolve_artifact_target` | Under admitted project visibility and `artifact.read` eligibility, return one digest's normalized target metadata, not payload. Recheck actual full target before repository read. Never accepts a guessed environment as authority. |
| `row_allowed` | Domain RLS bool, exact actual row tenant and resource target equal local bound context; action is supported; authoritative identity/credential/membership/time remain valid. Missing/empty/unknown/malformed context returns false, never wildcard. Audit uses a separate explicit project-only target. No `mixer.role` shortcut. |

All domain policies must check actual row organization/project plus app/environment/platform/runtime/digest where relevant. Only `audit.read` permits selecting successful audit rows; no Oban/outbox internals are exposed. Allocate event IDs from the locked tenant head and insert audit without returning audit content, so upload does not need audit-read permission. Artifact INSERT requires `artifact.upload`; audit/idempotency INSERT require the same admitted upload context, immutable principal and current tenant head. Idempotency SELECT is a repository-only upload retry operation matching tenant/key **and immutable principal/action/target**; it never acts as an unrestricted result endpoint. A different actor/action/target's hidden row still conflicts with the tenant/key unique constraint: map that collision to 409 and roll back without disclosing its body. For upload conflict detection, an upload context may SELECT only the exact target artifact, even if the bearer lacks `artifact.read`; do not return its body to the client. Direct missing-context SQL sees zero private domain rows; authz direct SQL receives permission denied.

RLS protects the trusted API against omitted predicates and routing mistakes. Runtime can set GUCs and resolver parameters, so arbitrary SQL/in-process compromise can impersonate authority. No claim of hostile-API or SQL-injection immunity follows. The DB does not cryptographically verify bearer tokens. See [PostgreSQL RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html), [locking SELECT privilege](https://www.postgresql.org/docs/17/sql-select.html), and [SECURITY DEFINER hardening](https://www.postgresql.org/docs/17/sql-createfunction.html).

Startup rejection must inspect the actual runtime connection before serving protected traffic: exact schema version/object privilege manifest; every private table FORCE RLS; no owned schemas/tables/functions/database; no direct or reachable owner/resolver/role with superuser, bypass, create-role/database, replication, server-file/program or blanket data privileges; no broad schema CREATE or TEMP. Use `pg_has_role(...,'MEMBER')` for conservative transitive rejection, including NOINHERIT chains that permit SET ROLE; reject unexpected membership rather than assuming NOINHERIT is safe. Check database-owner identity and effective/session identities explicitly. Compare function owner, SECURITY DEFINER/search_path/row_security, ACLs and policy definitions to the migration manifest; runtime cannot repair drift. The probe verifies narrow role acceptance plus BYPASSRLS and NOINHERIT owner-chain rejection as a candidate query, not a shipped startup guard or complete catalog verifier.

## Transaction and Elixir API freeze

```elixir
Authorization.with_authorized_transaction(verified_identity, command, fn context ->
  Release.Repository.upload_artifact(context, validated_artifact, idempotency)
  # or read_artifact(context) / Audit.list(context, cursor, limit)
end)
# {:ok, response} | {:error, closed_error}
```

`command` is an owned parsed value with fixed action, normalized route tenant and target reference. No role, actor or arbitrary Repo/connection argument is public. Upload input owns exact bounded body bytes, strict checked signed value, canonical manifest CBOR, digest, payload hash and derived target. Preliminary expensive parsing/cryptographic work precedes locks; policy and current artifact trust/runtime checks are reasserted inside. A valid upload signature never grants membership, release rights or compiler eligibility.

1. Runtime/key owner supplies the current verified identity; crypto validation remains independent. No raw token/email/full claims enters authorization, SQL context, audit, job args or logs. Exact profile version must match its durable admission row. Stage and validate candidate trust first; commit the durable new version/disable under exclusive profile lock/revision, then publish its matching local generation. Every propagation gap/mismatch fails closed; never fall back to an older enabled version. Emergency disable can retain version; re-enable requires a higher version. The key-owner slice does not implement this DB write.
2. Start **one** `Repo.transaction` at READ COMMITTED on the actual repository connection, never SQL Sandbox-only evidence. Set parameterized transaction-local settings on that same connection. Use five-second overall transaction and maximum statement deadline, a 250 ms lock timeout and decreasing statement budget from a monotonic deadline; the callback cannot extend it. `statement_timeout` alone does not bound a multi-statement transaction. An application/DB deadline breach rolls back; recheck deadline and fresh clock immediately before effect persistence. No nested authorization, network, signer, async task or customer code is allowed inside.
3. Lookup immutable binding/credential, then lock profile → principal → family → org head → project head, all shared. Sort IDs within a class if a later multi-target action is supported; this slice has one target. No locks on a missing membership/denial are relied on. Query current state in a **separate statement after the final lock**, including time and membership; no stale transaction snapshot or positive allow cache.
4. Upload binds actual signed app/environment/platform/runtime/digest; read resolves stored normalized target under project visibility then rechecks; audit binds project-only target with all artifact fields absent. Validate live parent rows. Mutation then locks its existing domain tenant head `FOR UPDATE`, after every authz lock. Do not upgrade authz locks inside callbacks. No release action exists.
5. Authorization creates a per-invocation internal context bound to owning process `self()`, actual Repo, checked-out connection/transaction identity and backend PID, opaque fresh reference, action, exact target, policy revisions, principal/credential and transaction deadline. Store the active invocation reference in the owning process for the callback duration and remove it in `after`; repository checks owner, active reference, Repo in-transaction state, connection/backend and exact operation/target every call. Closed contexts, foreign connection/process/Repo, spawned tasks and copied structs fail. Do not expose a constructor or return an authorization ticket; returning a captured context does not make it reusable. Ecto/DBConnection implementation details must be frozen and tested against the pinned versions; process dictionary alone does not identify a transaction.
6. Same transaction stores domain mutation, successful immutable audit and idempotency result. Any failure rolls all three back. Commit uncertainty returns storage-unavailable; same-key retry starts with fresh identity and authorization. No raw-token retention. If Oban is included, its job insert uses this Repo transaction and retains no dispatch authority; otherwise the domain/job atomicity gate remains explicitly pending.

This opaque context is API discipline within trusted BEAM code, not an unforgeable object against malicious code in that process. SQL GUCs provide defense against missing predicates. Neither substitutes for the verified-identity owner and repository entrypoint.

All authorization writers, including owner test fixtures, acquire conflicting locks in the same canonical order before writes, increment affected state/head revisions and emit management evidence. Profile disable needs the profile exclusive lock; principal disable/valid_after needs profile then principal; family denial/revoke needs profile/principal/family; membership and target changes additionally need org/project heads. Organization-wide changes need exclusive org head; project-specific changes take shared org head then exclusive project head. This serializes authorization at both race directions without locking every missing grant. No writer acquires a lower-order lock after a higher one; administrative bulk IDs sort lexically. Revocation success waits for admitted operations, and a newly admitted operation after that commit denies. Already admitted work may commit before revocation returns. Preserve fresh token-time checks at admission and before persistence, while acknowledging a bounded transaction can commit just after token expiry.

## Private artifact, audit and idempotency storage

`mixer_hosted_release.artifacts` PK `(organization, project, manifest_sha256)` has complete normalized `app, environment, platform, runtime`, protocol/schema=3, guestABI=2/UI=1, original checked signed-manifest JSON bytes ≤64 KiB, canonical manifest CBOR bytes, signature bytes (64), payload SHA-256/size, immutable blob reference and creation actor/event reference. Composite FK binds full environment ancestry; platform is ios/android; runtime/digests match 64 lowercase hex; payload ≤4 MiB. PostgreSQL stores metadata/reference, not production payload bytes. A disposable local content-addressed blob fixture is acceptable development evidence and must not be called R2/durable remote upload. Stage/verify fixture blobs before policy locks; commit only an immutable reference with verified bytes, then collect orphaned staging objects outside the transaction. Multi-process blob durability/reconciliation is separately pending.

DB CHECKs compare every normalized scope/runtime/protocol/ABI/UI/payload field to its JSON projection with type checks and `IS NOT DISTINCT FROM`, rejecting missing/null/type-confused values; check `manifest_sha256 = encode(sha256(canonical_manifest_cbor),'hex')`. These structural checks cannot prove JSON↔CBOR equivalence or signature validity: the owned strict protocol parser/standard signature verifier must prove that equivalence and host/trust compatibility before repository admission. Freeze golden-byte parity before implementing persistence. No regex, JSON cast, DB hash or syntax check alone authorizes an upload/release.

The digest remains SHA-256 of **canonical manifest CBOR**, not payload or JSON. Artifact Ed25519 preimage remains `mixer.artifact.v3\0 || canonical_manifest_cbor`, exactly as `services/protocol/v3.go`; preserve strict closed envelope `{signed_manifest,payload}`, canonical base64, duplicate/unknown/case rejection, 6 MiB whole body/64 KiB signed document/4 MiB payload bounds and current host/root validity. No verifier fallback or protocol probing. First insert returns 201; a new key uploading an identical existing signed value/payload returns 200; changed immutable contents return 409. Same key returns the original exact status/body. Private GET returns the same v3 envelope and bytes; unsigned hosting metadata never changes signed scope. No `published` or `validated` flag can be set in this slice. Unsupported v1/v2/public/release endpoints reject explicitly.

`tenant_heads` PK tenant carries `last_event` uint64-compatible numeric, `audit_hash`, `state_hash`; serialized after authz locks. New `audit_events` PK `(tenant,event_id)` is append-only with actor/decision snapshots, exact target, action, reason ≤512 bytes, generated request ID, trusted source IP or NULL, decision/recorded times, previous/current state commitments and chain hashes. Runtime can INSERT/SELECT authorized records, never UPDATE/DELETE. A deferred constraint trigger or single narrow mutation routine must enforce head/event/idempotency linkage, no event ID gaps on rollback, exact actor from context and immutable hash/body consistency. Root must choose one before implementation; bare independent INSERTs are insufficient evidence.

Audit wire/storage is explicitly **hosted audit schema 1**, distinct from signed artifact schema3 and historical unversioned Go events. Preserve list envelope `{events,next}` and cursor `after` uint64/limit 1..100, but each hosted event includes `audit_schema:1`, immutable internal principal/kind, binding/profile ID/version, stable issuer/subject/client references, credential digest/family, authentication/decision time, policy/head/membership lifecycle revisions and exact target/action. Never return secrets, unrestricted claims or Oban details. Later role/name/binding lifecycle changes cannot rewrite the snapshot. Legacy Go data remains a separate historical stream, never assigned to the currently authenticated principal.

Freeze a new deterministic RFC 8949 CBOR audit preimage (fixed versioned field schema; integers/byte strings/text/explicit null; no floats/maps with ambiguous keys), `SHA256("mixer.hosted.audit.v1\0" || canonical_event_without_event_hash)`. Tenant-scoped previous hash is included; first previous hash is empty bytes. Domain-state commitment has a separately versioned deterministic encoding. Store exact encoded bytes and hash alongside a validated JSON display envelope; bytes are immutable. No change to Go Event JSON/hash preimages or v3 artifact/assignment signatures. Golden Go audit preservation and new Elixir deterministic audit vectors are separate assertions, not a false cross-language equality claim.

`idempotency` PK `(organization,project,key)` retains tenant/key uniqueness; key follows existing ValidID. Required fields: `idempotency_schema=1`, immutable principal ID, action, exact target encoding/hash, request hash version 1, successful status, exact response bytes, original event FK and creation time. Request hash v1 preserves Go's `SHA256(method || " " || normalized_exact_route_path || NUL || original_bounded_body_bytes)`; reject ambiguous path encodings before this point, do not reserialize JSON. Principal/action/target equality is independently checked, never inferred from a hash alone. A refreshed eligible credential for the same principal may retry. Current authorization, expiry/revocation and target visibility run **before** dedup lookup. Different principal, bytes, action or target is 409 without cached-body disclosure. Same match returns original bytes/status/event with no new event. New key on unchanged artifact produces its own successful upload audit as the Go behavior does. No successful read event is fabricated by ordinary GET.

An exact-target INSERT/unique-conflict race is serialized by the tenant head. Hash mismatch, immutable conflict, forced audit/idempotency failure, deadlock/lock timeout, DB loss and uncertain commit must be covered using real transactions/restart; no partial successful event or phantom cached response. Root must pin finite fixture/storage/admission budgets before implementation; membership bound is 64, request/body bounds above are fixed, and no global allow cache exists.

## Required executable acceptance and unresolved freezes

The [machine-readable required matrix](../verification/hosted-membership-storage-contract/required-matrix.json) is the executable owner handoff, not a claim of passing integration. Each future case runs real Phoenix HTTP, standard cryptographic verification and disposable PostgreSQL together unless its scope explicitly says otherwise. Producer and independent reviewer must freeze the actual source tree and retain exact command/tool versions/input hashes/output/cleanup. Native/physical, hosted-provider and GA claims require their own evidence.

Observed in this contract only: [probe.py](../verification/hosted-membership-storage-contract/probe.py) executed 19 real PostgreSQL pattern cases in [run-3](../verification/hosted-membership-storage-contract/run-3/receipt.json). Both lock race directions, lock timeout, transitive owner-chain rejection, missing context, no direct authz DML, nonrecursive resolver RLS and transaction-local cleanup passed. Run-1 failed before startup because the OS temporary socket path was too long; run-2 exposed the missing UPDATE-policy lock trap. All owned directories were removed; run-2/run-3 servers stopped. No existing DB cluster was touched. No hosted authorization/product migration, HTTP/provider mock, production resource, UI/device or R2 evidence was produced.

Root decisions before ownership freeze: approve the schema/privilege/function manifest and explicit org-wide membership semantics; coordinate durable profile row/version/disable with key-owner activation; pin transaction-identity implementation against Ecto/Postgrex; choose deferred constraints versus narrow atomic domain-write routine; freeze audit/state CBOR vectors, response/body budgets and local fixture blob durability. Production blockers remain real credential registration/refresh/bootstrap, member-management/audit workflows, selected provider/CI lifecycle, hosted Neon/R2/Cloudflare/Oban qualification, external security review and final product acceptance. They do not block this bounded host development slice. Root reported user-resumed computer use/simulator/emulator testing during this task; this lane remained host-only and did not start any native/UI process. Physical phones remain deferred.

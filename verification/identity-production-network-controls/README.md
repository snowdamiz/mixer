# Independent identity network collector controls

This packet records pure Python controls for the proposed targeted remote identity collector. It qualifies orchestration fault decisions for exact frozen source bytes only. It does not qualify actual Docker isolation, Linux namespace setup, image/tool execution, the two product methods, database migration state, OpenSSL fixtures, real cleanup, custody, artifact retention or any product/GA gate.

The independent vectors in `vectors.json` were derived from the frozen contract and existing product method assertions before the collector source was available. The executable controls keep the immutable image/config, source/lock, exact method names and semantic receipt facts independently written rather than deriving expected facts from the producer constants.

The controls exercise:

- Frozen source/lock admission, safe source paths, immutable AMD64 image/config roots, and explicit environment construction.
- Archive traversal, links/devices/duplicates/expanded-size limits; prepared archive exact membership/hash and contamination decisions.
- Namespace, capabilities, mount, publication, privilege and resource assertions, including PostgreSQL exposed-null metadata versus a published host port.
- Exactly two named successful methods in one complete ordered suite, strict event statistics, and every retained semantic fact including key-directory removal.
- Source mutation, command/aggregate output caps, monotonic deadline and cleanup reserve decisions.
- Exact retained-CID cleanup plans, sticky permission/identity refusal and unresolved create responses.
- Actual collector method and `run()`/`finally` wiring through a strict fake command transcript, including eight representative phase ownership states, cancellation, uncertain creation, denied execution, frozen primary failure, real receipt sealing and exclusively owned scratch removal.

Two test boundaries are explicit. Prepared-archive composition uses a tiny source-admission stub and substitutes fixed source/helper/Rebar preimages to exercise real membership, contamination, artifact pin and hash-composition decisions. Separate controls exercise the real frozen source/lock validator and independently hardcoded official bootstrap URL/version/checksum roots. Outer-wrapper fault controls override `collect()` to inject faults with representative owned records, then use the real `run()`, cleanup and seal methods. They do not execute the real collection phases or claim that those phases pass.

All command-looking values in wiring tests are fake transcript inputs. The tests use only stdlib modules, in-memory archives and exclusively owned temporary files. They do not launch child commands or use Docker, sockets, product imports, native runtimes, compilers or version probes. The Python version in receipts comes from the executing interpreter's metadata. Tests and frozen imports run with bytecode writes disabled and a 50-second alarm.

`run-controls.py --label <new-name>` copies both producer and control bytes into a new owned snapshot and runs those copies in-process. Each receipt binds exact hashes, the two-script source tree digest, command, interpreter metadata, duration, outcome and complete test log. Root must compare the selected receipt's producer hash to final delivery bytes. A later source edit requires a new selected receipt.

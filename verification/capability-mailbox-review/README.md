# Independent review of the experimental Rust mailbox

No actionable defect was found in commit `4e37b357ae029d9cdf5e5c6b4281d82f61b65f3a` within its documented, nondefault Rust-only scope. This is a scoped implementation review and host test result, not guest capability, native adapter, security, release, or GA approval. No production source was edited.

The reviewer exported all 47 implementation inputs from Git objects into a read-only ignored snapshot at `.build/capability-mailbox-independent-4e37b35/source`. The manifest digest independently matches `369b698053b2ca5217819679b9050e0a43a9947c9de87c0b66be4e1722ccbe49`; every exported file was checked before and after execution. The 12 frozen profiles, contracts, headers, decoder/executor, numeric, validation, FFI, and session inputs match the prior implementation base `b4f13ec9a78b882380a6cfba0a9607990ca9babe`. `feature-wiring.patch` shows only an empty nondefault Cargo feature and its conditional Rust module export. A real default-build consumer fails with compiler error E0432 when it tries to import the mailbox.

The review tests are independently authored. Public behavior is tested through a separate crate depending on the frozen VM snapshot. Private exhaustion/malformed-identity checks use a separately derived crate whose library is the exact original module bytes followed only by a review test-module declaration. The original snapshot remains untouched. The implementation's six private tests are compiled but filtered out of these three independent boundary tests.

There are 9 public adversarial tests, 1 allocator test and 3 independent private-boundary tests per build mode. Both modes passed all 13. Formatting and clippy with warnings denied passed. The frozen snapshot's existing default and combined-feature execution suites also passed; those are baseline regression checks and are not counted as independent tests.

On this macOS arm64 host the independent probe confirmed 984 inline metadata bytes, zero construction allocations, and a 64-byte first-lock standard-library allocation. Refusing that allocation in a child process aborts with SIGABRT. Its negative transcript is retained in each independent build log; this is an expected documented limitation, not graceful OOM handling. The default-API compilation rejection is also an expected negative probe. No unexpected failed test experiment occurred. Earlier successful-run logs are preserved as `.previous-1.log` files where subsequent output changed.

The review accepts the documented scope boundaries: this value has no counted process/session quota and cannot enforce retention of its owner through native exit; payload reservations exclude synchronization metadata, allocator overhead and caller/native/codec buffers; standard locking, copies and OS suspension have no hard real-time bound; payload bytes have no strict schema/grant/adapter authorization. The tests are finite host schedules, not a proof of all interleavings or a sanitizer result. The allocator measurements are platform observations, not a portable allocation promise or general OOM/no-unwind guarantee.

Still unqualified: guest imports/raw-token and guest memory contracts, VM fuel/byte charging, C ABI, counted registry integration, strict wire codec, actual native I/O/exit observation, Swift scheduler, activation or release admission, immutable package dogfood, physical iOS/Android, signing/store acceptance, operations, independent security review, and every GA gate.

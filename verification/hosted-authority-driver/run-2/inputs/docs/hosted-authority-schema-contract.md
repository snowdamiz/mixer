# Hosted current-authority schema and resolver candidate

Status: frozen isolated prerequisite for root selection and independent review. This is an executable additive `mixer_authz` candidate, not an installed product migration or accepted authorization service. It supplies a bounded W11/W16 prerequisite for product-plan §§6.4, 13, 17 and 18. The binding product scope remains unchanged.

The exact expanded [DDL](../verification/hosted-authority-schema-contract/probe/schema.sql), [resolver source](../verification/hosted-authority-schema-contract/probe/functions.sql), [catalog query](../verification/hosted-authority-schema-contract/probe/catalog.sql), executable [driver](../verification/hosted-authority-schema-contract/run.py), and [probe cases](../verification/hosted-authority-schema-contract/probe/tests.py) are the candidate. The independently reviewed configured-identity startup closure remains a separate accepted input; its integration receipt is copied into each attempt. The [atomic storage correction contract](hosted-atomic-storage-corrections.md) and [root writer direction](../verification/hosted-transaction-context-root-review/atomic-writer-direction.json) override the older membership blueprint's direct runtime domain-DML proposal. This packet neither changes nor accepts the separate corrected atomic-writer specimen.

Only verified humans and `artifact.read`, `artifact.upload`, `audit.read` are supported. Release validation/publication/promotion/rollback/halt, service and CI authority, member management, login/linking/bootstrap/refresh, signing, public delivery and dispatch fail closed. No raw bearer, refresh credential, email linkage, full claims, JWKS or signing key is persisted. A configured signature alone never registers a credential or creates membership.

## Exact schema and ownership

The candidate installs 14 tables, six explicitly declared composite types and ten functions in a new schema. It never references or changes historical `mixer_release` tables, the Go migration, wire vectors or old events. PostgreSQL extensions and new package dependencies are unnecessary. The probe uses Python's standard library and PostgreSQL's installed `libpq`; PostgreSQL is already recorded in `THIRD_PARTY.yml` as a verification dependency.

All 14 tables have ENABLE and FORCE RLS. Text identifiers use exact equality and `COLLATE "C"`; no normalization, case folding, email inference or wildcard expansion exists. Public org/project/app/environment IDs are 1–128 ASCII bytes `[A-Za-z0-9_.-]`. UUID identities are non-recycled lifecycle IDs. Digest columns are exactly 32-byte `bytea`. Revisions are positive signed `bigint`; guarded updates increment exactly one and overflow aborts. Authoritative integer seconds are 0..9007199254740991. Membership windows start inclusively and expire exclusively; optional endpoints must increase when both exist.

| Table | Required authority and invariant |
| --- | --- |
| `identity_trust_profiles` | Exact profile PK, current positive int32 version, enabled, immutable issuer/client/class, revision. Profile ID ≤128 UTF-8 bytes, issuer ≤2048, client ≤256. Disable may keep version; re-enable requires a greater version. Changing immutable identity needs a new profile and explicit binding. No endpoint/key cache is stored. |
| `principals` | UUID PK, human/service kind, active/disabled, monotonic valid-after, revision. Human has no owning org; service requires an existing owning org. Kind/ID/owner cannot change. Service is still rejected at resolver entry. |
| `external_identity_bindings` | UUID PK and unique exact `(profile_id,issuer,subject,registered_client)`; subject ≤256 UTF-8 bytes. Composite FKs enforce matching profile issuer/client/class and principal kind. All updates and deletes reject. |
| `credential_families` | UUID PK, immutable binding/principal/profile composite FK, active/revoked, monotonic valid-after and revision. Revoke is irreversible; no deletion. |
| `credential_references` | PK `(binding_id,jti_sha256)`, family/binding/principal/profile composite FK, exact accepted issued-at/expiry. Immutable. The trusted adapter hashes the verified `credential_ref`'s exact UTF-8 bytes with standard SHA-256; binding/profile/issuer/client supply its namespace. No bare global digest lookup. |
| `credential_denials` | PK/FK credential reference including its registered expiry, denied-at, retain-until, revision and closed reason `revoked/incident/operator`. Retain-until ≥registered expiry+30; its bound permits that exact addition. No runtime removal or cleanup API exists. |
| `organizations`, `projects`, `applications`, `environments` | Exact composite ancestry FKs, active/deleted, revision; no hard deletion or reactivation of deleted records. Environment risk is development/staging/production and confers no release permission. |
| `organization_authorization_heads`, `project_authorization_heads` | Precreated exact ancestor PK/FK and positive revision. Runtime never creates missing heads. |
| `organization_memberships`, `project_memberships` | UUID lifecycle PK, exact principal/scope FK, six-role CHECK, invited/active/revoked, optional window, revision, 32-byte management-evidence reference. Org binding is explicitly `organization_wide` or `organization_only`. Scope/role/evidence/lifecycle are immutable; revoked cannot become active. A regrant uses a new ID. |

The expanded DDL is authoritative for column order, nullability, FKs, CHECKs, indexes, partial active-lifecycle uniqueness, trigger definitions and exact privileges. The final observed catalog records these installed properties, rather than inferring them from SQL text. The test bootstrap is an isolated offline superuser. Guard triggers and constraints protect ordinary writes; they do not claim to constrain an offline privileged owner who disables triggers, truncates data, drops indexes or coherently rewrites policy.

`mixer_hosted_schema_owner`, `mixer_hosted_authz_resolver` and `mixer_hosted_domain_writer` are separate NOLOGIN, nonsuperuser, non-BYPASSRLS, non-createdb/createrole/replication roles with no membership chain. The schema owner owns tables, types, guards and private invoker helpers. Resolver owns only four enumerated SECURITY DEFINER functions. Domain writer owns no authority function and receives only the exact recheck entry. A separate fixture login `mixer_hosted_runtime` owns no object, has no schema CREATE/database CREATE/TEMP, no membership/elevation path and no direct authz table access. Its eventual deployed name/DB owner are frozen deployment inputs, not arbitrary caller arguments.

Resolver has SELECT on the named authority tables and UPDATE(`revision`) only on the five lock tables. Simple role-specific SELECT policies use true; the five lock tables additionally have an explicit resolver UPDATE policy. PostgreSQL needs both the narrow UPDATE grant and UPDATE RLS visibility for `FOR SHARE`: each of five independently removed UPDATE policies made its lock query invisible and caused closed rejection. No resolver function updates authority rows. Schema CREATE is absent for resolver/writer. PUBLIC function EXECUTE and explicit composite USAGE are revoked before the creation transaction commits; six named type grants and individual function grants are enumerated. No broad future helper grant is used.

All four resolver entries are VOLATILE, PARALLEL UNSAFE, non-LEAKPROOF, fixed `search_path=pg_catalog`, `row_security=on`, schema-qualified, bounded, and contain no dynamic SQL, callback, transaction control or network operation. Authz policies never call a resolver and do not query domain tables, so no policy recursion is introduced. Private pure helpers use fixed `search_path=pg_catalog` and invoker authority.

## Exact composite transport

The following field order is normative and checked against the installed catalog. Composite constructors are transport within trusted Mixer code, never cryptographic capabilities.

| Type | Ordered fields |
| --- | --- |
| `verified_identity_v1` | `profile_id text, profile_version integer, issuer text, subject text, client_id text, credential_sha256 bytea, issued_at numeric, expires_at numeric, identity_class text, scopes text[], authentication_completed_at numeric` |
| `target_v1` | `action text, organization text, project text, app text, environment text, platform text, runtime_sha256 bytea, manifest_sha256 bytea` |
| `transaction_identity_v1` | `backend integer, full_xid text, database_name name, runtime_role name, nonce text, deadline timestamptz` |
| `admission_v1` | `identity verified_identity_v1, target target_v1, transaction_identity transaction_identity_v1, principal_id uuid, binding_id uuid, family_id uuid, profile_revision bigint, principal_revision bigint, family_revision bigint, organization_revision bigint, project_revision bigint, lock_statement_at timestamptz` |
| `membership_witness_v1` | `lifecycle_id uuid, role text, revision bigint` |
| `decision_v1` | `outcome text, principal_id uuid, binding_id uuid, family_id uuid, decision_at numeric, profile_revision bigint, principal_revision bigint, family_revision bigint, organization_revision bigint, project_revision bigint, memberships membership_witness_v1[]` |

The three identity-time inputs are **unconstrained numeric**, so the function can reject NULL, NaN, infinities, fractions, negatives and one-over values before any authority/effect. There is no scale-zero rounding typmod. Require issued-at <expiry and authentication-completed-at <expiry. Identity class is exactly human. Scopes are a zero-to-three-element, one-dimensional, unique nonnull array of exactly `mixer.artifact.read`, `mixer.artifact.upload`, `mixer.audit.read`; the accepted `AccessTokenVerifier.scopes/1` already returns the exact known-scope intersection. The captured source is binding input; no new scope mapper or change to the accepted identity behavior is proposed. Unknown names in SQL therefore indicate malformed transport, not a new restriction on otherwise valid OAuth tokens. Array lower bound is one when nonempty.

The trusted coordinator captures completion time immediately after `ConfiguredVerifier` succeeds and retains it immutably in the invocation context. It constructs this SQL transport value without modifying the accepted `VerifiedIdentity` struct. The timestamp is not accepted from HTTP, arbitrary claims or a subsequent refresh of the same context. This coordinator is a future implementation seam; the isolated probes do not invoke a real provider.

Artifact targets require all app/environment/platform/runtime/manifest fields, exact ios/android, both 32-byte digests and valid IDs. Audit is project-only: all five artifact fields are explicitly NULL. Upload target comes from the independently checked signed artifact; read target must eventually come from the stored normalized resource, then be compared again. This authority-only specimen has no artifact table: it checks full live ancestry and exact supplied target binding, and does not prove artifact existence, signature validity, metadata resolution or read correctness.

Transaction identity matches the actual backend, assigned full `xid8` rendered as text, database, original runtime `session_user`, exact `role=none`, READ COMMITTED and a 64-lowercase-hex transaction-local nonce. Full xid is never truncated to 32 bits or converted to a JavaScript number. SQL deadline is finite, strictly future, at most five seconds ahead and exactly equals its original transaction-local setting. The pinned coordinator separately preserves its monotonic deadline and current process/Repo/dynamic Repo/active invocation reference. SQL wall-clock checks do not replace that monotonic application guard.

Lookup returns an incomplete `admission_v1` with null revisions/lock timestamp and no permission. Lock fills all five revisions and a finite statement timestamp. Decision requires exact nested identity/target/transaction values and exact immutable binding/principal/family IDs. Revisions must exactly match the actual locked/current rows. A separate earlier lock statement is required; a same-statement combined call and nonfinite timestamp reject. Timestamp and settings are discipline within trusted code, not independent proof of prior locking.

The decision witness is internal and bounded: one principal/binding/family, five revisions, integer DB clock and at most 64 sorted lifecycle/role/revision triples. The HTTP layer must map its closed outcome, never serialize its internal identity or membership witness wholesale. It supplies a future audit encoder with bounded policy evidence without exposing an arbitrary identity/policy query endpoint.

## Exact helper allowlist and admission order

Signatures below use schema-qualified composite types from the preceding table.

| Function | Runtime EXECUTE | Writer EXECUTE | Purpose |
| --- | --- | --- | --- |
| `lookup_admission(verified_identity_v1,target_v1,transaction_identity_v1)` | yes | no | Exact preprovisioned immutable binding + registered credential/times. No permission or auto-registration. |
| `lock_admission_rows(verified_identity_v1,target_v1,admission_v1,transaction_identity_v1)` | yes | no | Reassert mapping/context and acquire five ordered actual row locks, asserting exactly one visible row after each. |
| `decide_current(verified_identity_v1,target_v1,admission_v1,transaction_identity_v1)` | yes | no | Admission-stage duplicate acquisition and fresh current decision, before any tenant-head acquisition. |
| `recheck_current(verified_identity_v1,target_v1,admission_v1,transaction_identity_v1)` | no | yes | Sole domain-writer fresh recheck with **no lock acquisition**; exact prior context/mapping/revisions and current state/time. |

Private schema-owner invoker identities are exactly `finite_uint(numeric,numeric,numeric)`, `bounded_text(text,integer)`, `valid_id(text)`, `validate_inputs(verified_identity_v1,target_v1)`, `assert_transaction(transaction_identity_v1)`, and trigger `guard_lifecycle()`. Resolver receives only the first five necessary EXECUTE grants; runtime/writer receive none. The four definer entries are resolver-owned; resolver can call its own exact functions. The complete actual identities, definitions/hashes, owners, ACLs, types and policies are in the final `catalog.json`.

The coordinated transaction protocol remains the [root-selected pinned context](../verification/hosted-transaction-context-root-review/selection.json): fixed Repo/process, `queue: false`, one real READ COMMITTED transaction, original absolute monotonic budget ≤five seconds, decreasing statement budgets, 250ms lock timeout and same connection/backend/full xid/database/role/nonce. No nested/reentrant admission, arbitrary SQL callback, async task, customer code, signer or network request is permitted. This SQL probe does not requalify Ecto queue/deadline behavior already measured in the separate context packet.

1. Perform bounded trusted parsing/crypto work before the transaction. Start the pinned context. Call exact lookup; no bearer enters SQL.
2. Lock **profile → principal → credential family → org authorization head → project authorization head**, all `FOR SHARE`, with no SKIP LOCKED. Every stage requires cardinality one; no missing denial/membership row serves as a fence. Reassert immutable lookup after all locks.
3. In a **separate SQL statement**, call admission `decide_current`. It duplicates those same five actual acquisitions and checks every result, then invokes the lock-free fresh current-state routine. This costs five extra indexed row-lock queries and is a bounded candidate choice requiring later deployment measurement. It prevents a forged admission composite or omitted prior lock call from bypassing actual admission locks. The prior-statement timestamp still expresses coordinator discipline, not an unforgeable ticket.
4. Current-state queries reassert exact enabled profile/version/identity, active human principal, active family, registered credential/times, absent denial, issued-at ≥principal/family valid-after, strict DBnow <expiry, completion within `[DBnow−45, DBnow+30]`, live org/project/app/environment and membership/windows/scopes. There is no completion≤decision requirement. DBnow is a finite integral Unix-second clock. After credential/ancestry reads, capture a chosen final decision clock and recompute the entire bounded applicable membership union at that clock, including all windows/cardinality/duplicates/roles/scopes; record that exact clock with its witness. Recheck fresh token/completion/deadline immediately before successful return. Membership evidence describes the recorded decision clock, not a promise that time cannot advance after it; the fixed writer must repeat the current recheck after later waits and before effects. No indefinite retry loop or unconditional second-boundary rejection exists.
5. Only after all authority locks and initial fresh allow may a future domain writer lock its tenant head. That sole fixed writer calls **`recheck_current`**, never admission `decide_current`/`lock_admission_rows`, after the tenant head and before idempotency/effects, after later waits, immediately before the first mutation, after mutation and before replay/success, following AS02. It must never acquire a lower-order authz lock while holding the tenant head. The four-entry ACL split prevents an ordinary writer from invoking the admission acquisition entry. This packet implements no tenant head, artifact mutation or domain writer.
6. Revalidate the trusted owning process/Repo/active reference/full SQL identity and original monotonic budget before every fixed repository call and completion. Commit remains separate. Failure racing an already-sent COMMIT is uncertain: report storage unavailable, preserve referenced immutable blobs, and use a fresh verified/current-authorized principal-bound idempotent retry. Neither disconnection nor expiry proves rollback, and an already-sent COMMIT can finish just after expiry. The lost-COMMIT-response and atomicity evidence belongs to the separate atomic-writer packet.

PostgreSQL's uncontended row locks cannot be reliably attested by reading `pg_locks`; this contract does not invent such a proof. A malicious runtime with arbitrary SQL or malicious code in the same BEAM process can forge transport/GUC values. Product protection relies on verified-identity ownership, pinned coordinator discipline, closed helper ACLs and the sole fixed mutation path. Writer recheck deliberately relies on those retained locks and must not be exposed by a runtime callback or backdoor wrapper. The disposable writer wrapper used to test definer nesting is removed before catalog capture and is explicitly absent from product DDL.

## Membership and management serialization

Roles are exactly `owner`, `administrator`, `developer`, `release_manager`, `billing_manager`, `viewer`; old reader/editor/publisher values reject. Active, in-window project memberships and explicit organization-wide memberships union. Organization-only grants do not grant project visibility. Owner/administrator/developer permit all three actions; release_manager/viewer permit artifact.read/audit.read; billing_manager permits none. Each yes also requires its exact action OAuth scope. An active billing-only project member gets forbidden; a nonmember or unavailable live target gets not_found. Unsupported action/class/shape/current credential state rejects closed.

The indexed query fetches at most **65** applicable rows, sorted by UUID, before aggregating. More than 64 returns authorization_unavailable with no truncated allow and no membership witness. Because the two membership tables have separate PKs, a duplicate lifecycle UUID across their applicable union also returns authorization_unavailable with an empty witness; the audit contract requires unique UUIDs in strict order. An exact same-UUID organization-wide/project fixture proves this rejection. Partial active-role uniqueness makes ordinary first-slice grants much smaller; the 64/65 tests temporarily remove that index through the offline fixture owner to test the defensive overflow boundary, then restore it. This is owner-corruption test machinery, not a supported duplicate-grant workflow.

All future authority writers must take conflicting locks in the same order before writing and increment the affected state/head revisions. Profile disable locks profile exclusively; principal changes take profile then principal; family/denial/registry changes additionally take family; org-wide policy/lifecycle changes take exclusive org head; project-specific changes take shared org head then exclusive project head. Binding/principal/family tuples never move. Provisioning inserts heads with ancestors atomically; missing heads fail closed. Within a later multi-target class, sort stable IDs lexically. Management evidence and revision changes belong to the same authorized management transaction. No management API or lock-enforcing management writer is implemented here: triggers enforce immutability/revision shape, while the offline bootstrap can violate lock discipline. A real management writer needs separate qualification.

An admitted operation holds shared fences until transaction end. A later revoke waits; already admitted work may commit before revoke returns. Once revoke commits, fresh admission denies. The probe observes both actual wait directions and a separate test makes the outer decision statement start before a waiting writer commits: its fresh VOLATILE internal query sees the committed revocation after lock release. This is local PostgreSQL primary evidence, not a Neon/pooler guarantee.

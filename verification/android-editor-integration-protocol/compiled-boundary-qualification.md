The old source map contains 189 records: 184 V2 boundaries and five V1 compile
baselines. The preparation's 171 unchanged-line hints and 18 changed/removed
hints are search aids only. No line-count match, ordinal match or mechanical
remap demonstrates current callback coverage or authorizes integration/release.

After corrected-source acceptance and root selection, independently enumerate
the complete selected renderer, NativeAppearanceViewsV2 including NativeField/
Record/Mutation/FieldPreservation/Replacement, direct NativeEditorConnectionV2
and all API31/33/34 subclasses. Include new field-only preservation callbacks,
loss observation/lifecycle continuations, replacement-event evaluation/claim,
cleanup drain, creation/scrubbing and all callable observations. Re-evaluate
unchanged product regions affected by the new direct adapter or altered caller
authority; source changes are not the only reason a boundary can change meaning.

For every old V2 boundary record one independently reviewed disposition:
retained with a newly qualified compiled identity, replaced/split by exact new
IDs, or removed with reason and replacement/refusal evidence. Preserve five V1
positive baselines separately. New direct-editor, field and renderer boundaries
are mandatory even without an old ID. Derive a fresh complete inventory; never
take 171 or 184 as the expected new total. Keep callback entry, return and
failure stages explicit, and retain controls for source-only native-pending
observations without counting them as executed rows.

Compile the exact frozen complete closure with explicit named sources and empty
sourcepath/classpath where appropriate. Record source bytes/map/tree digest,
JDK binary/version/flags, actual classes and each class digest. Use `javap -c -p
-s -l` or an independently authored classfile reader to map exact class name,
method name **and JVM descriptor**, instruction-boundary BCI, invocation opcode,
callee owner/name/descriptor and line table to each source expression. Resolve
synthetic lambdas/bridges and inherited direct-adapter methods explicitly.
Line numbers annotate a proven class/descriptor/BCI identity; they are not it.

Bind the pinned SDK37 InputConnection interface's exact 38 descriptor obligations
to concrete implementing Base/Api31/Api33/Api34 methods, or a separately reviewed
intentional refusal/default resolution. Compare descriptor sets, not counts.
Prove no unreviewed default/inherited forwarding or InputConnectionWrapper path.
Record class availability/linkage for API-specific types separately from the
unchanged SDK36 entry guards. Include overload descriptors so region attributes
sharing one mechanical leaf cannot falsely credit the other call site.

Each executable matrix row records selected source/class hashes; exact receiver
and original authority tuple; caller descriptor/BCI; selected native entry or
beforeReturn event and full production frames; injected stimulus; observed
native/event/JNI sequence; original result; gate/retirement/count/cleanup/fatal
disposition; and exact expected versus observed result. Source or class hash
changes invalidate the row. Do not credit a different invocation on the same
source line or a different overload/receiver. For helper boundaries, prove the
exact caller into the helper and its full nested native sequence. A nested hook
gets only its true scope; direct callback credit needs direct entry/return proof.

Run the seven existing matrix stimuli where semantically applicable: clean,
terminal-at-entry, terminal-before-return, dirty-at-entry, dirty-before-return,
ordinary throw after callback and fatal throw after callback. Add the editor
case split, queries/snapshots, close idempotence, creator/cleanup/failure states,
field-preservation and focus-history reservation/event states required by the
selected source. Retained genuine successor rows may return the original
completed scalar; they must not reuse the old scope for new callable/native work.
Unsupported direct methods get refusal/wrong-thread controls rather than
invented target boundaries. New accepted source findings expand the matrix.

The map checker must reject missing or duplicate active IDs, foreign source or
class digests, mismatched overload descriptors, BCIs between instructions,
unexpected opcode/target, absent emitted classes, omitted new direct/renderer/
field subjects, zero-hit or wrong-caller rows, incomplete state coverage,
unsupported-successor claims, stale historical-only rows and source-only rows
reported as executed. Mutation controls change each identity field, delete one
row, move a hook to a neighboring invocation and remove a direct editor subject;
each must be rejected. These checks validate evidence integrity, not behavior.

`check_protocol.py` includes synthetic certificate mutation controls solely to
make these integrity requirements executable before the real map exists. Its
synthetic fixture is not a source inventory and carries no product acceptance.
The actual selected-source matrix, exact 38-descriptor audit, unsigned SDK/D8/
Swift/JNI integration and independent reviewer decision remain pending. A
successful evidence checker never authorizes OTA by itself; OTA, native runtime,
public V2 and GA retain their separate specified gates and accountable review.

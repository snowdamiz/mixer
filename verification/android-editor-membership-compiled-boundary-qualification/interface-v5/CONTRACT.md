The external root is the canonical pinning parent, the trusted OS utility paths/identities, qualification-entry.sh, admission-core.sh, the selected bootstrap and the external Python admission policy/file/path/symlink rosters. The parent must start the entry using a fixed absolute env -i /bin/sh invocation. Entry always starts a clean shell environment and pins core. Core pins bootstrap and all admission rosters, verifies the complete actual Python runtime/import-support files, exact prefix path set and symlinks BEFORE launching Python. The selected file set includes transitive non-OS dynamic-library dependencies of admitted Python extensions/core. Mandatory -I -B -S, exact executable/base executable/prefix/base prefix and admitted sys.path keep venv/site/loader/environment substitutions out. No inherited PATH, ENV, BASH_ENV, SHELLOPTS, Python, locale or loader option can select child startup.

The OS utilities are explicit external trusted inputs; their current hashes are checked as drift detection before Python. This does not claim to authorize execution of an unknown OS utility by hashing it after execution. The same boundary applies to all Python needed for admission: only the shell root performs pre-startup admission. Python consistency checks rehash the already-admitted files to detect drift; they do not retroactively prevent startup code. Direct Python bootstrap invocation is not the canonical qualification authority; standalone checker always refuses distinctly.

Trust DAG: reviewed parent -> entry -> core -> bootstrap -> descendant execution manifest -> payload/complete emitted classes/JDK. Core also pins the external Python admission rosters; bootstrap pins the external runtime-policy reference and rechecks current runtime. No descendant manifest includes a pinning ancestor or the ancestor runtime policy itself. The semantic policy, exact product source/context map and reference obligations remain separately pinned inside the descendant checker closure. No checksum fixed point or matrix-supplied status can approve replacement data.

The bootstrap compiles the exact closed explicit source roster with normal JDK17 no-g flags and empty source/class search paths, checks all product/support classes, runs the immutable complete per-case roster in bounded60-second children, then invokes one bounded assembler. It rechecks source/class/tool/runtime closure before execution and certificate acceptance. All rows must come from a fresh selected producer; static matching cannot produce a qualified certificate. A different compiler/platform, Python installation or support source/class closure requires separate review. Actual Ubuntu CI remains unqualified here.

# Private Swift function cache producer evidence

The producer commands pass. Independent implementation review and root acceptance
remain pending. This slice does not instantiate, initialize or invoke the
53,777,114-byte target and does not provide an executor or public Swift cache
route. No physical devices were discovered or run. No GA gate changed.

`producer-receipt.json` binds the frozen source, exact commands, outputs, tools,
accepted root prerequisites, layout map and preserved historical observations.
`source-freeze.json` uses explicit baseline
`39199ae5475de5d03926807ce60add5dcb0741c2` plus named SHA-256 overlays, regardless
of subsequent unrelated repository commits. `frozen-source.tar.gz` contains those
exact source bytes with fixed archive metadata. The manifest includes source and
contract files; it does not include unrelated website or Android lane changes.

The private implementation shares one sealed borrowed cache/decoder algorithm
between the frozen legacy mode and Swift mode. Swift preserves the entire
original AdoptedProof and both tickets, borrows its validated descriptors, uses
one permanent 512-Patch allocation, and admits actual RuntimeControl tickets and
live counts before allocations or publication. Tests use independently authored
small complete-validated fixtures with the exact accepted ABI. They never
instantiate those modules.

The cache prepares construction and operation phases on the existing construction
ticket. Callers retain the actual Option<Result> return storage, take the final
owner/diagnostic, end any large intermediate failure wrapper scope, and pass the
empty storage into consuming complete before restoration. Rejected foreign
proofs retain their exact adopted owner and tickets. Operation omission and
cleanup-tail omission retain conservative charges.

Cleanup accepts caller-owned Option<SwiftFunctionCache>. Rejected owner/WASI
preflight leaves the exact Some(cache) intact. Once destructive cleanup starts,
every entry, fixed buffer and whole adopted proof drains, preserving first
failure, and returns the original header in CacheCleanupTail. Its consuming
complete drops the actual supplied return storage in a helper whose frame ends
before the final header refund. The remaining borrowed-handle/header tuple uses
a whole named foundation transfer slot. The detailed simultaneous type/count
and final-tail map is in `layout-map.md` and `layout-map.json`.

# Worker request header amendment

This amendment changes the outbound header selection in the version 1
[worker transport contract](hosted-worker-transport-contract.md). The JSON wire
version, endpoint, authentication, request identity, immutable binding and response
checks remain unchanged. It is a selection for the next candidate; it does not
accept the existing transport implementation.

The pinned Mint 1.11.0 implementation adds a `User-Agent` field when one is not
supplied (`hosted/deps/mint/lib/mint/http1.ex`, `add_default_headers/2`). Independent
review observed that eighth field in an actual TLS request. The original contract
specified seven fields, so its implementation and evidence remain a failed match
for that requirement. Preserve that result and the original frozen candidate.

The next candidate must explicitly send `User-Agent: mixer-worker/1`. The exact
client-originated field set, compared case-insensitively, is:

| Field | Value |
| --- | --- |
| Host | Validated configured endpoint hostname |
| Content-Type | `application/json` |
| Accept | `application/json` |
| Accept-Encoding | `identity` |
| Connection | `close` |
| Content-Length | Canonical decimal UTF-8 body byte count |
| Authorization | `Bearer ` followed by the validated configured pool token |
| User-Agent | `mixer-worker/1` |

Each field occurs exactly once. No other client-originated header is permitted.
Host and Content-Length may still be generated by Mint. The complete serialized
request header section, including all generated fields and delimiters, must stay
within 8,192 bytes. Neither dependency versions nor host, tenant, source, token or
build metadata belongs in the User-Agent value. Use Mint's public request API;
do not patch dependency internals to suppress its default field.

Acceptance requires an actual TLS fixture to retain and check the complete
received request line and header field inventory, exact values, duplicate absence,
body length, and byte bound. The test token must be synthetic; never record a real
credential. Exercise the production request path for all three commands. A helper
returning the intended headers or source-text assertion does not prove emitted
bytes. Existing credential, peer validation, framing, deadline and cleanup
controls remain required.

This exact field set describes what the client sends to its TLS peer. A managed
Cloudflare ingress may add or transform transport metadata before the Worker
receives a Request. Controller validation must separate such provider-owned
metadata from the closed application message and must still reject ambiguous
authentication or application fields. This amendment does not qualify provider
behavior; real ingress behavior and configuration need separate evidence before
deployment acceptance.

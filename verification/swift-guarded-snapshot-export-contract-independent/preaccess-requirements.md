## Requirements

1. **Authority and ordering.** The original initial-construction phase and owner
   checks precede the sole original `InitialProfileBorrowV1` literal. Snapshot
   export borrows that same guard before the existing header and rows. The guard
   can be re-exported crate-visible with private fields solely to cross privacy
   boundaries; the serializer accepts a borrowed guard, not an arbitrary proof,
   digest, callback, second guard, constructor retry, or external claim. Immutable
   borrows cannot escape their guard/owner lifetime or enable mutable access.
2. **Original outcome preservation.** All eight original construction variants,
   owner/failure/completion payloads, first-error identities, cleanup, ticket
   refunds/quarantine, and header-then-rows order survive unchanged. Snapshot
   status is a distinct outer observation. Failure and partial output do not
   replace original outcomes, skip rows, manufacture completion, or add a retry.
3. **Complete proof inventory.** Cover source, metadata, policy, all 34 resolved
   imports, validation usage, and observations. Metadata covers signatures,
   parameters, imports, functions, globals, exports, data, elements, optional
   memory/table, separate declaration maxima and offsets, and instruction count.
   Each of the eight `Buffer`s retains logical length, requested capacity,
   charged bytes, category, and all logical elements. Export no address, padding,
   unused allocation contents, native enum representation, or compiler layout.
4. **Exact element grammar.** Explicit fields and tags cover Signature
   `(first,count,result)`, Type, Import `(module,name,type_index)`, Function
   `(body,type_index)`, Global `(ty,mutable,initializer)`, Export `(name,kind,index)`,
   Segment `(payload,destination,count)`, and Span `(offset,bytes)`. Integer width,
   endianness, boolean/tag meaning, optional presence, absent payload, reserved
   bytes, ordering, and all 34 resolved-import mappings are unambiguous.
5. **Exact wire admission.** A versioned header and section roster have exact
   extent equations; sections cannot overlap, duplicate, leave unexplained gaps,
   exceed source-derived policy limits, or overflow arithmetic. Total extent,
   source length, lengths/capacities/charges, counts, cross-references, span bounds,
   known tags, optional payloads, reserved zeros, and trailing bytes fail closed.
   Deterministic encoding is logical-field encoding, not raw memory copying.
6. **Ceilings from actual policy.** Source <=67108864; types <=512; total type
   parameters <=8192; imports =34; total functions <=80000; globals <=8192;
   exports/data/elements <=4096 each. More specific actual validator constraints
   remain applicable. Any proposed section/total cap must be independently
   recomputed from element widths and these source limits, using checked math.
7. **Authentic provenance only.** Selected provenance comes from the original
   adopted body under the sole guard. It retains five validation limits,
   source_extent, six 32-byte digests, and four exact 64-byte FileIdentity records
   with signed timestamp semantics explicit. Ordinary provenance is absent and
   cannot be upgraded by matching strings/digests. The derived record does not
   relabel actual build/session records or claim package authentication.
8. **Runtime binding is contextual.** Any distinct runtime record uses authentic
   original control identity, complete 17-field runtime budget, optional actual
   WASI limits/grants, and explicit scope. It cannot be minted from caller fields
   or imply that current loader session already carries those data. Exact owner
   binding and optional WASI association must be checked through the original
   authority. No signed-package, hostile-launcher, semantic replay, or FSM claim.
9. **Accounting before work.** Name and measure all new argument, guard/borrow,
   output, result, error, caller, move, cleanup, writer, and schema-owned arena
   storage in unit and ordinary production contexts. Integrate real source
   places, simultaneous requested storage peaks, fallible allocations, transfer
   buffer, and I/O state before allocation/write. Include lifetimes and release
   points, not only a layout roster. Preserve every existing selected ceiling.
10. **Bounded I/O and artifact scope.** One reusable transfer <=4096 bytes; <=32
    real write attempts per transfer, including Interrupted, short, zero,
    overreported, failure, and exact partial-progress observations. Define output
    initial File scope, position/extent/type admission, alias/custody limits, and
    observations that are acknowledged output rather than close/durability/name
    proof. The raw Debug result remains its own retained artifact; later typed
    output cannot substitute for original final consuming usage or error owners.
11. **Finite implementation gates.** Future implementation must freshly exercise
    positive guard-bound export and all original outcomes, privacy/lifetimes,
    malformed wire, and partial/bounded I/O. A separately labelled positive host
    grant must be derived after implementation from fresh actual measurements.
    Format tooling and baseline compiler controls validate only their stated
    scope; they do not count as a working exporter or operational qualification.
12. **Evidence custody and truthfulness.** Verify the released closed seal and
    source attribution, retain all failures, commands, versions, digests, and
    outputs, and distinguish newly executed checks from immutable historical
    receipts. Product/canonical integration, loader allocation admission, actual
    File-close, semantic context/FSM/full workload, native/device/FieldLog,
    signed-package/store/customer/operational/GA gates remain unaccepted.

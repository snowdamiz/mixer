# Private Android native appearance V2 consumer

The concrete development consumer has executed on a dedicated API37 emulator; the final source-sealed receipt is retained below. This is the concrete `NativeRenderer` V2 consumer; no public bootstrap, signed support, ordinary engine/JNI join, physical-phone, published FieldLog, or GA qualification is supplied.

The repository-only asset path is `MixerAppearanceV2/descriptor.json`. `InstalledAppearanceV2` reads one bounded AssetManager stream and validates the complete canonical Swift descriptor and both themes. The first slice requires systemSans in both themes and an empty complete catalog. Every resource declaration (including unused image/font declarations) rejects before native preparation. No second Java default is maintained.

`NativeEnvironmentV2` reads the actual Activity resources, root window geometry/insets, direction, locale, font-weight adjustment, high contrast, system contrast and animator preference. Configuration, insets, root layout and preference listeners invalidate a checked owner generation. Capture and pre-attachment checks read the whole tuple synchronously. Preferred body size uses actual SP17 / DIP1 public conversion, validates the unrounded14…53 range and chooses the nearest twelve-profile anchor with ties upward. All role fonts then use explicit PX with native systemSans weights and script fallback. API29 cursor/selection APIs are used. Faithful public high-contrast read/listener first exists on API36, so this prototype rejects API28…35 contexts. Production minimum28 DEX compilation does not qualify those runtime contexts; the product minimum remains28 and alternatives are pending.

The private HStack policy probes every child under full available width, keeps intrinsic sizes when they fit, and otherwise splits remaining logical64 width after exact gaps equally, distributing the remainder to earliest logical children in source order. It then remeasures without stretching narrower children. Fixed hit/visual footprint overflow rejects. RTL mirrors placement only. This is an authored shared private policy, not an unchanged SwiftUI measurement claim.

Preparation constructs detached native widgets and measures real TextView Layouts, computes checked logical extents and closed group/switch paths. Candidate ownership, exact base packet/map identity, captured installation and native window generation are checked. Native Button/EditText/Switch/ScrollView objects survive exact document identities. Existing callbacks resolve only the current owner packet; gates suppress programmatic and retired events. Active editors/selections require unchanged appearance, ancestry, frame and desired native buffer. Conflicting composition mutations reject before attachment; accepted echoes preserve the actual Editable, native selection and composing spans without a restoration claim.

Attachment gates draw/input, applies prepared bindings and parents, and lays out prepared geometry. An already allocated rollback journal retains the old tuple, parent membership, inactive buffer and selection, and scroll offsets. Rollback failure retires the owner with presentation/input gated. `validateAttachedV2` must be called immediately before the coordinator's scalar engine commit; `finishV2` performs prepared reference swaps and gate reopening only. The current ordinary engine/JNI coordinator is not joined here, so this consumer alone cannot qualify engine/display atomicity.

Native measurement/drawing and adversarial tests are retained by `verification/android-native-appearance-v2/qualify.py`, targeting only explicit emulator serials. API37 cannot establish support for other OS versions. Physical side-by-side design, TalkBack/keyboard workflows and final device qualification remain pending.


The native corpus uses one dedicated read-only/no-snapshot emulator. It includes the identical canonical Swift packet/descriptor exported by the Apple lane, at an actual 402×874 logical viewport and 3x density; actual safe areas, font fallback and native glyph extents remain platform-specific and are exported beside the screenshots. Sharing bytes or viewport does not assert design parity. Twelve synthetic **actual Activity configuration contexts** exercise Android's nonlinear native SP conversion, both schemes and both directions; this is not evidence of physical settings workflows or a Cartesian 48-context matrix.

Native tests exercise actual Button/Switch touch and cancellation, Button key activation, native compact-navigation scrolling, real Editable/InputConnection selection and composing-span identity, oversized/malformed IME rejection before mutation, stale installation/window/base and foreign/replayed candidates, every current node-binding/parent/root/layout attachment fault, post-attach rollback and retirement when rollback fails. Actual AssetManager capture is exercised by separately installed APK variants for noncanonical/oversized descriptors, unused image declarations, valid unselected bundled fonts and invalid unselected theme metrics. Resource-backed configurations are rejected, not qualified. Native rollback preserves current native toggle value as well as old packet/parents and inactive text/selection/scroll state.

The bounded consumers reject Button/EditText/Toggle descendants nested below a List row root before attachment. Direct control rows separate semantic extent from hit envelopes. Recursive semantic/hit routing inside container rows is a coordinated pending extension; native hit envelopes that cannot fit the admitted current row geometry also reject. An active editor or selection whose appearance, ancestry or actual frame changes rejects before attachment; arbitrary theme/profile changes during composition are not accepted. Unsupported IME correction/content/handwriting/replace-text extension methods fail closed; the qualified path is native text proposals, composing-region/text, selection, deletion and submit. These restrictions do not narrow the binding product scope.

Retained failures remain part of development evidence: initial test packet encoder lacked List output, Switch inherited Button's activation listener until separated, the initial Activity override was applied too late, native keyboard focus needed real touch-mode transition, compact navigation visibility needed to survive record rebinding, a test-only redundant cast failed `-Werror`, and candidate 9's otherwise-passing416 native assertions had administrative AGENTS.md drift. Product behavior and source sealing are reported separately. No failed run is relabeled a clean final receipt.


The V2 mode requires a fresh native owner. The legacy constructor uses its existing API28-safe collections and allocates no V2 callback/helper objects; exported bytecode is checked separately, with runtime API28 still pending. Existing V1 owners cannot convert in place, and V2 owners cannot call legacy apply. Native focus and editor-selection changes invalidate pending candidates through the same checked interaction epoch. Detached/hidden/unfocused windows and retired records cannot accept native callback/IME input. Window detachment retires that capture rather than reusing observers from another window.

The acknowledged binding and native transient value are distinct: a Switch may change locally during user input before a guest response. A new document/revision candidate always reasserts its desired checked value if the actual native Switch differs, even when the new desired value equals the previous acknowledged value; binding causes no guest event. A recoverable native attachment rollback restores the exact pre-attachment native value, including a transient value, and the old acknowledged packet. The eventual ordinary engine/input coordinator owns response/retry/rejection policy; this renderer does not silently claim that join is complete.


Pre-attachment validation also compares the captured actual native tuple directly, closing listener gaps for selectable TextView selections, composing-only spans and pressed-only state. It checks buffer identity/value, all composing span objects/ranges/flags, selection, control/drawable state, checked value, focus, scroll, actual frames and exact parent/root child order. Attached validation deliberately omits that old-state comparison because attachment has intentionally changed native bindings. An exact byte-identical owned committed packet may prepare an environment-only candidate that reuses the exact UiPacket/revision/identities; changed bytes at that revision and older packets reject. Candidate byte ownership remains defensive.

Native text proposals cannot inject arbitrary rich font/size/color/replacement spans. The initial native input path accepts plain strings, metadata annotations and native composing underline spans; other rich styles, content/correction/handwriting extensions and invalid Unicode/dead-key proposals fail before mutation. This is an explicit prototype restriction, not full IME/editor qualification.

A genuine exact-byte same-revision environment-only candidate instead retains the current native field/toggle transient value, including the actual Editable and composing span identity when the existing appearance/frame remains safe. The acknowledged packet is reused exactly; a new revision remains authoritative even when its binding equals the previous acknowledgement.

Committed environment invalidation immediately closes presentation/input gates. Input also synchronously compares the committed tuple before delivering an action, closing queued-listener gaps. Valid recapture alone cannot reopen a gate; a successful prepared environment transaction is required. Unsupported recapture retires the old owner. The native corpus includes actual root-layout invalidation, recovery, and an isolated synthetic Activity resource Bold Text adjustment; this does not qualify a physical preference workflow. Checked interaction-epoch exhaustion retires before event delivery.

This bounded consumer also rejects navigation whose immediate content is a container containing a List: indirect compact-navigation relayout is not qualified. Direct navigation/List remains admitted. Nonzero button label insets are applied before native intrinsic/constraint measurement; a separately packaged canonical positive descriptor checks long-label wrapping, horizontal intrinsic width and Layout-plus-vertical-inset containment with software/compositor captures.

The final review replay is invoked as `python3 verification/android-native-appearance-v2/qualify.py --output candidate-15 --emulator emulator-5586 --paired-viewport`. The observed result, exact source closure, native assertion count and retained build hashes live in that candidate's `receipt.json`; its `artifact-seal.json` covers the evidence. A failed attempt stays failed and requires a subsequent numbered candidate. `emulator-cleanup.json` records disposal of only the current lane-owned instance; prior lifecycle receipts are retained separately. Runtime support is still API37 evidence only, API36 prototype floor, with API28…35 and the final physical matrix pending.

Candidates11…13 retain the failed exact-snapshot investigation: constructing a SpannableString copy also copied native watcher spans and advanced the live editor interaction epoch during journal preparation. The journal now captures a plain immutable text value, retains the original buffer by identity, and records composing spans separately without copying framework watchers. Collapsed selectable-text selection is treated as active native selection too. The exact pre-attachment guard remains enforced.

Candidate14 passed450 native behavior assertions,9 separately packaged inset assertions and five complete-catalog rejection installations with unchanged source. Local visual inspection then identified stale/blank compositor captures; that visual gap is retained rather than inferred passed from native assertions. The capture harness now waits for actual hardware frame submission, obtains a public PixelCopy window image plus UiAutomation compositor image, and requires both to match the current software scene by structural ink intersection/union (at least0.75), with bounded capture attempts retained. This is a same-platform stale/blank-frame check, not pixel parity or cross-platform acceptance.

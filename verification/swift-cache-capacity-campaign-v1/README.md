# Swift cache capacity campaign v1

This isolated diagnostic compares the full retained Swift workload with 64/64M,
64/128M, 128/64M and 256/64M resident/work profiles. The first run is a fresh
control because every candidate uses the same widened resident-index format and
the CI toolchain/host differs from the preserved macOS baseline. Historical
failure and timing receipts are unchanged. No candidate changes canonical VM
source, installed limits, release authority, validation grammar or capability
grants. The selected lead is `gpt-6-astra`, `xhigh`, fresh context, under policy
commit `b6410e917fab899731dece2678fe2ade2e854464`.

The named unlock is both corpus calls returning all 11 original native-reference
fields correctly on one initialized owner, followed by consuming cleanup with
zero reservations/live counts/tickets and no invariant. This is diagnostic host
feasibility. A work-only success establishes profile feasibility. A single run
does not establish a CPU/latency optimization, production default or native/GA
acceptance. The fifth combined variant is reserved for a root decision from the
four primary results; this driver does not spend it speculatively.

## Selected execution boundary

Root integrates `workflow.yml` into `.github/workflows/` and dispatches that
workflow once at the committed source. It uses a fresh GitHub-hosted Linux
runner, no self-hosted or local execution. The exact decisive command is:

```sh
python3 -B verification/swift-cache-capacity-campaign-v1/campaign.py run \
  --output "$RUNNER_TEMP/swift-cache-capacity-campaign-v1"
```

Each profile compiles the same accepted 132-file observer closure, applies the
small retained patch, runs four finite actual-cache tests and the original
synthetic harness control, then attempts the exact full reactor once. Compile is
bounded to 180 seconds; each finite command to 90; each full target to 170, plus
five seconds each for TERM/KILL. The workflow has a 25-minute ceiling. There are
four primary full attempts, counted before spawning, with no automatic retry or
resume. A timed-out/unclean owner stops the comparison. Only the new remote child
group is checked or signalled; no global process inventory is used. The owned
scratch is removed after all owned groups exit, including failed runs. Raw
stdout/stderr, source manifests/patches, tool versions, binaries' identities,
commands, per-child wait4 CPU/RSS, first failures, complete phase observations,
attribution and cleanup outcomes survive in the uploaded artifact.

The driver has a separate 1,080-second aggregate deadline and declines a command
unless its complete existing timeout plus 20 seconds for cleanup/receipts fits.
Thus the sum of four pessimistic per-command maxima cannot overrun the outer
workflow. Rust installation has a separate three-minute bound. SIGTERM/SIGINT
request cancellation through the same owned-group TERM/KILL and receipt path;
they do not immediately abandon a child. Hard OS termination remains an external
limit and cannot be represented as successful cleanup.

The exact full input is the existing 18,976,211-byte gzip, copied unchanged with

Source and workload are checked again after each target. The original complete

Native/UI/capture remain paused, phones disconnected, Android stopped-v5 stays

## Storage and lifetime audit

| Item | 64 residents | 128 residents | 256 residents | Admission/lifetime |
| --- | ---: | ---: | ---: | --- |
| Resident index, 128 fixed buckets plus N links, u16 | 384 B | 512 B | 768 B | Whole payload charged in cache header before allocation; dropped before header refund. |
| Cycle bitmap per helper inventory | 8 B | 16 B | 32 B | Three complete `ResidentIndexInventory` copies in existing operation reservation; no heap allocation. |
| Eviction-plan bool array | 64 B | 128 B | 256 B | Existing operation reservation uses `size_of`; every cell is recounted and charged. |
| Resident slots | N × actual `SwiftSlot` size | same formula | same formula | Checked multiplication and exact-capacity allocation under original cache reservation; per-entry ticket is inside the slot. |
| Ticket count ceiling | 86 | 150 | 278 | N + unchanged 22 overhead; this ledger is a counter, not an additional fixed ticket array. Resident tickets/transfer copies already charged by actual types. |
| Active pins | 64 | 64 | 64 | Pin storage, nonce identity, first-free search and limit unchanged. |

The new bitmap arithmetic introduces no retained named locals: `slot / 64` and
`slot % 64` index the accounted array. Link element/borrow/Vec types and all their
existing inventory copies become u16 consistently. Bytes and element counts are
separate constants. The 128 bucket hash, full-chain validation, lookup/rebuild
debits and fail-before-publication order remain unchanged. Wider tables increase
construction work and planning scans naturally; charges are never discounted.
Cycle scratch zeroing covers one, two or four u64 words per lookup. Credit
comparisons retain the existing semantic cell/probe charges; CPU and RSS remain
separate measurements, and this bounded scratch work is not a new unbounded scan.
The shared generic planning maximum changes only inside this isolated test
closure, which is never published as a library. Frozen/public profiles require
their own integration and independent regression before any promotion.

The cache stays 16 MiB, each entry 8 MiB, guest memory 48 MiB and combined logical
reservation 256 MiB. Original instruction fuel 100M, execution work 1B, 64 frames,
host/WASI budgets, validation deadline 120 seconds and cumulative runtime/WASI
deadlines 30 seconds remain. The existing conservative full-owner envelope test
is generalized to N actual residents and checks the same combined ceiling, then
consumes the actual owner. New controls retain N residents, force eviction,
exercise 64 pins and reject the 65th, walk/corrupt a full N-node hash chain, test
slot 256 encoding, and reuse original exhaustive replacement work/cancellation,
constructor allocation and narrowed-header lifetime controls.

The accepted fixed-size attribution observer is copied unchanged. Its test-only
memory/output and the external input Vec remain separately observed external
diagnostic overhead, not silently declared product reservations. RSS is reported
separately from logical reservation peaks. Timing includes this instrumentation;
it is a single observation, never a historical paired speedup claim.

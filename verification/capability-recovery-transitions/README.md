# Private recovery transitions

This lane adds internal, opt-in schema-3 recovery transitions. It does not expose an OTA factory or coordinator. Production composition, concrete adapter retirement, actual UI milestones, device lifecycle, published packages, FieldLog and GA gates remain separate.

`run.py --label <fresh-label>` exports immutable dependencies from `bf5021e2ce920dae78f0c778511040617f65082c` and exactly four named transition files, plus this runner and three original public compile negatives. It copies the existing frozen b25 experimental native stage and checks its source/feature receipt. It builds one Swift graph, retains Debug and Release products/module maps before TSan, and records commands, source/header/archive/product hashes, tool versions and output. No default Rust archive is linked. No bit-reproducibility, total RSS or OOM-recovery guarantee is inferred.

The worker alone mints selection issuer keys. A published selection follows full signed/payload verification, real native admission and durable attempt write. Consume checks the exact worker handle/epoch, cutoff, same-context evidence and signal generation. A safely discarded valid unconsumed handle throws `CapabilitySelectionConsumeError.rejected`; `.cleanupRequiresReopen` is not fallback authority. Foreign/stale calls never discard a real handle. Consumed/discarded/closed selection handles release their input reference; a stale handle retains only bounded identifiers.

Intent is durably recorded before enable, with an in-memory sticky signal latch set at commit entry. Observation begins only when the private coordinator confirms actual successful enable. Health requires the configured native milestone set, monotonic observation and exact evidence revalidation. A terminal arriving during entered health I/O cannot undo its durable result, but the API returns false and preserves active attempt linkage for recovery. Deterministic counting uses exact checked typed startup/invocation/wake failures and stable codes, including fuel/host-call/depth/stack limits. Other resources, malformed/API/unknown/cancel/deadline/panic outcomes never become deterministic guest traps. Any terminal after intent returns recoveryRequired; no live guest switch is offered. Cold incomplete attempts become unknown interruption, never inferred deterministic failure, and do not retry a fresh stage. Records and sequence remain durable.

`requestStop()` synchronously denies new store operations and cancels admitted validation without descriptor I/O or a Task. It does not claim actual close: the sole counted closing owner must still call and await `close()`. The close-request latch is separate, so a prior stop cannot skip the real descriptor close. Abandoning after stop still pins/quarantines. An active checked terminal must be recorded with `failAndPrepareFallback` before this permanent stop; the signal latch blocks execution/health in the meantime. This store method does not substitute for the enclosing coordinator's terminal and cleanup ordering.

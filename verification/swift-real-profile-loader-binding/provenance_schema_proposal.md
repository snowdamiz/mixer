# Concrete proposed local development preimages

Pending root schema selection. Both are logical binary records; no Rust images, caller bools or digest strings. This is scoped trusted-local correlation and not package authorization.

`MIXLBD01`: fixed512-byte header followed by four exact length-delimited retained preimage sections: complete candidate source+host manifest, exact compiler argv, exact selected compile environment, compiler full version output. Total<=131072. All values are u64 little-endian; source manifest contains every distribution/support member's exact relative path/bytes/SHA256 and a closed count. Header: magic0..8, version8..16=1, fixed header bytes16..24=512, total bytes24..32, distribution count32..40=144, host count40..48=11; section lengths48..80 (four words), output extent80..88<=67108864; target88..152 exact64-byte zero-padded selected aarch64-apple-darwin; source+host manifest digest152..184, compiler argv digest184..216, selected compile environment digest216..248, compiler version output digest248..280, compiler executable digest280..312, actual compiled output digest312..344; remaining344..512 zero. Header section extents must sum exactly to total; no tail. The exact first three section digests and compiler executable/version digests are separately injected through compile-time env by trusted runner, and every runtime retained section is hashed and compared. Binary output digest is computed only after terminal compiler success and checked against the loader's actual current_exe bytes; the output digest is intentionally not embedded to avoid circularity.

Compile environment is a closed explicit ordered record, includes candidate identity/feature/target/configuration and the compile-time env variables. The embed values cannot include their own digest: compile environment section excludes only the identity-injection variables by an explicit closed rule and lists the excluded identity-variable names; their exact values are verified against the record at runtime. The runner fixes compiler flags rather than accepting arbitrary argv. It hashes compiler and candidate members before/after compiler child and verifies all output bytes before writing build preimage. Build record is immutable retained bytes. The host runner is trusted; fabricated compiler claims or compromised compiler/launcher are outside scope.

`MIXLSE01`: fixed512-byte header followed by four exact length-delimited sections: source-role/identity roster, actual invocation argv, actual selected runtime environment, actual cwd bytes. Total<=65536. Header magic0..8, version8..16=1, fixed512 at16..24, total24..32, source extent32..40<=actual validation source limit, section lengths40..72, actual five validation limits72..112 in source_bytes/metadata_bytes/scratch_bytes/work_credits/deadline_ms order, fresh nonce112..144, source digest144..176, complete build-preimage digest176..208, actual producer executable digest208..240, section digests240..368 (four32-byte SHA256s), remaining368..512 zero. All preimage sections are nonempty, exact, contain no hidden or trailing bytes and match actual process observations and retained input handles in accepted local scope. Source roster is one regular source File's dev/inode/size/mtime/ctime representation, paired with role bytes `original-input`; build/session/producer handles have separately preserved identity observations in the returned LoaderFiles. The nonce is issued by the trusted runner from OS randomness; presence alone does not prove freshness or authenticate a launcher.

The loader never reconstructs missing limits from usage. It verifies every actual caller-supplied validation-budget word equals the session's complete five limits before calling the original validator. Actual source bytes must hash to source commitment and equal returned proof.source byte-for-byte while both live. `MIXLSE01` session record digest is carried with actual budget in private provenance after all joins pass. Session and build files cannot alias each other/source/self executable. File handles and exact metadata are returned on every result; external close/name uncertainty is never converted to successful cleanup.

## One paid acquisition outcome and explicit retirement

`TestReservation.outcome` is created with the reservation, before any input
effect. The fixed thirteen-slot table retains raw obligations, validated state,
adopted File owners, retired state and sticky one-time adoption bits. The
thirteenth slot is the actual path-packet File. Safe model adoption immediately
moves each handle into `paid.owned`, with no intervening fallible action.
`Refused.outcome` identifies that exact carrier on acquisition/admission/
correlation refusal. The original raised refusal and any underlying original
read/allocation/retirement object retain identity in the paid diagnostic roster.

The root reserves an operation partition, a separate finite cleanup partition
and the whole storage charge together. Acquisition operations have no access to
cleanup work. The synthetic tests use 1000 cleanup units; this is not a native
price or selected product quantity. A too-small cleanup provision can never
produce a complete retirement token. Storage remains fully charged while any
actual modeled File, body, packet, diagnostic, selected result or carrier lives.

`destroy` makes one bounded model retirement attempt. Adopted Files retire with
separate cleanup tickets. A still-raw/validated/invalid slot never receives a
close operation: even after all known adopted owners retire, the **entire
reservation remains charged**. A separately reviewed process-level retirement
protocol would be needed to discharge raw obligations; none is supplied here.
The test model deliberately supports that conservative branch instead of
pretending an unchecked descriptor integer is an owned File.

Full retirement destroys all thirteen inherited Files, independent loader Files
and buffers, the twelve identity bodies, five native and five retained paths,
the independently live packet buffer, diagnostic/result places and finally the
carrier. Only the complete original once-only token can release storage. Missing
or incomplete token, cleanup exhaustion, failure or unwind retains the charge.
Retirement cannot retry a possibly attempted close or adopt a retired slot.
Model retirement reports **no healthy native close**. Post-retirement misuse is
rejected by the external test caller and cannot resurrect a paid carrier.

Every future allocation adapter must provide a reviewed **requested extent +
maximum success slack + original failure backing** bound before invocation.
The synthetic `AllocationContract` charges all three conservatively even when
success/failure backing could be mutually exclusive. No post-hoc capacity test
or `try_reserve_exact` assumption is used. Actual allocator, original error
pointees, native operation costs and Python scaffolding allocations remain
outside the model's qualification.

## Necessary zero-claim transport amendment

The original helper encodes its opaque claims before rows. SHA-256 of actual rows
cannot honestly be supplied before those rows exist. Rust std has no SHA-256,
and suspension into a host callback while the guard lives is prohibited.
The proposed separately reviewed amendment therefore has two explicit artifacts:

1. The original512-byte transport header, encoded by the actual accepted helper
   with **all eight opaque input slots zero**, and the original typed constructor
   result retained unchanged. Zero is transport content only. It means no actual
   digest was supplied or verified. Retain and hash the exact raw512 bytes;
   never replace them in historical result/evidence, treat zeros as predeclared
   bindings, or rewrite a returned original outcome.
2. A distinct final512-byte host header. The host independently checks every
   nonclaim byte: words0..15 at[0,128), including actual extent/type/slot/pin/
   nonce/B/capacity/entry fields, and reserved zeros at[384,512). It checks
   transport[128,384) is exactly256 zeros. It derives eight digest byte strings
   from exact retained inputs below and constructs a new header by preserving
   [0,128), inserting those256 bytes, and preserving[384,512). Compare all256
   nonclaim bytes again. The final header is a new host artifact; the original
   transport's unverified claims are never retroactively authenticated.

`bind_fixture_template` implements only this byte witness on a synthetic header.
It is not product selection or proof that the scalar bytes came from an owner.
The composer accepts a separate final header and independently hashes all inputs
again before creating its exclusive output. The test retains both header digests
and proves the original transport bytes survive unchanged.

## Same-guard actual snapshot exporter proposal

The future private exporter must live inside the validator/cache privacy boundary
and be called only through the actual live `InitialProfileBorrowV1`, never an
external snapshot parameter. Its sole proposed interface is:

```rust
fn export_initial_snapshot_binding_v1(
    initial: &InitialProfileBorrowV1<'_>,
    provenance: &SelectedSnapshotExportProvenanceV1,
    output: &mut File,
) -> Result<SnapshotExportObservationV1, SnapshotExportErrorV1>;
```

The private selected provenance contains the closed accepted build/source/session
record handles and complete validation/invocation budget records. It cannot be
minted from caller strings, phase bits, matching hashes or an imported profile.
An authentic private producer must compare those selected facts with actual build
configuration and original validation provenance. The current owner does not
retain its original validation budget or build/session transcript; that provenance
capture is a real additional source dependency, not reconstructible from usage.

Call the exporter after authentic phase completion and all initial guard checks,
before header/rows and before any acquisition. Obtain `initial.cache.proof()`
directly; serialize fields through shared immutable borrows in source order.
The same guard then emits the zero-claim transport header and unchanged row body.
No callback, await, guest/native operation, mutable control/owner operation or
arbitrary writer closure is reachable between export and row emission.

The proposed outer orchestration result is a product of the **unchanged** original
`InitialProfileConstructionOutcomeV1` and
`SnapshotEmissionStateV1::{NotAttempted,Attempted(Result<SnapshotExportObservationV1,SnapshotExportErrorV1>)}`.
It adds no ninth original variant. Original tags1..5 and7 have NotAttempted;
tag6 from pre-guard admission has NotAttempted, while tag6 from the later encoding
helper retains Attempted and the exact exporter result. Tag8 always has Attempted.
Preserve this branch distinction without adding an original phase authority bit.
Once the guard exists, attempt export exactly once,
retain its exact error/progress, and still run original header/row emission in its
original order. An export failure makes the bundle unusable regardless of row
success; it does not refund, destroy, relabel or suppress any original owner or
failure. An outer observer failure cannot become an original runtime failure.
Return cache/proof owners through the original owning-control cleanup. No drop
stands in for a ledger refund; no retry of constructor/export/output name occurs.

`protocol-types.rs` freezes proposed data fields and source-private discriminants,
without compiling or claiming their sizes. Exporter errors are fixed

Retain physical partial output. It requires a distinct empty,

## Canonical byte grammar for the eight digest preimages

Every slot is `hashlib.sha256(exact_preimage_bytes).digest()`; no custom crypto,
concatenation of unframed hashes, pointer/object images or new dependency. Digests
are32 bytes; textual hashes inside records are64 lowercase ASCII hexadecimal
characters. There is no final selection/profile digest inside the header or
snapshot record, avoiding a digest cycle.

Structured records use eight ASCII magic bytes + LF + one canonical ASCII JSON
object + LF. JSON keys are sorted by their ASCII bytes; separators are exactly
comma and colon with no whitespace. Integers are canonical unsigned decimal
0..2^64-1 with booleans/floats/negative zero/exponents forbidden. Absence is
explicit JSON `null` where the schema permits it. Strings are printable ASCII;
JSON escaping is Python `ensure_ascii=True` (including quote/backslash escaping).
Duplicate/missing/unknown keys, noncanonical escape/number/key order, trailing
bytes, unsupported versions and record size>16MiB refuse. Depth<=16; array<=80,000;
string<=4,096. `schema.py` is the executable normative key/order/type grammar for
the proposed version1 records, scoped to host preparation. The source manifest's
and compositor's narrower record caps below also apply. Arrays preserve actual
source/index order, except the explicitly byte-sorted member/type/enum lists.

| Slot / header offset | Exact proposed preimage | Independent provenance still required |
| --- | --- | --- |
| 0 /128 | `MIXSRC01` record with role `baseline`, exact selected member list | Every named member opened/hashed; accepted baseline build/source relation |
| 1 /160 | `MIXSRC01` record with role `candidate`, exact complete selected member list | New exporter/adapter/diagnostic inputs/count schema, patch/member completeness, build-to-binary proof |
| 2 /192 | Raw original reactor input bytes, exact length, no prefix/newline/transcoding | Actual immutable owner's source equality and original input custody |
| 3 /224 | `MIXEVS01` complete event-schema definition record | Exact selected field/enum/flag/reserved mapping and actual writer source/executable relation |
| 4 /256 | Raw selected compiled profile-adapter executable bytes | Accepted source/toolchain/configuration/build receipt, not executable name alone |
| 5 /288 | `MIXLAY01` complete configuration-specific measured layout receipt | All complete types/lifetimes/build facts and independently accepted accounting |
| 6 /320 | `MIXSNB01` immutable actual snapshot binding record below | Sole private actual-owner exporter, original validation/session/build and same-guard correspondence |
| 7 /352 | Raw exact2,560,000 retained row-body bytes | Same guard's unchanged row writer; independent equality with final profile[512,2560512) |

`MIXSRC01` keys are `schema=1,role,members`. Each member has
`path,bytes,sha256,role`; paths are unique strictly increasing ASCII relative
paths, <=4,096 bytes, <=255/component, no empty/dot/dotdot/absolute/backslash/NUL.
Roles are distribution/host_support/patch/diagnostic. Counts1..4,096. A manifest
does not include a receipt which hashes that same manifest. Baseline/candidate
roles are bytes in the preimage; equal lists with different roles hash differently.
The current140+11 list is a predecessor, not automatic coverage of new sources.

`MIXEVS01` keys are `schema=1,event_magic,record_bytes,byte_order=little,fields,
enums,writer_source`. Fields contain exact `name,offset,bytes,kind`, cover every
byte contiguously, include magic/reserved fields, and use unsigned/enum/flags/
digest/reserved_zero/magic kinds. Enums contain exact `field,values` tables with
ordered `value,name` pairs. The accepted selection must enumerate every enum and
flag value and enforce unknown-bit refusal, field-specific applicability and
writer identity. This preparation's synthetic `SYNTEV01` is no real event schema.

`MIXLAY01` keys are `schema=1,target,rustc_sha256,rustc_vv_sha256,configuration,
candidate_manifest_sha256,adapter_binary_sha256,type_inventory_sha256,types,totals`.
`types` lists exact ID/name/bytes/alignment entries by increasing ID. Bind the full
selected inventory bytes externally and require every complete Result/caller/
transfer/error/cleanup type, not an arbitrary subset. `totals` names foundation,
constructor_union,prepared_bound,headroom,row_union,cleanup_union. Debug, optimized,
production and cfg(test) facts cannot be merged into one unsupported layout.
This preparation's synthetic layout is no actual compiler/layout receipt.

No current real context magic/version is selected. The future selection handle

Each metadata buffer (`signatures,parameters,imports,functions,globals,exports,
data,elements`) stores **capacity,charged,category,items**, preserving the actual
private Buffer accounting/capacity rather than guessing from a Vec size. Category
is exactly Metadata. List length is serialized by canonical array structure;
len<=capacity; source policy finite caps in the scaffold are512/8,192/34/79,966/

Every span is `[offset,bytes]` with exact checked source bounds and u32 coordinates.

## Descriptor custody and distinct composition protocol

The only executable scope is `trusted-quiescent-fixture-v1`. Coordinated hostile
path rewrites, metadata restoration, writes through other descriptors, malicious
children or filesystem aliases are unsupported. Reject any request for that
scope. Path/metadata/hash checks detect the finite tested failures; they do not
prove immutable files against a coordinated attacker.

The future actual entry takes a private independently admitted selection handle,
not caller paths/digests/booleans as authority. Inputs are one retained descriptor
for each of the eight exact preimages plus the original transport header/result
artifacts and their exact receipt correspondence. The prototype's public fixture
paths/sizes/header arguments are explicitly untrusted testing inputs.

For each exact absolute path, walk from retained root through every bounded
ancestor with O_DIRECTORY|O_NOFOLLOW; keep all ancestor descriptors until close.
Open the final regular file O_NOFOLLOW|O_NONBLOCK; check exact length, initial
offset0, dev/inode/mode, single link, and component identity. The borrowed-body
entry also supports the same still-open descriptor at exactEOF after the finite
synthetic writer; it never reopens that body path. Other offsets refuse. The real
producer handoff must independently require its actual successful writer's exact
EOF/progress and original retained descriptor, not choose a caller-supplied mode.
No symlink ancestor
or leaf, FIFO/device/directory, hardlink, wrong length, alias or reused fd admits.
Check path-component dev/inode/mode against fstat and retained file dev/inode/
mode/size/mtime_ns/ctime_ns/nlink before and after each hash. atime is excluded
because reads can change it. Current fixture directories are trusted/quiescent.

With one reusable4,096-byte parent buffer, hash all eight exact inputs through
their retained descriptors, with exact expected byte counts and bounded EOF.
Check source_extent equals retained input length, supported header fields,
reserved bytes and each actual digest slot. Create one distinct output once with
O_RDWR|O_CREAT|O_EXCL|O_NOFOLLOW,0600, regular/empty/offset0, distinct inode. Write
the separate final512-byte header; stream exactly625 body blocks from the retained
row-body descriptor. Every explicit read/write/EOF block has32 attempts including
Interrupted; zero, error, overreport, exhausted attempts or short/extra file refuses.
The last permitted successful attempt is accepted. No seek/reopen/truncate of an
output name, retry name, append workaround, removal or rollback occurs.

At success require exact output length and acknowledged offset2,560,512. Hash the
entire retained profile and independently its[512,2560512) subrange, with exact
EOF; compare subrange to original row-body hash and slot7. Retain both hashes.
After the finite consumer, repeat complete-profile/subrange hashing and every
input hash/metadata/component check through the same retained descriptors. Any
drift/mismatch refuses. Header/body bytes do not imply fsync or durability.

The closed fixture child argv is recorded exactly in evidence: the resolved
current Python executable, -I,-S,-B, this packet's exact consumer.py, profile fd,
body fd. No shell, arbitrary flags/consumer/path, environment inheritance,
additional pass_fds, external harness or current product binary is used. Exactly
two descriptors are privately adopted once with fdopen(closefd=True); duplicate
adoption refuses. The child independently hashes complete profile/subrange/body
with its own single4,096-byte buffer and finite32-attempt blocks. Parent wrappers
refuse read/seek/check/close while their shared OFDs are leased. Parent does no
read/seek until terminal wait/reap. Child output is fixed three hashes+adoption
count,245 bytes here, with an independently checked512-byte stdio cap after reap.

Timeout is5 seconds, then kill and terminal wait up to5 seconds, with a final
kill/wait attempt if still live. A nonterminal child leaves the involved owners
leased in explicit quarantine; it cannot authorize close/reuse, release the OFD
guard or report healthy cleanup. This nonterminal OS-fault branch is source-only
in this preparation. The fixed successful child is trusted; it inherits the
actual output's writable descriptor although its FileIO is opened rb. A generic
or hostile consumer is not qualified by this test. A future real custody protocol
must select descriptor access and executable admission independently.

On ordinary failure preserve physical partial output, progress and original
inputs; close every owned retained descriptor/ancestor and child stdio context.
On healthy execution all tracked owners close and owned scratch is removed. A
test-local fault witness actually writes512+13 bytes then fails; evidence records
that exact retained partial file and progress before test cleanup. Cleanup removes

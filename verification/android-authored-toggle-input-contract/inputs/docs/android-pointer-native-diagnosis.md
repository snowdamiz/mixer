# Candidate-5 first pointer failure: offline diagnosis

P03-1 delivered its complete presealed drag to the Activity, including UP, but did not satisfy the required one-revision acknowledgement. The strongest source-supported explanation is a mismatch between the authored switch geometry and the platform `Switch` drag range, compounded by the platform's slop transition. The recorded data do **not** establish the platform-private state or the exact child event route, so this explanation remains a conditional causal model. No product or fixture correction is accepted by this analysis.

This is a read-only diagnosis of [the failed runtime](../verification/android-pointer-timing-correction/runtime/runtime-1/receipt.json). Only the diagnosis document and its [owned proof directory](../verification/android-pointer-native-diagnosis/) were written. No native command, device discovery, new gesture, source change, Git operation, tracker change, or runtime cleanup was performed. The original runtime and candidate sources remain unchanged. The earlier user pause and subsequent native-test resumption remain historical/current authorization evidence respectively; this analysis does not dispatch another experiment.

## Concrete carrier mismatch hypothesis

The bound [frozen product source](../verification/android-pointer-oracle-repair/candidate-5/inputs/native/android/app/src/dev/mixer/android/NativeAppearanceViewsV2.java) creates a real `NativeSwitch`, applies zero view padding and TOP/START gravity, binds an empty native thumb with intrinsic size 111×72 px, sets switch minimum width 189 px, and binds an empty track of 189×84 px. `Empty` only overrides intrinsic size and drawing. The product subclass overrides `onDraw`, not `onTouchEvent` or native measurement/layout. Its authored drawing centers the track vertically and uses checked state for the visible thumb; it does not use the platform's continuous drag position. The bound fixture computes the same authored centers from those paths. These points are therefore intentional authored points, not arbitrary offsets.

The official AOSP `android17-release` branch was resolved to immutable frameworks/base commit [`94b4c163b7dfe5ce3607f7bb8456f9573f7de57d`](https://android.googlesource.com/platform/frameworks/base/+/94b4c163b7dfe5ce3607f7bb8456f9573f7de57d). The fetched branch and pinned [`Switch.java`](https://android.googlesource.com/platform/frameworks/base/+/94b4c163b7dfe5ce3607f7bb8456f9573f7de57d/core/java/android/widget/Switch.java) are byte-identical, SHA-256 `811b763bc9785f645f3fb77b7d9dc52212727b14a45570f740f7ad6a952fa6f7`. This source is official Android17 reference material, **not** a verified byte-identical match for the installed Google API37 framework. The [reference metadata](../verification/android-pointer-native-diagnosis/aosp-pinned-reference.json) states this limit.

In that reference implementation, native measurement reserves at least twice the thumb width. Crossing slop enters dragging and resets the previous touch coordinate without applying that crossing movement. Later movement changes normalized thumb position by distance divided by the native scroll range. A non-fling release selects on only above 0.5. [Base Drawable defaults](https://android.googlesource.com/platform/frameworks/base/+/94b4c163b7dfe5ce3607f7bb8456f9573f7de57d/graphics/java/android/graphics/drawable/Drawable.java) provide zero padding and optical insets.

The executable [conditional calculation](../verification/android-pointer-native-diagnosis/analysis-1/conditional-carrier-model.json) yields:

| Quantity | Authored / delivered | Conditional native carrier |
| --- | --- | --- |
| Track / carrier width | 189 px | max(189, 2×111) = 222 px |
| Off→on travel / scroll range | 66 px | 222−111 = 111 px |
| Track left/top in screen pixels | 921 / 1590 | 888 / 1566 with TOP gravity |
| First movement exceeding 24 px slop | 24.75 px at offset 240 ms | enters dragging and resets touch coordinate |
| Movement accumulated afterward | 41.25 px | 41.25÷111 = 0.3716216 |
| Non-fling UP selection | expected on | predicted off because 0.3716216≤0.5 |

This reference predicts strict off-thumb hit bounds `(864,1542)`–`(999,1674)`, containing the authored DOWN. It therefore predicts entry into the thumb path, followed by insufficient normalized travel, rather than a simple missed thumb. As arithmetic counterchecks, using the authored 66 px range would yield 0.625 after the same slop transition; retaining all 66 px in the 111 px carrier would yield 0.5945946. Both exceed 0.5. The combination of carrier range and slop transition matters.

The calculation assumes zero initial native thumb position when dragging starts, the positional release branch, no parent cancellation before the child, and the pinned algorithm matching the installed framework. None of those private runtime facts is independently captured. The 150 ms stationary endpoint gap alone does not measure `VelocityTracker` output. AOSP source and arithmetic do not close that evidence gap.

The fixture's accepted geometry preconditions prove visible authored centers, a fully visible target and distance beyond actual slop. They do not prove alignment with the platform carrier or sufficient native drag displacement after slop. Because the product delegates input to that carrier while drawing the authored geometry independently, a mismatch is a product behavior issue under this gesture contract until resolved. Moving the fixture away from the visible authored points would not resolve that requirement.

## Minimal next private diagnostic contract for root selection

No next runtime is dispatched by this document. The proposed experiment is observation-only and must be separately selected and frozen by root:

1. Preserve all production class/library/descriptor bytes and the P01→P02→P03 prefix, exact coordinates, pressure, offsets, settle logic, environment and failure oracle. Recompute and seal geometry using the same existing rules. Stop after P03; this experiment does not execute or qualify the remaining matrix.
2. Before any DOWN, preflight a passive read-only carrier observer on the debuggable private harness. Capture public dimensions, padding, gravity, switch minimum width/padding, compound padding, thumb/track intrinsic dimensions, drawable padding/optical insets and current drawable bounds. Capture the actual platform class/source or bytecode identity if root can retrieve it through official platform tools. Source identity retrieval alone is not an input pass.
3. To establish cause rather than merely strengthen the model, capture the actual `Switch` carrier bounds/width, thumb width/position, touch mode/last touch, and animation state before/after the existing Activity dispatch; capture selected release velocity and target state if available through non-pausing standard debuggable inspection. Also establish the actual child/parent event route, including any internally generated cancellation. The observer must not call `onTouchEvent`, invoke listeners, replace listeners, consume/retarget events, draw-for-measurement, set private state, disable animation, or change forwarding behavior. No breakpoint may pause the gesture or evade its immutable 100 ms lateness bound.
4. Private platform access is a precondition, not an assumed capability. If ordinary debuggable read access is denied or the necessary observations cannot be obtained without changing event behavior, retain that failed preflight and stop before injection. Do not grant hidden-API exemptions, change system settings, add product seams, widen coordinates or revise timeouts to get a result. Root can select a separate official-tool diagnostic approach after reviewing that evidence.
5. Export a bounded final settled snapshot in a `finally` path before owner close, even when the revision assertion fails. Label it as observation only; preserve the original failure and counts. Retain every attempted packet and log, bind all sources/tool versions/commands, seal nested receipts, and apply the existing one-owned-instance cleanup rules. No callback count may be invented.

If actual state matches the predicted 222/111 px carrier and enters dragging at the 24.75 px MOVE, stays below 0.5 and chooses the positional off result at UP, this hypothesis is established for that exact runtime. A missed child/thumb, parent cancellation, surviving animator, different carrier range or release branch instead identifies the next cause to investigate. Any subsequent correction must preserve the shared appearance requirement and be separately implemented and validated; this document chooses no implementation.

Only P01-1 and P02-1 currently pass their bounded cases. The full 20-action pointer matrix, physical-phone matrix, public Activity, system IME, accessibility, signed OTA, separate-repository FieldLog, store, operational and GA evidence remain unqualified.

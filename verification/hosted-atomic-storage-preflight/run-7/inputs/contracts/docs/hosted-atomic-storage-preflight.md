## Exact API and transaction boundary

The product Elixir entry remains `Authorization.with_authorized_transaction(identity, command, callback)`. Expose only fixed `Release.Repository.upload_artifact(context, checked_artifact, request)`, `read_artifact(context)` and `Audit.list(context, after, limit)` operations. Supported actions are exactly `artifact.upload`, `artifact.read`, `audit.read`; there is no arbitrary SQL, Repo/connection, callback, role, actor, audit-body, event-ID, state/hash or job argument on the repository API. The transaction callback is trusted fixed product code. Fixture arbitrary SQL, asserted audit display, controllable clock/fault rows and the foreign EXECUTE grant are adversarial machinery, forbidden in the product.

Use additive `mixer_authz` and `mixer_hosted_release` schemas. Do not modify `mixer_release`, its historical migration or Go data. The sole product mutation entry is precisely:

```sql
mixer_hosted_release.upload_artifact_v1(
  mixer_hosted_release.writer_context_v1,
  mixer_hosted_release.artifact_input_v1,
  mixer_hosted_release.request_input_v1
) RETURNS mixer_hosted_release.upload_result_v1
```

No overloads, default arguments or other mutation entry points. The [manifest supplement](../verification/hosted-atomic-storage-preflight/contract-manifest.json) freezes types, role/grant/policy responsibilities and explicitly distinguishes product names from disposable specimen names. Composite fields, in order:

| Type | Exact fields and bounds |
| --- | --- |
| `writer_context_v1` | `backend_pid int4`, `full_xid text` (canonical full `xid8` decimal, never 32-bit/JS number), `database_name name`, `runtime_role name`, `invocation_nonce text` (64 lowercase hex for 32 random bytes), `sql_deadline timestamptz`, `principal_id uuid`, `token_expires_at numeric(20,0)` (0..2^53−1). | `request_input_v1` | `key text` (ValidID, 1..128 ASCII bytes); `normalized_route text` (exact `/v3/private/artifacts`, 21 ASCII bytes); `original_body bytea` (1..6,291,456); `request_sha256 bytea` (32, independently recomputed); `reason text` (valid UTF-8, 0..512 bytes); `request_id uuid` (server generated); `source_ip text or NULL` (canonical host IPv4/IPv6 without prefix/zone, 1..45 ASCII bytes; supplied only by trusted transport). The SQL routine cannot cryptographically establish signed JSON↔CBOR equivalence, signature validity, stage durability or bearer identity. Before entry, the accepted artifact admission owner must provide/recheck exact retained bytes against current trusted host/roots/time, normalized metadata must match the signed target, and the local fixture must verify stage bytes before locks. The product repository preserves current-policy rechecks and immutable comparison. The specimen deliberately accepts synthetic canonical bytes and `{}` documents, not v3 artifacts; no upload/release claim follows from these fixtures.

Retain the selected original fixed Repo/process/dynamic-Repo/ref/backend/full-xid/database/runtime/nonce/action/exact-target guard. Enter READ COMMITTED first, with `queue:false`, one immutable absolute monotonic deadline capped at five seconds, decreasing `statement_timeout` and per-call timeout/deadline, and 250 ms `lock_timeout`. A busy pool fails before callback entry. No protected retry may reuse a context or wait inside the original authorization callback for pool recovery.

Immediately before the function call, `AuthorizedContext` must compare actual **runtime** `current_user`, owner process, fixed Repo/dynamic Repo, reference, backend, full xid, database, nonce, exact action/target and remaining original deadline. Derive the SQL wall deadline from the remaining monotonic budget; it never extends the DBConnection deadline. Recheck that original context after return and before transaction completion. The database routine does not start/commit transactions or create a new context.

`SECURITY DEFINER` intentionally changes `current_user`. Inside the sole routine require the exact allowlisted writer owner and exact runtime `session_user`; require `current_setting('role') = 'none'`, rejecting even `SET ROLE` to self; require captured `runtime_role` equals the configured runtime login, exact backend/full xid/database/nonce, exact principal/action/target and a nonexpired SQL deadline no more than five seconds ahead. Resolver calls have their own exact definer owner and remain on the same backend/xid/nonce. Never allow a generic set of role names or compare the writer's `current_user` to the runtime's captured value. Startup must reject pool/session identities that do not match this topology. PostgreSQL documents the identity distinction in [session information](https://www.postgresql.org/docs/17/functions-info.html) and definer hardening in [CREATE FUNCTION](https://www.postgresql.org/docs/17/sql-createfunction.html). Neon or role-changing poolers are unqualified.

The nonce/GUC/context remains API discipline inside trusted BEAM code; malicious owning-process code can forge GUCs and issue raw SQL. This is not a bearer verifier, in-process sandbox, hostile-runtime defense or SQL-injection guarantee.

## Role, policy and complete mutation manifest

Use separate `mixer_hosted_schema_owner`, `mixer_hosted_authz_resolver`, `mixer_hosted_domain_writer` NOLOGIN roles, all NOSUPERUSER/NOBYPASSRLS/NOCREATEDB/NOCREATEROLE/NOREPLICATION, and the exact configured restricted runtime login. Schema owner owns tables/types/policies and pure codec functions. Resolver owns only its enumerated authz definer helpers. Domain writer owns **only** `upload_artifact_v1`; it owns no schema/table/other function. Neither runtime nor writer may inherit or SET ROLE through any membership chain to owner/resolver/elevated roles. Runtime owns no database/schema/table/function and has no TEMP/schema CREATE/server-file/program/blanket data privileges. Startup compares exact object definitions/ACLs and effective/session roles against the coordinated migration manifest; this preflight does not ship that inspector.

Create/revoke PUBLIC execution atomically; set default privileges closed; no PUBLIC or unexpected grantee execute. Every definer is VOLATILE, PARALLEL UNSAFE, non-LEAKPROOF, `SET search_path=pg_catalog`, `SET row_security=on`, schema-qualified fixed SQL, no dynamic identifiers/SQL/network, exception text without input secrets. Every private table has ENABLE and FORCE RLS. Only offline fixture/migration owner has explicit bootstrap policies; never pool it.

Runtime has USAGE and EXECUTE on only the selected public resolver/read/write helpers, scoped SELECT for artifact reads/audit reads, and **no INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES on artifacts, audit, idempotency or tenant heads**. No direct idempotency/head SELECT endpoint. Writer has SELECT/INSERT on artifacts/audit/idempotency; SELECT and UPDATE only of `last_event,audit_hash,state_hash` on existing tenant heads; EXECUTE on private pure codecs and narrow resolver evidence. It cannot UPDATE/DELETE immutable rows or create heads. Resolver's five-class lock grants remain as selected in the membership contract. In the specimen, one synthetic policy row and its narrow UPDATE(revision) grant stand in for those five classes; no full authz lock implementation is claimed.

Resolver policy predicates read only authoritative authz tables under simple resolver role policies; they never recurse into the domain table whose RLS called them. Domain writer policies check authoritative current context and the actual row tenant/resource scope. Idempotency lookups are bounded to the locked tenant/key; the routine reads a mismatched principal only to return a closed conflict, with no body disclosure. Runtime read policies require exact action and actual target, not a `mixer.role` shortcut. Full target-aware product RLS remains an implementation gate; specimen tenant `o/p`, app `a`, environment `e`, platform `ios` are deliberately fixed synthetic values.

The routine performs exactly this sequence:

1. Validate all bounded typed inputs, recompute `manifest_sha256 = SHA256(canonical_manifest)`, payload reference/hash correspondence and request hash. Bind normalized fields to already checked signed target; actor comes only from current admitted identity. No caller event/hash/display may decide persistence.
2. Require canonical existing shared authz locks (profile → principal → family → organization head → project head) in the product seam, then lock the **existing** tenant head FOR UPDATE. Assert exactly one row after every lock. No lazy runtime head creation, lock upgrade or SKIP LOCKED. The specimen uses a synthetic shared policy lock then the actual head lock.
3. Execute a fresh separate VOLATILE policy/evidence query **after the final lock** and check fresh expiry and SQL deadline before any idempotency lookup. Under READ COMMITTED each volatile SQL query obtains the relevant fresh snapshot; do not rely on a waiting statement's earlier snapshot. Product full credential/binding/policy/time decision is pending. Current-policy revocation/expiry denies even a byte-identical retry.
4. Validate initial head or the stored terminal event: event ID, tenant, previous/current state, previous event hash, standard hash of exact event CBOR, exact display↔CBOR mapping and stored display bytes. Require bounded ID increment and no wrap; corruption fails closed. Product audit verification must additionally check the predecessor edge and complete typed row constraints; the specimen proves terminal linkage and rejects changed previous-hash columns/display/body/head but is not a full historical-chain verifier.
5. For a tenant/key row compare immutable principal, exact action, exact target bytes and request hash **independently**. All equal returns original status/body/event without new writes; refreshed eligible credentials for the same principal may match. Any difference is 409 with no cached body. The unique tenant/key constraint remains the conflict fence.
6. For a new key compare the complete immutable stored artifact projection. An absent artifact inserts and returns 201; identical exact signed-document/canonical/signature/payload-reference/normalized metadata returns 200; changed immutable content is 409. Original retained signed-document bytes are part of this equality, so a different signed-document byte representation can conflict even when manifest digest matches. A changed original upload body alone changes request hashing, not stored artifact equality.
7. Compute the next fixed event from actual authoritative values and actual change, then insert artifact if absent, immutable audit, exact idempotency result, and update the head. No successful new-key return bypasses audit/idempotency/head writes. Any error at any boundary aborts all writes and leaves no event-ID gap. No Oban intent exists in this artifact-only routine; domain/job atomicity and G24 remain pending.

## Audit schema1 and state commitment1

Use the deterministic subset of [RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html): definite arrays, shortest-width unsigned integers in 0..2^64−1, valid UTF-8 text, byte strings and explicit CBOR null (`f6`) only. Reject negative/fractional/float/boolean/tag/indefinite/map values, overlong encodings, trailing items and unexpected field counts/types. No implicit absent optional value, arbitrary metadata map or raw token/claims. The immutable CBOR bytes are the hash authority; JSON is a validated display projection.

Below `B` means a CBOR byte string, not lowercase hex text. UUIDs are B16 in network byte order; hashes are B32. Root/profile/membership revisions are positive signed-bigint values; profile version is 1..2^31−1. Times are checked integer Unix seconds (identity/token values ≤2^53−1); future schema changes require a new version. The current action is successful `artifact.upload`; read operations do not fabricate successful upload events.

```text
Event1 = [
  1, event_id_u64, [organization,project], Actor1, Decision1, Target1,
  "artifact.upload", reason_utf8, request_uuid_B16, canonical_source_ip_or_null,
  recorded_at_seconds, previous_state_B32, current_state_B32,
  previous_event_hash_B0_or_B32, request_sha256_B32
]                                             // exactly 15 fields
Actor1 = [principal_B16,"human",binding_B16,profile_id,profile_version,
          issuer_ref_B32,subject_ref_B32,client_ref_B32,credential_jti_sha256_B32,
          credential_family_B16,authenticated_at_seconds] // 11 fields
Decision1 = [decision_at_seconds,profile_revision,principal_revision,family_revision,
             organization_head_revision,project_head_revision,
             [[membership_lifecycle_B16,canonical_role,revision],...]] // 7 fields
Target1 = [organization,project,app_or_null,environment_or_null,platform_or_null,
           runtime_B32_or_null,manifest_B32_or_null] // 7 fields
```

For upload all Target1 optional fields are present. Audit-read context is project-only with all five explicit nulls; it is not an upload Event1. Membership evidence has 1..64 unique applicable lifecycle IDs sorted lexically by UUID bytes, with canonical roles exactly owner/administrator/developer/release_manager/billing_manager/viewer. Only owner/administrator/developer may upload; release_manager/viewer may artifact/audit read, billing_manager neither. Each permission also needs its verified exact OAuth scope. Unsupported roles/actions/identity classes fail closed. The specimen executes role ceilings but supplies synthetic scope/time/binding evidence; real scope/credential enforcement is pending.

`issuer_ref`, `subject_ref`, `client_ref` each equal `SHA256("mixer.hosted.identity-ref.v1\0" || CBOR([kind,profile_id,exact_verified_value]))`, with kind exactly `issuer`, `subject`, `client`. No normalization or email linkage. Credential digest remains the membership contract's exact UTF-8 jti SHA256, namespaced by immutable binding/profile. `authenticated_at` is the trusted verifier evaluation time, not an unverified optional claim; `decision_at` and `recorded_at` are trusted database current seconds. None substitutes for expiry/current policy.

```text
event_hash = SHA256("mixer.hosted.audit.v1\0" || CBOR(Event1))
initial_state = SHA256("mixer.hosted.state.v1\0" || CBOR([1,organization,project]))
Change1 = [1,manifest_B32,payload_B32,payload_size_u64,blob_reference,
           Target1,signed_document_sha256_B32,signature_B64] // 8 fields
changed_state = SHA256("mixer.hosted.state.v1\0" ||
                      CBOR([1,previous_state_B32,[Change1]]))
```

No actual domain insert means `current_state = previous_state`, including a new-key identical artifact success. This commits an **ordered transition projection** of prior state and actual immutable artifact changes. It is not an order-independent canonical database snapshot, nor a commitment to every database column. Creation actor/event metadata is bound by the immutable event and row linkage; the stated Change1 projection covers semantic artifact material and normalized target. SHA256 is PostgreSQL17's built-in standard function, not pgcrypto or custom cryptography; see [binary string functions](https://www.postgresql.org/docs/17/functions-binarystring.html).

The display object has exactly `audit_schema,id,tenant,actor,decision,target,action,reason,request_id,source_ip,recorded_at,previous_state,current_state,previous_hash,request_hash,hash`. It has no other keys. Nested actor/decision/target retain the exact array positions above. `audit_schema` is JSON integer 1; **all other integer fields are canonical unsigned decimal strings**, preventing JSON number truncation. UUIDs are canonical lowercase hyphenated text; B32/B0 are exact lowercase hex; text remains the exact UTF-8 value; optional null stays JSON null. `hash` is the computed event hash. Reconstruct Event1 from every display field, reject an extra/missing/wrong-type/noncanonical field, encode it and require exact equality to stored CBOR. Product decoder/constraints must enforce the complete closed shape, including absent-versus-null and nonempty required fields; specimen mapping/recomputation is scoped to generated fixed-shape events and corruption cases, not a complete public decoder.

Store both validated JSONB and its exact PostgreSQL17 `jsonb::text` UTF-8 bytes; those bytes are immutable display output, not the audit hash preimage and not a cross-version canonical-JSON standard. Preserve them on reads/retries instead of roundtripping through Elixir. Qualified PostgreSQL upgrades must recheck generated display bytes against this vector. The [hand-authored vectors](../verification/hosted-atomic-storage-preflight/probe/golden-vectors.json) freeze a full Event1, initial state, actual transition, target, request hash, expected display object and exact display bytes independently of the SQL/Elixir encoders. Standard Python hashlib and OTP crypto verify the expected hashes. Width vectors include 0,23,24,255,256,65535,65536,2^32−1,2^32,2^64−1; `[1,null,B0,""]` is `8401f64060`.

Request hash version1 remains exactly `SHA256(ASCII("POST ") || ASCII(normalized_exact_route) || NUL || original_bounded_upload_bytes)`. No JSON reserialization. Tenant/principal/action/target comparisons are independent checks. The Go `Event` retains its original JSON field order, hash-empty preimage and unversioned plain SHA256; signed artifact/assignment v3 retains its original canonical encoding and signature domains. Separate executable preservation tests invoke the existing Go Event/protocol code and unchanged v3 vectors. Hosted CBOR is deliberately a different versioned stream.

These finite application bounds do not claim a total RSS, allocation, CPU, service-wide storage or network SLA. The codec premeasures before encoding; on-disk blob reads reject lstat size/type first and still read at most payload-max+1 to cover a growth race. Root directory enumeration is a trusted-owned-local-root assumption: `File.ls!` is not qualified against an adversarial unbounded directory. Mode0700 does not defend against malicious code under the same OS user. No external directory, remote bucket or shared multi-process root is accepted.

Local staging computes actual payload digest and uses immutable `sha256:<lowercase hex>` references with matching regular-file names. Exclusive create-if-absent never overwrites; an existing object is fully bounded-read, hash/size/byte compared. File data is synced and closed before the transaction; payload staging/verification and all filesystem I/O happen **before** authz locks. Reopen rechecks every object/count/quota; partial, oversized, symlink, unknown-name or hash-corrupt objects fail closed. A crashed partial immutable file is corruption requiring offline recovery; do not silently replace or treat it as success. The specimen proves process reopen and simulated interrupted create, not power-loss/directory-entry durability, multi-process coordination or a production filesystem contract.

A transaction failure may leave an unreferenced bounded object. Never remove a staged object in a transaction's exception path: COMMIT may be uncertain, or a different successful row may already reference the same digest. Collection runs outside transactions only after an authoritative complete reference scan and resolution of every uncertain operation. Any uncertain COMMIT freezes collection. After reconnect/restart, fresh identity/current authorization plus the original key/body must determine the committed outcome; preserve referenced bytes and return the original status/body/event if committed. Delete only proven orphan objects. The local fixture has no R2/production durability, distributed coordinator, retention automation or multi-host guarantee.

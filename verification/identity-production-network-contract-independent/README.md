## Minimal implementation clarifications

These are concrete requirements for the implementation candidate and its canonical contract, before execution selection. Root can resolve them as routine implementation choices. No additional user permission flow follows from this review.

1. **Make bootstrap capability explicit.** The packet freezes exact Hex 2.5.1 and Rebar 3.28.0 URLs and checksum rows, but its preparation prose does not name the downloader, checksum mechanism, installer argv, archive mechanism or exact installed Rebar executable path. Image config/history is not a filesystem inventory. Do not infer `curl`, `wget`, Python, `tar`, a checksum CLI or a usable `openssl` from those records. Select a finite command/literal plan and check every executable it actually uses in the owned remote image. A BEAM/Mix route is available for design: retained `mix-local-hex.ex` uses `Mix.Tasks.Archive.Install` with `--sha512`; retained `mix-local-rebar.ex` supports a local Rebar path with `--sha512 --force`. A reviewed BEAM download/hash helper can satisfy the contract's explicit local-path rule without assuming an extra downloader. If using a helper, hash its literal and bound TLS, redirects, response bytes, output and time. Ensure the final executable actually used equals `MIX_REBAR3=/workspace/tooling/rebar3`; do not assume a Mix local-install destination equals that path. This review does not claim any executable is absent. The existing rule remains: missing prerequisites fail; no install, derived image, alternate image or fallback is implicitly selected.

2. **Stage the prerequisite checks consistently.** `collector_controls.future_tests[0]` says to refuse a wrong tool before any container create. Actual in-image tool versions, OpenSSL capability and namespace facts cannot be observed before a container exists. Make the candidate require source/lock/static image/config/host architecture checks before create; actual image-local runtime/tool checks after create and before bootstrap/dependency work; actual test namespace/resource/capability and restored source/tool checks before passing `MIXER_ISOLATED_NETNS=1`. Controls must prove that ordering. Runtime preflight containers must be the already budgeted prepare/test/PG containers, not extra probes beyond the three-container limit.

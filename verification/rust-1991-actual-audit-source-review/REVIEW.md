# Source review of the prepared Rust 1.99.1 actual audit

Decision: **changes required before the prepared auditor is selected for the first actual artifact**. This is a source/data review only. The auditor, its guard, checked-in runner and replay were not executed or imported. No actual compiler result is accepted here.

Reviewed baseline: preparation seal SHA-256 `5302dd2551e58ce993004e4888b233df9a026bbb8f12e071d444e6dbc2bd9620`, auditor `c18b0490f92f4ead446c0a9ace1f4290aac404ddda7be4715600c9a9c6679adc`, guard `45b97a467e7e8bcd401c8bf90e2aa2495c1400a6c0408d98f16e7af306d5247a`. Findings below concern these original bytes.

1. **Bound the JSON/check-report expansion before rejecting unexpected members.** `audit_actual.py:50–53` retains a dictionary in global `CHECKS` for every `need()`. The duplicate-key hook at lines 78–91 calls it for every key in every parsed object; `unpack()` at lines 231–232 parses every archived JSON file before the final exact archive closure check at line 495. A bounded but unexpected 32 MiB JSON member containing an array of small objects can add millions of check dictionaries. The final `data-audit.json` write at lines 551–552 has no output bound. ZIP byte caps therefore do not provide a practical bound on audit working memory or output. Use bounded check counters/report storage, finite JSON key/node/depth or aggregate parse budgets, and reject unselected paths before reparsing. This is a static source finding; no large input was constructed or parsed.

2. **Validate original ZIP names before Python sanitizes or remaps them.** `unpack()` lines 203–210 validates `ZipInfo.filename` only. In the installed Python 3.14 library, `ZipInfo.__init__` stores `orig_filename`, then `_sanitize_filename` truncates at the first NUL. Unicode path extra field handling can also replace `filename`. `ZipFile.open()` compares the local raw name with `orig_filename`; matching local and central names with a NUL suffix are therefore not rejected merely because the auditor later reads the member. The auditor can treat that entry as an expected truncated path and pass its closure checks. Require the original and effective names to match exactly and validate the original spelling before uniqueness and closure checks. This is a source derivation from the installed standard library; no malformed archive or auditor was run.

3. **Complete the named active-API guard boundary.** `deny_runtime.py:53–85` replaces public `os` and `signal` attributes, while the import guard at lines 88–92 permits `posix` and `_signal`. The installed `os.py` copies exports from `posix`; `signal.py:57–58` delegates to `_signal.signal`. Underlying process/session/group/wait and signal/timer functions therefore remain directly available, with no matching audit-hook event in lines 27–29. Descriptor-relative `os.open(..., dir_fd=...)` also lacks a wrapper, while the `open` audit event does not supply that directory descriptor to this path check. The pinned pure facade/replay call graph does not use these routes, so this finding does not allege an active attempt. Patch or deny those underlying routes and descriptor-relative mutation before claiming they are blocked. This is a guard for selected source, not a general sandbox for hostile Python.

4. **Bind root's acquisition closure, or keep it an explicit external acceptance prerequisite.** The requested future strict root binding includes acquisition closure. The prepared schema and `binding()` have exactly four evidence references: delivery/run/job/artifact. The normalized artifact record binds id/run/revision/name/bytes/hash/expired, with no acquisition transport EOF, external-reader/lease closure or provider-disposal evidence reference. The README and result correctly disclaim those proofs, but the binding itself cannot enforce that root retained them. Add a required inert hash-bound acquisition/custody record, or require root's separate immutable acceptance contract to bind that exact record and describe source approval as data-only. No single ZIP can supply it.

The intended audit flow otherwise preserves the important boundary: guard installation precedes the two pinned checked-in subject imports; it never imports artifact code or the adoption adapter, and it never calls `load_runner()` or `select_compiler()`. Its fixed fingerprint facade compares recorded metadata rather than recreating the adapter's private resolver observation. The unchanged replay requires the full ordered 40 commands, exact terminal status, successful capture/custody rows and source snapshots. Explicit additional checks retain the complete 1.99.1 identity/SHA, seven adapter snapshots, source/job/selection equality, 78 producer methods in 18 groups, 14 independent methods, 32 layouts, 16,170 plus 5,544 counters, API one/eight coverage, 92 retained payloads, four product records, eight postflights, cleanup, warning flags and original budgets. Compiler-product hashes are recorded identities; removed binaries cannot be rehashed independently.

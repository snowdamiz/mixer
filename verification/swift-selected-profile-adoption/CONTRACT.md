# Private selected-profile adoption

This candidate implements the exact private adoption slice selected in
`selection.json`. `CONTRACT-PROPOSAL.md` is the historical preparation proposal.
The final distribution is `source/vm`; discovery sources, compiler variants and
failed attempts are evidence and are not alternative accepted implementations.
Independent review and root scoped acceptance remain separate decisions.

The binding product scope remains `mixer-product-plan.md`. This packet does not
provide canonical integration, operational loader-storage admission, export or
context joins, package authentication, native qualification, FieldLog release,
OTA, store, customer, operations or GA acceptance.

## Authentic ownership

The original public `ValidatedSwiftReactor` API and layout are unchanged. The
private loader owns the only selected carrier. Its complete validator, exact
source-byte comparison and final metadata check produce the non-Clone
`SelectedValidatedProfileV1`. Only consuming that carrier can create a body with
`Some(full_original_LoaderProvenanceV1)`. The provenance retains all five actual
validation limits, original source extent/digest, manifest/build/session/current
executable commitments, launcher nonce and all four complete File identities.

`AdoptionBodyV1` has private proof and optional provenance fields. Its ordinary
constructor accepts only the original proof and creates `None`. It exposes only
borrowed proof and borrowed optional provenance tied to the actual owner's
lifetime. `LoaderProvenanceV1` has a parent-visible nominal type and entirely
private fields. Neither type has Clone, owned proof/provenance extraction,
serialization, a parts API, arbitrary pair construction, digest minting or
boolean minting. The field-by-field496-byte encoding exists only under
`#[cfg(test)]`; no parser or authority constructor consumes it.

The existing `RuntimeControl::adopt` signature is unchanged. It immediately
wraps the ordinary proof and delegates into `adopt_body`. The carrier-consuming
method delegates into that same `adopt_body`. This is the one original ledger:
the original budget checks, deadline, cancellation, owner allocation, source,
metadata, control, cancellation-backing and foundation admission order remains.
The authentic `AdoptedProof` owns the body and both original proof tickets and
moves through the original cache prepare/construct/complete and failure paths.

Admission refusal destroys the body, proof and inline provenance before source
and metadata ticket refunds and the original consuming control cleanup. Final
proof cleanup destroys the body before independently evaluating both refund
attempts, then retains the original `source_result.and(metadata_result)` return
behavior. Original typed failures, first cause, snapshots, real returned owners
and deliberately quarantined charges remain distinct from healthy zero.

## Actual storage and initial guard

The retained full provenance is inline. Actual production/unit layouts include
body1168, optional provenance504, adopted1216 (previous712), original proof664,
and the complete initial roster of201 records. The original165 IDs and type
identities remain in order; appended IDs166..201 name the original23 loader
classes and13 actual body, borrow, entry, move, result, pair, optional owner,
final recheck, cleanup and test-encoding classes. Private loader types are
measured where defined, without exposing their fields or constructors.

Four pre-migration configurations were measured before literals were promoted:
Debug and optimized unit, plus Debug and optimized production host. Ordinary
production metadata probes independently assert all201 sizes/alignments and
the resulting envelopes with no unit or host configuration. Literal migration
and retained discovery inputs are in `layouts/` and `source-preimages/`.

Foundation retains explicit adoption entry, result/move and destruction/refund
places plus all original initial-profile wrapper ingress/output/move groups
before dependent preparation. Existing execution bootstrap inventories continue
to measure their actual embedded owners. Cache header accounting still
subtracts only original `ValidatedSwiftReactor`, leaving all inline sidecar
bytes charged in the cache remainder. Cache cleanup, construction, operation,
initial wrapper, final and returned-failure owners use their actual full types.
These are conservative source-object/requested-storage envelopes, not physical
stack, RSS, allocator overhead or an OS syscall-time bound.

All original ceilings remain: source64MiB, metadata16MiB, cache16MiB,
entry8MiB,64 slots/pins, cache work64000000, combined256MiB and all original
state/fuel/work/deadline limits. The old300000 combined grant now honestly
refuses at adoption because the larger foundation cannot fit; a separate
explicit400000 grant retains preparation-refusal coverage. Neither is a raised
production cap. No loader allocation or File storage gains operational admission
merely because a conservative numeric union fits.

All eight original initial-profile constructor outcomes and the sole original
fresh guard remain. The selected tests compare every original provenance field
on the real returned adopted owner, rejected adopted owner or caller cache, and
assert original prepare/construct/complete/guard chronology. No snapshot,
exporter or real-context route is added by this slice.

## R1 and external custody

Final metadata rechecks now pair Source, Build, Session and Executable with their
actual respective File. Metadata mismatches keep the original identity-array
offset0..3. Typed metadata I/O errors keep their original role, offset and error
payload. Actual safe-File mismatch tests exercise all four roles and retain all
four owners. Separately labeled helper tests inject synthetic I/O errors for
all four roles; these are not claimed as real failing metadata syscalls or full
loader-entry failures. No borrowed descriptor is unsafely closed for testing.

The loader's returned Files remain independently owned on all outcomes.
Rust File drop, process exit, descriptor reuse and owned-name removal do not
prove close success and do not authorize a runtime refund. The trusted runner
terminally waits only its own direct children and removes only owned scratch.

Trust remains a trusted launcher/compiler and quiescent local macOS host.
Correlation is not signed package/toolchain origin, hostile-parent protection,
concurrent mutation protection, mapped-image pathname integrity or replay policy.
Raw cwd/executable pathname and raw argv0 limits remain explicitly unrun in this
packet. Native, simulator, emulator, UI, capture and process inventory are paused.

The original `external_surface_and_borrow_privacy` wrapper remains unrun because
it launches nested unbounded Cargo/compiler commands. Its exact13 compiler
sources and diagnostic classes are reproduced by separately bounded commands;
the mapping is in `public-compiler-source-mapping.json`. Ordinary cache borrow
behavior is separately covered by the direct cache suite. This reproduction is
not called a pass of the original wrapper.

# Browser preauthentication storage composition

This bounded component implements the first real preauthentication database and
Vault roundtrip from the [runtime contract](hosted-browser-lifecycle-runtime-contract.md).
The selected producer run passes 23 executable PostgreSQL 17 methods. Independent
review and root acceptance remain pending. Root owns metadata and delivery. No
Application child, route, provider, active authentication, production migration
or native test is enabled.

## Fixed private interfaces

`RuntimeOwner.start_link(runtime_config)` manually starts the registered owner.
`status/0` exposes only phase and generation; `storage_ready` is internal storage
admission, never browser authentication readiness. `bootstrap(metadata)` and
`load(raw_cookie)` are the fixed preauthentication orchestration operations.
Metadata is exactly `%{request_id: hex32}` with a lower-case hexadecimal 32-byte
ID generated by trusted server code. No Repo, clock, verifier, provider,
destination or callback is accepted.

Success is `{:ok, %PreauthDraft.Preauth{cookie, csrf, expires_at, source}}`; load
absence is `{:ok, nil}`. Source is the committed StoredSnapshot. The whole result
is private and Inspect-redacted, never an authenticated session, facade response
or HTTP serialization contract. `Store.bootstrap(%PreauthDraft.Bootstrap{},
metadata)` and `Store.load(%PreauthDraft.Load{})` return committed decoded
snapshots only. `Store.admit(runtime_config, original_deadline)` is one fixed
startup operation requiring the actual registered RuntimeOwner as caller. There
is no exported executor or operation callback.

Failures are private `{:error, %Store.Failure{code: :session_unavailable, phase:
phase, outcome: outcome}}`. Phase is admission/effect/decode/commit; outcome is
not_started/rolled_back/committed/unknown. No exception, stack, SQL, key, cipher,
token, identity or endpoint is retained. A known committed result can be withheld.

The closed redacted Lease has owner, reference, caller, generation, deadline,
started_at and runtime. Bootstrap has lease, context, sealed, cookie, csrf and
expires_at. Load has lease and cookie_digest. These trusted application types are
not a sandbox against hostile BEAM code. The fixed internal owner messages are
`{:reserve, original_monotonic_deadline_ms, original_wall_seconds}`,
`{:checkpoint, lease}`, `{:finish, lease, expires_at_or_nil}`,
`{:failed, lease, {:error, failure}}`, and release cast
`{:release, actual_caller_pid, reference}`. Reservation retains the exact Lease
for the actual GenServer caller; copied maps, foreign callers, reused references
and changed owner/generation fail. None is an HTTP/request API.

## Ownership and publication

The owner monitors fixed LifecycleRepo, default registered KeyOwner and ordinary
Repo PIDs. LifecycleRepo validates a closed startup option set and forces logging
off. Its actual supervisor owns a protected ETS table containing only a
fingerprint of the connection/pool options used at startup. `bound?/1` checks
that fingerprint and registered supervisor ownership. No password/key bytes are
stored in this table. This avoids Ecto Repo.config/0, which re-reads Application
settings rather than attesting the options used by the running pool.

Both current catalogs pass before storage_ready. Every Store operation owns
fixed LifecycleRepo and one original five-second monotonic deadline through
checkout, admission, SQL, decoding and COMMIT. Catalog.check_function_surface!/4
with fixed integer version 2 and RelationCatalog.check_relation_surface!/3 must
both succeed in that same owned READ COMMITTED transaction. Partial results do
not establish readiness. Checkout/queries fix queue:false, no retry, remaining
positive timeout and DBConnection's original absolute deadline. LOCAL statement
and idle limits are exactly 5s, lock timeout 500ms, JIT off, search_path
pg_catalog and bytea hex. Existing lifecycle/ordinary transactions, changed
dynamic Repos or ordinary authorization context deny.

At most 32 caller-monitored operations are admitted without an operation waiting
queue, separately from the fixed two-connection pool. Slots close on success,
failure or caller death. An expiring in-flight lease conservatively clears
readiness and advances generation because COMMIT acknowledgement may be
outstanding. Unknown results and current catalog drift also clear readiness.
This manual component requires owner restart and fresh admission; shared live
supervision/re-admission is not wired. Fresh wall samples cannot move backward
within a lease. Expiry equality denies. No clock is injected.

Bootstrap fixes randomness, exact preauthentication Vault AAD and cipher before
its transaction. Decoded results match every prepared context/counter/deadline
and sealed field; SQL-owned fresh timestamps and audit sequence are checked.
Encrypted load commits before Vault open. Loaded active snapshots fail closed.
Decrypted CSRF, current configuration, cookie digest, caller and owner generation
must still match before private release. Failed/uncertain results never
reconstruct a cookie. Known PostgreSQL ERROR class 23/40 or ERROR 57014/P0001
rejecting COMMIT can prove rollback. FATAL/PANIC (including administrator shutdown)
and driver/connection loss remain unknown. Confirmed COMMIT followed by owner
loss reports committed while withholding every private result. No replay occurs.

Sensitive Store calls additionally fix telemetry_event:nil: pinned Ecto SQL
emits parameters/results before checking log:false. The executable telemetry
control sees catalog events and no sensitive bootstrap/load event. Actual owner
status formatting redacts retained state, messages, logs and reasons. Pinned
Ecto Repo initialization still emits full startup options to trusted internal
BEAM telemetry observers; this component does not patch that dependency or claim
protection from hostile trusted observers. Application logs/errors/receipts must
not contain secret values.

## Executed evidence and limits

Run `python3 verification/hosted-browser-preauth-store/run.py`. It compiles only
the selected accepted ordinary source closure and new files using pinned
BEAM dependencies and actual projectless Mix formatting. One owned PostgreSQL
17 fixture installs the ten selected migrations locally and provisions synthetic
restricted lifecycle/ordinary roles. The actual accepted default KeyOwner starts
with no verifier or fetch call. Product source is not rewritten; no fault hook
is added to it. Commands, versions, revision, source/dependency hashes, output and
cleanup are saved for successful and failed attempts.

The 23 named methods cover real bootstrap/load; actual pool option binding and
two-slot no-queue pressure; foreign transactions/context; owner-only cap32,
caller death, one-use/foreign/copied leases; original deadline continuity and
equality; real browser row-lock timeout and settings restoration on rollback and
commit; AEAD rejection of synthetic owner-corrupted stored bytes; independent
partial catalog successes hiding neither current counterpart drift; deferred
COMMIT rejection; backend termination/unknown result; actual deferred COMMIT wait
bounded by the original deadline; committed bootstrap withholding after default
owner loss; and status/SQL telemetry redaction. Counts include compound
assertions, not complete lifecycle or launch coverage.

Capacity controls use fixed internal reservation messages from real processes;
they prove owner capacity, not 32 simultaneous SQL operations. BEAM tracing
observes unchanged candidate return checkpoints and suspends an owned request.
Synthetic operator DDL after admission adds temporary rejecting/sleeping deferred
triggers. Synthetic owner corruption bypasses then restores an exact trigger
before admission. These exercise error/crypto handling outside the malicious
owner boundary, not catalog stability against coherent operator DDL. No traced
secret arguments/results are logged or serialized.

The fixture deliberately assembles a trusted RuntimeConfig for localhost, random
port and ssl:false. It does not pass/qualify RuntimeConfig.new/4 production
direct-host/TLS/5432 rules. Default KeyOwner and Config use the same synthetic
manifest, but no active identity is verified. Shared live Application startup
provenance, deployed Neon/TLS and external custody-source qualification remain
pending; ordinary Repo configuration observation cannot prove that provenance.

Remaining runtime cases include the full immutable 40-case owner and 18-case
lifecycle matrices, independent valid durable active-snapshot rejection, all
per-field source/AEAD mutation controls, definitive response loss after successful
COMMIT acknowledgement, provider/OIDC/current access verifier, begin/claim/
activation/logout owners, browser HTTP/console, cross-replica operations and
operational recovery. Device/customer/immutable FieldLog/GA evidence is pending.
Native/UI/capture execution remains paused. Frozen catalog-inspector,
authority-driver and rejected Worker V2 sources are excluded. Failed receipts
and cleanup evidence are preserved.

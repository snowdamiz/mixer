# Planning policy review

Scope: documentation and execution policy only. No VM/compiler/native/UI/capture
experiment, process inventory, production change or gate acceptance was performed.

Two fresh-context agents used the user-requested `gpt-6-astra` model with `xhigh`
reasoning and bounded read-only ownership:

- `/root/budget_policy_review`: empirical VM budgets, the finite comparison matrix,
  coupled accounting, baseline identity and acceptance classifications.
- `/root/blocker_policy_review`: escalation triggers, stronger-agent dispatch,
  vertical-slice priority, review termination and full-scope/hold preservation.

Their initial recommendations informed the draft; both separately reviewed the
edited plan, ADR, instructions and machine-readable policy. They found no required
relaxation of security or existing native/custody holds. Root resolved the concrete
consistency findings:

1. Updated the decision register and remaining coordinator wording, retaining
   user control of the main model and explicit Sol/Astra role selection.
2. Allowed finite baseline reproduction, independent reproduction and variance
   measurements within campaign bounds; prohibited purposeless repeated failures.
3. Required a candidate 64/64M control when parameterization/instrumentation changes
   comparability, while preserving the historical failure separately.
4. Required correct observations, no invariant failure and consuming cleanup for
   host feasibility; one-shot timing remains an observation rather than a speedup.
5. Distinguished resident capacity from active pins and required all coupled
   ticket/index/storage changes to stay accounted within retained byte ceilings.

The executable `validate.py` records final structural checks, the repository's
manifest/acceptance guardrail, command outputs, source hashes and actual scope.
The reviews and validation accept a planning change only. The matrix is planned;
all original implementation, environment, product and GA evidence remains required.

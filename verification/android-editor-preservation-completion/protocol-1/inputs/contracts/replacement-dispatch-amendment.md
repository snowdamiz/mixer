# Replacement dispatch exclusion

This additive implementation refinement preserves the committed replacement
amendment (`b386f832479884f2487df114fb080f14ebac99c747208bffd0428477c32d844b`).
It grants no additional native or Mutation authority.

Select scalar `Input.editorDispatchAvailable(record)` for renderer-wide new-entry
exclusion while any replacement reservation exists. New ordinary adapter,
creator, widget and replacement entries check it before native live getters.
False is a clean no-call refusal that preserves existing healthy connections;
it does not by itself terminally retire a field. The scalar is neither readiness
nor a target or callback lease.

Already-entered exact replacement, predecessor cleanup and lifecycle scopes keep
only their captured continuation. Their required native suffix is not blocked by
the new-entry guard. Actual foreign lifecycle loss still records denial while
new input is excluded. The selected exact own-predecessor close exception and
ordinary native-depth, operation and commit barriers remain unchanged. No foreign
attempt receives close authority. `getHandler` remains constant null on any
thread with no state access. No owner/core/coordinator edit is selected.

Require complete-source foreign-field adapter/widget/creator/second-replacement
controls that prove refusal before native getters, exact own predecessor close,
loss-latch persistence and fresh later ordinary entry. General native/runtime,
public V2 and GA qualification remain pending.

# Selected field preservation and loss observation protocol

This refines the selected focus-history amendment
`736476a269fae9a6745fbfbd5413a7ef231f57f9254c3279e41c2921d2088833`.
It coordinates private interfaces before dependent implementation. Prior
connection, cleanup, replacement, descriptor and native qualification limits
remain binding.

Select these internal Input signatures:

```java
long editorLossObservation();
void editorLossObserved(Record record);
void fieldPreservationBegin(Record record, FieldPreservation preservation);
void fieldPreservationEnd(Record record, FieldPreservation preservation);
void replacementEvent(Record record, Replacement replacement);
```

The renderer owns a monotonically increasing, checked long loss observation.
Every actual authored lifecycle loss is observed, even an already-latched loss.
Capture the observation before callable replacement admission facts and payload
reads; compare after callable getter bundles and at each stage boundary. Any new
own or foreign loss invalidates that replacement's success. Gain does not erase
an observation. Exhaustion is terminal and never wraps; equality at MAX cannot
authorize success after exhaustion. Observe failure/fatal without dropping the
exact already-entered superclass suffix or fabricating native completion.

Loss observation is scalar bookkeeping, not authority. Perform it while an exact
standalone lifecycle lease or already-entered replacement/field suffix owns the
callback, before the loss denial/revocation and native super. Preserve initial
record-null bootstrap. Genuine initial construction retains its existing strict
scope; post-construction binding must not hide lifecycle observations behind a
construction/changing shortcut. Appropriate original Record/View/fence custody
must be checked; no caller can use this interface to mint a native scope.

Select a separate exact FieldPreservation scope for a previously blurred,
settled retained field. It carries the original current TRANSACTION Mutation,
exact Record/View/Editable, old and selected compatible Binding identities,
unchanged text/selection/composition snapshot, settled attempt identity and
RETURNED/NO_TARGET scalar disposition, and the captured loss observation.
It carries no InputConnection target or EditorLease. An absent predecessor is
also admissible under the same original field facts. Availability remains a
refusal probe and does not create this scope.

Only the renderer's exact candidate/journal attach path may begin this scope,
after actual compatible-binding and native-journal validation. It applies only
to the inactive field needing preservation, never to another field's active
editor continuation. A focused B's already-entered EditorLease may coexist while
settled A has field preservation; their ownership identities remain separate.
Reject any existing editor lease on A, unresolved predecessor, replacement,
creator, drain, quarantine, incompatible update or invalid original transaction.

The Record retains the exact preservation scope through compatible bind,
parent/hierarchy work, measurement/layout and any eligible attach failure
restoration. Its callback Mutation cannot authorize bind/layout: requireMutation
must refuse it. Those operations use the separately captured original
transaction. Every native field callback must check the exact scope and
unchanged native snapshot. New loss invalidates success; only a matching
already-entered native/lifecycle suffix retains its narrow captured continuation.
It grants no new entry, target operation or arbitrary callback after invalidation.

Restoration uses only an already-captured, still-current original transaction
and its exact candidate/journal scope. No new scope may be minted during restore
or rollback; no successor or general CLEANUP conversion is allowed. The journal
must remember the forward compatible-preservation disposition: the existing
NativeState.active flag is insufficient for blurred A. Eligible restoration
preserves the same Editable/text/selection/composition and restores only the
exact old Binding/geometry through the selected preserve path. Invalid mutation,
loss or snapshot authority makes restoration fail honestly.

Begin/end use exact counted scope custody in the existing outstanding-native
busy count. Do not infer that this count must be globally zero when beginning A
while B's legitimate editor callback remains active. Validate bounded count and
scope identity before increment/decrement. After applicable native work, eligible
restoration and reporting, remove callback authority, mark ended, validate no
outstanding hooks/callbacks, and release the matching count last. Imbalance retains
busy custody and terminal/fatal information; never reset a shared counter or
resume the owner synchronously after clearing. An ordinary abort can release only
its exact counted identity without native getters after reporting.

For replacementEvent, pass the exact completed Replacement, not loose scalar
arguments. It owns immutable captured eventValue, original Mutation and loss
observation plus a once-only delivery claim. After native/final validation and
reservation release, require exact DONE/endReady/completed provenance and fresh
field eligibility under settled focus history. Recheck Record/View/retention,
original current authority, observation and eligibility after callable open
getters. Claim delivery before ordinary scalar interaction and synchronous event
send. Do not bypass checks by reviving the old attempt or broadening generic
eventsAllowed. Failure before send after completed native mutation is uncertainty,
never successful replacement. After send only the existing scalar original-result
rule remains: no native getter, second event or successor scope.

No owner/core/coordinator changes, new asynchronous work, SDK admission changes
or native qualification are selected. The new complete-source tests must exercise
both failed ordinary sequences, eligible and refused restore, multiple fields,
existing B lease coexistence, exact count/fatal cleanup, repeated loss/gain and
exhaustion, alongside the prior selected controls. Independent implementation
review remains required before canonical promotion.

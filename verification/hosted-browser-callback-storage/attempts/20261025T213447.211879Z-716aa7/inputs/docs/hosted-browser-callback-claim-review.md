The SQL source confirms that load projects a current pending attempt without
filtering that attempt's expiry, and hides claimed or terminal attempts. Callback
discovery therefore independently requires a live, non-null pending PREAUTH
attempt and exact cookie/state/configuration/profile/provider/context binding.
Begin's permission to replace an expired pending attempt cannot authorize a
callback. Ordinary preauth load remains narrower. Valid active browsers must be
tested as actual durable states and remain unavailable in Unit A.

Claim and provider rejection advance audit_sequence without advancing browser
revision. Revision CAS alone misses that race. The contract now requires fixed
load followed by whole StoredSnapshot equality under its held browser SHARE lock
in the mutating transaction, then unchanged claim/reject SQL. A SHARE upgrade
loser rolls back without replay. The output must equal the entire source browser
with only audit_sequence +1, retain the entire session envelope/context/cipher,
and match every attempt field except the declared transition. Claim additionally
checks the independent raw32-secret digest, bounded SQL claimed_at, exact fixed
claim expiry, null completion and erased cipher. Rejection checks its fixed
terminal reason and null claim fields. Neither comparison confuses canonical
PostgreSQL hex attempt members with decoded envelope bytes.

Discovery must commit before Vault opening. Both code and provider-error paths
authenticate the exact preauth session outside the mutation transaction and
require canonical recovered CSRF whose SHA-256 equals the browser digest. The
code path additionally opens the exact pending verifier and retains PKCE/nonce
evidence before claim SQL erases the ciphertext. Provider rejection needs no
verifier opening, claim secret or child. SQL signatures, catalog expectations,+migrations and grants need no proposed change for Unit A.

The original five-second operation budget spans parsing, both transactions,
cryptography and publication. Claim expiry is fixed from original entry, capped
by entry +60 seconds and all saved browser/attempt deadlines; the separate local
claim lifetime also begins at that original monotonic sample. Waits, process
startup, transfer or later failure calls cannot extend it. Equality and backward
wall time deny. Store retains actual-caller checkpoints, foreign/nested transaction
rejection, fixed pool two, queue:false and remaining absolute deadlines.

The source exposed a failure-report ownership gap in the first proposal:
Store.transact returns Failure, while RuntimeOwner's existing closed failed
message performs readiness invalidation. The revised contract makes each new
fixed A operation report an authorized failure synchronously through that
retained owner within the original deadline. Only its acknowledgment supports a
completed invalidation/release assertion. Missing acknowledgment stays unavailable
with no readiness assertion or retry; existing expiry/monitor cleanup is the
explicit bound. Unknown COMMIT never publishes a snapshot, Claim or provider
exchange. A known committed result may still be withheld, without a rollback
claim. Unit A's selected caller must test both acknowledgment and deadline cleanup.

Unit B's proposed combined cap includes operations, staged children, retained
claims and terminal cleanup. It transfers the original counted slot after known
claim COMMIT instead of releasing and reserving again. Its fixed supervisor,
helper, child, bootstrap reference, parent links, caller monitor and private timer
tokens must be checked by actual process identity. Dormant startup monitors its
retained owner and actual supervisor; reservation already monitors the original
caller, and authenticated installation adds the child's original-caller monitor.
Late startup cannot install or arm after slot/deadline loss. Cleanup must confirm
exact owned parent/child membership and preserve foreign/replacement processes.
Actual trap_exit/parent-loss/late-start behavior remains a required runtime test.

Supervisor child specifications must contain no private record/configuration or
code/PKCE/key material. The revised contract explicitly requires OTP format_status,
termination, abnormal-exit, helper and supervisor report redaction, beyond struct
Inspect, with actual crash/sys-status controls. Untrappable kill cannot rely on
terminate running. These are Unit B implementation requirements, not behavior
proved by this review or the Python models.

The original caller alone can consume the exact handle. Local use becomes
terminal before one explicit :session_failed SQL attempt; a distinct retained
cleanup lease keeps the slot counted and cannot authorize ordinary operations.
The helper returns boolean true, so confirmed COMMIT proves that transition but
provides no independently compared post-state/audit snapshot. Timers, crashes and
publication failure retire local custody without automatic failure SQL. An erased
verifier and unknown raw claim secret cannot be reconstructed from later load.
Same-PID KeyOwner trust changes remain an explicit limit; later activation still
needs the real current default verifier and its finish checks. The private final
publication sample is not atomic with later scheduling or external delivery.

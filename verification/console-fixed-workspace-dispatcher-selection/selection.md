# Fixed private workspace dispatcher selection

Status: source selection only, 2026-10-27. The proposed API below is closed for
root selection. It is not implemented, compiled, tested or independently accepted
by this packet. W14 and G22 remain incomplete. Root owns product assignment,
status/graph/gate changes and delivery.

## Decision and usefulness

Select a private, same-process `MixerHostedWeb.BrowserWorkspaceDispatcher` that
joins the existing bearer plug and workspace controller through an in-memory
capture adapter. It can be implemented without callback Unit A, ClaimOwner,
active-session storage, Sessions, a provider, cookie routes or startup changes.
It makes the required fixed application join concrete and testable without
claiming that any caller possesses an authenticated browser session.

This is independently useful as a backend component: it fixes the exact
token-to-ordinary-workspace dispatch and response-confinement boundary that a
future `Sessions.workspace/3` must invoke. There is no production caller selected
here. A synthetic token or a successful component test cannot enable a browser
route, bootstrap authenticated state or qualify a customer workflow.

The binding W14 scope remains onboarding, permissions, SSO, commercial workflows
and the complete public UX/API; this component closes none of those acceptance
gates. The prior frontend packet explicitly selected this dispatcher as a
possible independent prerequisite and required the existing ordinary defaults.

## Exact local contract

```elixir
MixerHostedWeb.BrowserWorkspaceDispatcher.dispatch(
  server_held_access_token,
  {:organizations, %{limit: 50, cursor: nil}},
  %{request_id: "0123456789abcdef0123456789abcdef"}
)

# The only other operation:
{:projects, exact_organization_id, %{limit: 50, cursor: nil}}

# A completed ordinary pipeline outcome, including ordinary denials/outages:
{:ok, %{status: integer, headers: [{lowercase_name, value}], body: json_binary}}

# No valid complete pipeline outcome was obtained:
{:error, :invalid_request | :authorization_unavailable}
```

`{:ok, response}` describes a captured response, never authenticated-session
readiness. Only `status == 200` describes that one committed, currently authorized
workspace page. The dispatcher returns no session, stored identity, permission
capability, private connection or reusable authorization ticket.

The three arguments are mandatory. There is no options argument or configurable
dispatcher, verifier, provider, facade, repository, clock, HTTP client, destination,
method, header map or caller-supplied connection. Server-held means the future
trusted caller obtained the token from the accepted active-session lifecycle;
this API itself cannot establish that provenance. A same-VM module is not an
isolation boundary against malicious trusted BEAM code.

Input admission is exact:

* Token: raw binary, 1..4,089 bytes, before constructing the internal header.
  No scheme, Cookie, ID token wrapper or identity struct is accepted. Do not
  implement another bearer grammar or JWT parser: the canonical `BearerIdentity`
  plug alone decides lexical/token admission and current verification. A bounded
  binary that violates that grammar receives its existing fixed 400 response;
  a syntactically admissible but invalid token receives its existing 401 response.
* Page: plain atom-key map with exactly `:limit` and `:cursor`, integer limit
  1..100; cursor nil or the existing canonical bounded cursor. Validate by calling
  `CustomerWorkspace.Input.page/3` with `"organizations"`/nil or `"projects"`/the
  exact organization. Discard its decoded `after` result: serialization carries
  the original admitted cursor, and the ordinary transport/domain checks run
  again. Do not accept an `after`, string-key map, struct, extra key or operation.
* Organization: the existing `Authorization.Scope.identifier?/1` predicate,
  preserving exact bytes. Do not trim, normalize or turn it into a path segment.
* Metadata: plain atom-key map with exactly `:request_id`; exactly 32 lowercase
  ASCII hexadecimal characters, freshly generated by the trusted server caller.
  Shape validation does not prove randomness or provenance. Do not copy an outer
  request header or generate a replacement inside the dispatcher.

Invalid shape returns only `{:error, :invalid_request}` before invoking identity
or storage. It never echoes the invalid value or a dependency exception. The
future HTTP layer owns rendering this local failure into its fixed error contract.

## Fixed composition and ordinary authority

1. A pure request codec validates the typed operation and emits exactly
   `%{operation: :organizations | :projects, path: fixed_path, query: binary}`.
   Its API is `BrowserWorkspaceDispatcher.Request.new(workspace_request) ->
   {:ok, request_map} | {:error, :invalid_request}`; it accepts no other argument
   and never receives a token, identity, Repo or server metadata.
   The paths are `/v3/orgs` and `/v3/projects`. Query order is organization_id
   when applicable, limit, cursor when non-nil; keys are fixed, limit is canonical
   decimal, each exact string value uses `URI.encode_www_form/1` once. Assert the
   final query is at most 8,192 bytes. No raw query is an input.
2. Refuse a preselected dynamic repository unless
   `MixerHosted.Repo.get_dynamic_repo() === MixerHosted.Repo`. Recheck equality
   after the call before returning. Never call `put_dynamic_repo/1` to repair,
   reset or silently replace caller state. The default Repo module alone is not
   enough: Ecto's `get_dynamic_repo/0` consults the current process dictionary.
3. Construct a fresh `%Plug.Conn{}` with the owned capture adapter, `owner: nil`,
   fixed `method: "GET"`, the selected fixed path/path_info and encoded query,
   `req_headers: [{"authorization", "Bearer " <> token}]`, and only the admitted
   `x-request-id` response header. Assigns/private/params/cookies start empty or
   unfetched. There is no copied outer conn, body, cookie, inbound correlation
   header or network URI. No Endpoint, Router, Plug.Test, HTTP transport or socket
   is involved. The capture adapter reads exactly an empty internal request body.
4. Call `BearerIdentity.call(conn, BearerIdentity.init([]))`. If halted, project
   that response. Otherwise call `CustomerWorkspaceController.call/2` with
   `CustomerWorkspaceController.init(operation)` using its **atom** init clause.
   The controller itself runs `CustomerWorkspaceRequest`. Never use the
   controller's injectable list init clause in the dispatcher.
5. The fixed defaults remain `ConfiguredVerifier.authenticate/2`, the registered
   default identity owner and actual Unix clock; `CustomerWorkspace`; and the
   ordinary `MixerHosted.Repo`. The dispatcher receives no stored identity and
   cannot construct one as a shortcut. Every call obtains current token evidence,
   then the existing human/scope admission and ordinary current database checks.
6. Return only the bounded response projection. Discard the local conn and all
   its assigns, private values, adapter state and authorization header. Do not
   return a function, process ID, request representation or identity alongside it.

Canonical Storage owns its transaction, refuses an active Storage/Context or
Repo transaction, checks caller PID and dynamic Repo/connection binding, takes
ordinary identity/tenant/membership locks, uses READ COMMITTED/RLS, rereads current
profile/binding/principal/family/credential and membership evidence, validates
expiry/deadline and checks commit outcome before returning a page. Descriptive
roles in the page remain descriptive. The dispatcher changes none of this.

The join must execute in the **same caller process**. Preserve its process
dictionary, ordinary dynamic Repo and transaction context, and let the canonical
Storage guards refuse nested authorization. No worker, Task, supervisor,
callback, admission pool, temporary repo selection or context clearing is needed.
Moving to a fresh worker would erase the very context the guards examine and
would require additional caller guards and lifecycle design; it is excluded.
The future Sessions caller must finish all lifecycle transactions before entering
this join. This packet does not prove or implement that missing lifecycle fence.

## Capture and safe projection

`CaptureAdapter` is a Mixer-owned local collector, not a webserver. The installed
Plug 1.20.3 implementation of `Plug.Conn.send_resp/1` invokes the adapter then
sends `{:plug_conn, :sent}` only when `conn.owner` is non-nil. Keep owner nil.
The adapter returns its captured body/state directly and sends no mailbox
notification or network response. The Adapter documentation's standard sent
notification is guidance for webservers; this local adapter never attaches to
Endpoint and must not pretend an outer response was already sent. A host test
must prove an existing caller mailbox is unchanged, including a preexisting
`{:plug_conn, :sent}` marker. No flush/drain of caller messages is permitted.

The initial adapter state contains only a zero send count. `read_req_body/2`
returns `{:ok, "", state}`. `send_resp/4` accepts exactly one finite response,
checks iodata length before materialization, captures status/headers/body, and
returns the captured binary through the adapter tuple. Maximum body is 262,144
bytes. A second send or file/chunk/upgrade/inform/push operation fails closed
with a fixed reason; none opens a file or performs I/O. Unused mandatory peer/
protocol callbacks cannot expose a caller-selected transport. A local protocol
atom is not a real HTTP receipt.

`BrowserWorkspaceDispatcher.CaptureAdapter.new/0` constructs that internal adapter
tuple; all other exported functions are only the required adapter callbacks.
Projection stays private inside the dispatcher and cannot be supplied a conn by
a dispatcher caller.

Projection requires one completed capture, `conn.state == :sent`, matching
captured/conn status and body, no response cookies, and unchanged default dynamic
Repo. Allowed statuses are exactly 200, 400, 401, 403, 404, 415 and 503, preserving
the existing controller/plug error repertoire. The only headers are:

* Exactly one `cache-control: no-store`.
* Exactly one `content-type: application/json; charset=utf-8`.
* Exactly one `x-request-id` equal to the server input.
* Optional single `www-authenticate`, only the canonical Bearer challenge values
  (`Bearer`, `Bearer error="invalid_token"`, `Bearer error="invalid_request"`),
  never on 200, 403, 404, 415 or 503. A 401 requires its challenge.
* Exactly one `retry-after: 1` on 503, absent otherwise.

Reject unknown/duplicate headers, any Set-Cookie/Location/authentication-info,
cookie response state, non-binary/oversized body, unsupported status, missing or
mismatched capture, or unexpected response mode as `authorization_unavailable`.
Return headers in the fixed order above, omitting the optional challenge.
The body is the exact existing encoded representation; do not decode/reencode,
invent another row validator or replace an ordinary error with provider text.
The controller already validates successful page keys, row bounds, ordering,
roles and cursor. In particular `Identity.BoundedJSON.object/2` is **unsuitable
as a second page decoder**: it rejects arrays over 64, whereas a legitimate
workspace page permits 100 rows. The body cap is a projection/resource bound,
not another source of authorization.

No credential, identity, token header or caught error is returned, logged,
inspected, broadcast, persisted or included in telemetry by this component.
Only canonical authorized page data and fixed ordinary error bodies cross this
local boundary. The explicit token parameter stays transient in local variables
and the private request conn; this is not a claim of BEAM memory zeroization.
No arbitrary caught term, stack, SQLSTATE, provider response or `Exception.message`
is retained. `rescue`/`catch` return the fixed local unavailable atom. Uncatchable
process death remains process death, as in the existing ordinary HTTP pipeline.

There is no new retry or asynchronous timeout layer. The current identity owner
and ordinary storage keep their own existing bounded operations (including the
ordinary 5-second transaction deadline). This packet does not invent a proven
whole-dispatch deadline or solve provider/lifecycle budgets. A later HTTP/Sessions
composition must qualify its complete budget and response-loss behavior.

The API always performs the fixed GET representation. Future cookie ingress may
admit GET/HEAD according to its accepted contract, with ordinary Plug.Head/outer
adapter suppression for HEAD. Do not add a method parameter here or treat a
captured GET body as permission to send a HEAD body. Existing public `/v3` HEAD
behavior is untouched and is not requalified by a local capture test.

## Why not call the lower-level defaults directly

`ConfiguredVerifier.authenticate(token, System.system_time(:second))` followed by
`CustomerWorkspace.organizations/2` or `projects/3` can reuse current identity
and database authority, but it bypasses the canonical BearerIdentity credential
policy, CustomerWorkspaceRequest transport admission, controller result validation
and fixed status/header/error representation. Making it equivalent would duplicate
those contracts or require a separate extraction from active canonical sources.
It also does not itself prohibit a preselected Ecto dynamic Repo. Select the
small capture join instead; it reuses the already specified public bearer
pipeline while keeping its credential-bearing conn private.

`hosted/test/mixer_hosted_web/browser_workspace_dispatcher_capture_adapter_test.exs`,
plus a future producer directory `verification/console-fixed-workspace-dispatcher/`.
No existing product/default/controller/Repo/router/Endpoint/Application source,

The future producer should author a bounded standalone runner at
`verification/console-fixed-workspace-dispatcher/run_host_tests.py` with an exact

`python3 verification/console-fixed-workspace-dispatcher/run_host_tests.py`.
This is a requested future command, not an existing or executed runner. It must
compile only the new modules and their ordinary identity/workspace/authorization
closure, plus the selected new tests; no broad Mix/application boot, callback
source compilation, browser-auth fixture/harness, PostgreSQL or network. Record
the actual explicit closure/command/tool versions and remove its owned scratch.
Do not load ambiguous application BEAMs from a shared dirty `_build` directory.

Required host controls for that component slice are:

1. Pure typed request admission: both operations, nil and canonical cursors,
   1/100 row bounds, 65/100-row compatibility, invalid/extra/struct/string-key
   shapes, cross-operation/org cursor reuse, hostile exact IDs, whitespace,
   Unicode and reserved query bytes. Join the codec to canonical
   CustomerWorkspaceRequest with labelled synthetic identity fixtures to prove
   encoding roundtrips, without pretending those fixtures are verified authority.
2. Direct adapter and canonical controller composition with explicitly labelled
   existing trusted facade fixtures: one empty read/send, validated positive pages,
   controller denials/invalid row rejection, 100 rows, body-bound boundary and
   unsupported/double-send controls. These exercise capture/transport only;
   they are not default Repo or dispatcher success receipts.
3. Public dispatcher closed-argument failures and absence of injection options;
   exact default registered-owner absence yielding the existing redacted 503
   identity response without touching Repo; wrong dynamic Repo refusal with no
   reset; request-id continuity; fixed headers, private conn/identity absence,
   synthetic credential/error-marker redaction and unchanged caller mailbox.
   Run only in an isolated no-default-owner host test process, not against any
   real configured identity owner that could start a refresh flight.

No fake canonical module or injection hook may be added to make dispatcher
success pass. A true 200 through the exact default verifier/default Repo cannot
be qualified by the no-database host suite. Ordinary default Repo/RLS success,
membership/role/principal/family/credential revocation, expiry during lock/commit,
caller transaction refusal, dynamic binding and captured response equality to
the real protected route require a later separately authorized bounded ordinary
workspace database suite. That suite must exclude every callback Unit A path
and must not reuse or restart its interrupted PG16 harness. This selection does
not run or authorize that suite. The component can be accepted only at its stated
source/host-test scope, with this integration qualification explicitly pending.

If root prefers a still smaller first implementation, select only the pure
typed request codec and its tests from this roster. Its constructor/serialization
contract above is closed and useful without any identity owner, database or
callback prerequisite. It grants no authority. Do not substitute a lower-level
verifier bypass or a fake session for the full dispatcher.
